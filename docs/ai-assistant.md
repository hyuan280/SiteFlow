# 智能助手

菜单「智能助手」（`/assistant`）提供持久化对话、脱敏系统数据查询、受限网站观察、显式授权的单步验证和待人工审核的工作流提案；另行明确授权后，可导入已保存提案并运行绑定站点的完整测试。站点编辑器中的独立「AI 生成配置」入口已移除，AI 辅助配置统一使用智能助手；共享协议及仍保留的单次生成后端接口见 [AI 配置协议](config-ai.md)。生成提案本身不会保存站点、运行任务或启用调度。**目标确认只授权浏览观察；统一执行授权才涵盖受支持的登录、签到、点击和挑战单步验证，会实际提交请求，可能产生费用或其他副作用，不是模拟运行。** 截图与工作流导入/完整测试分别受独立权限控制，不开放购买、补签、插件、通用填充或任意代码执行。

外部 Agent 或 MCP 接入的独立审批、异步恢复和策略预授权建议见 [授权设计调研](assistant-agent-mcp-authorization.md)。该方案尚未实现，当前接口不是通用外部 Agent/MCP 服务。

## 启用与升级

- 设置 `SITEFLOW_CONFIG_AI_ENABLED=true`（默认关闭），复用「系统设置 / 大模型支持」中的 OpenAI 兼容连接、API Key、模型和模型超时，没有独立助手提供商配置；助手预算及可选的 `max_tokens` 覆盖在「助手设置」中调整。
- 模型必须支持 function/tool calling；普通文本或图片自测成功不代表工具调用可用。普通对话和 DOM 工具不要求视觉能力；`browser_screenshot` 另要求本轮模型配置 `supports_vision=true` 及宿主明确的截图同意，手动 UI 截图预览不要求视觉模型。
- 助手 `max_tokens` 默认为 null，继承全局模型配置；全局配置中 `SITEFLOW_VISION_MAX_TOKENS` 包括 0 在内会覆盖数据库设置。助手也可显式覆盖：正整数原样发送，0 省略参数、使用上游默认值，不代表无限输出。主对话、标题和摘要调用均使用本轮解析后的策略。思考模型也需留足最终答案和工具调用预算，系统不自动切换模型，见 [模型设置](vision-feature-settings.md#vision-integration)。
- 此功能需配套升级 **Web 前端、API、Worker 三个组件**。仅更新前端或 API 不会补齐 Worker 的浏览器接口；升级前停止助手轮次、工作流和人工浏览器会话。
- 当前以单 API 进程、单 Worker、持久化 SQLite 为部署前提。API 注册模型并通过 `Base.metadata.create_all()` 创建 `assistant_sessions`、`assistant_messages`、`assistant_workflow_actions`（导入/运行幂等账本）和 `assistant_run_guards`（运行配置守卫）新表；本次工作流授权字段保存在加密目标 JSON 中，不需为其新增旧表列。`create_all()` 不是已有列的迁移机制，不承诺迁移历史开发版助手表结构。
- 标题锁定、标题修订号和命名尝试标记保存在现有加密 JSON 载荷中，本次标题功能不需要新增列或数据迁移。缺少这些字段的旧会话按标题已锁定、修订号 0 读取，不会自动改写旧标题。
- 备份数据库，并单独安全备份 `SITEFLOW_MASTER_KEY`；丢失密钥无法恢复加密聊天。不要把模型密钥、浏览器令牌、密码、Cookie 或未脱敏页面内容写入日志、工单或公开备份。

## 助手设置

页面顶部「助手设置」位于「新建会话」之前，无需先创建会话。打开、刷新、保存或恢复默认均不调用模型。设置是所有用户、所有助手会话共用的全局配置，持久化在 `AppSetting` 的 `assistant.settings` 记录中，不是会话偏好；数据库备份应包含它。

| 字段 | 默认值 | 范围与含义 |
| --- | --- | --- |
| `max_tool_calls` | 20 | 1-200，每条用户消息对应轮次的工具调用总数 |
| `max_model_rounds` | 12 | 1-100，主对话模型请求次数；不含独立标题/摘要调用，但它们共用总时间预算 |
| `max_parallel_tool_calls` | 4 | 1-8，模型一次响应最多发回的工具调用数 |
| `turn_timeout_seconds` | 180 | 30-1800，整轮活动时间预算，单位秒；不含等待用户确认 |
| `context_max_tokens` | 64000 | 16000-1000000，本地预检的上下文 Token 预算，不是提供商上下文容量声明 |
| `max_tokens` | null | null 继承全局；0 不向提供商发送该参数；正整数上限为 9007199254740991 |
| `auto_compact` | true | 自动生成旧历史摘要及轮中上下文整理；关闭后的具体边界见 [上下文整理](#上下文整理) |
| `auto_title` | true | 自动生成会话标题；仍受前三条用户消息窗口和标题锁约束 |
| `auto_authorize_execution` | false | 显式勾选后默认授予目标内统一执行能力，不是逐功能默认值 |
| `auto_authorize_screenshot` | false | 显式勾选后默认允许截图发送；不替代视觉能力检查 |
| `auto_authorize_workflow` | false | 显式勾选后默认允许提案导入与绑定站点完整测试，不只是生成提案 |

UI 的「每轮并行工具调用数」标签容易误解：它只限制**模型一次发回的最多工具数，不是并行执行数**。服务端始终逐个、顺序派发工具，不因调高该值并行操作网站。「模型输出上限」勾选「继承模型配置」发送 null；取消继承后留空或填 0 都发送 0，不是恢复继承。数字输入只接受范围内的十进制整数，不接受小数或科学计数法；API 数值必须是整数，开关必须是布尔值，未知字段拒绝。

每条新消息被接受时读取设置快照，**同一旧会话的后续消息也会使用新设置，正在运行的轮次保持原快照不变**。标题和摘要同样使用该快照中的 Token 覆盖及剩余总时间预算。关闭 `auto_title` 不改写最后的标题，也不解除人工重命名或显式创建标题的永久锁；重新启用或恢复默认同样不会解锁，也不会补做已错过的命名窗口。

对话框显示 `source`（`default` / `db`）及 `revision`。记录不存在时只读返回默认值、修订 0；保存与「恢复默认」均携带 `expected_revision`，通过原子比较并交换（CAS）防止覆盖其他客户端修改。成功后修订递增；恢复默认将默认值写入数据库，不是删除记录或把修订归零。冲突返回 409 `assistant_settings_conflict`，UI 保留草稿、不自动重试，需核对后刷新并重新编辑；刷新会丢弃草稿。请求失败或响应丢失不证明未保存，应先刷新核对。

持久化记录损坏、缺字段或越界时返回 503 `assistant_settings_invalid`，新消息也不能以默认值静默继续；读取、保存和恢复默认都不会覆盖损坏记录，**「恢复默认」不是损坏数据修复入口**，需管理员排查数据库。

三个全局授权默认值均关闭，只有用户明确勾选并保存才生效；它们相互独立，不能跳过目标身份、额外可信来源或代理的显式宿主确认。执行开关只控制发现浏览器中的单步能力；第三个工作流开关是原有的组合权限，**同时涵盖提案导入和绑定站点完整运行，不是仅保存，也不依赖单步执行开关**，不拆分为两个权限。界面明确显示「默认授权导入保存配置并触发真实完整工作流运行」及其业务风险。新轮次可对已确认目标应用对应默认值，已保存的目标/会话显式权限仍有效；关闭默认值不会追溯撤销已经授予目标的权限。认证仍需可用的私有凭据来源，不因默认授权扩大 origin、凭据或受支持功能范围。

仅对完整匹配已发布旧版结构的持久化设置，读取时将 `context_max_bytes` 按 `ceil(bytes / 4)` 近似换算，再钳制到新范围 16000-1000000；旧字段原有合法范围为 64000-1000000 bytes。三个新增授权默认值补为 false，不迁移出新权限。读取不写库、不改修订；下一次成功 CAS 保存/恢复默认才持久化新结构，仍比较原始旧记录。其他损坏或不完整结构不静默迁移。

这些设置仅影响持久化助手，不修改提供商 URL、API Key、模型连接，也不改变单次「AI 生成配置」接口及其限制。整个模型请求 **1536 KiB**、主模型响应 **256 KiB**、单步活动 **90 秒**、浏览器 **15 分钟 TTL** 等仍是固定边界，不是可调设置；调高 Token 预算不能绕过序列化线协议字节上限，也不保证上游模型接受百万 Token。

## 页面操作

1. 打开「智能助手」，点击「新建会话」即直接创建并选中会话，**没有标题或同意弹窗，也无需预填目标设置**。初始标题为「新会话」，第一条 assistant 欢迎语由服务端固定写入，不调用模型；创建不代表已访问网站。也可从左侧选择旧会话继续；刷新列表和刷新会话均只读取状态。
2. 先提供不含秘密的站点 URL 和期望流程，请助手先用 `check_site` 检查是否已配置，再澄清站点名称、认证方式、代理偏好和需求。该工具按 hostname 检查，只返回最多 20 个匹配站点的名称和净化后的基础地址，不读取工作流或凭据，也不进行网络探测；需要配置线索时可另外调用下文的脱敏数据工具。
3. 助手在聊天中收集名称和公共 URL，必要时澄清认证来源（`manual`、`bitwarden`、`cookie`、`none`），再用 `request_user_interaction` 的 `purpose: "target"` 发起宿主确认。输入框上方的目标核对面板只以可读字段展示网站名称和完整公共地址，不展示原始 JSON；同源凭据绑定 `site_id`、独立配置目的 `workflow_site_id`（空为新建）及授权字段保留在私有载荷中。用户核对后「确认并继续」，原调用即恢复，无需再发消息。模型提供的是候选，聊天中说“确认”不能代替宿主决定。即使开启全局授权默认值，目标仍必须明确确认。
4. 直接发送消息（支持 Ctrl+Enter）；发送即同意将消息、有限历史和已授权观察结果交给配置的模型，UI 不再要求发送前勾选。确认目标后请模型调用 `browser_open`，再 `browser_observe`；确认本身不会打开浏览器。无需目标也能先聊天、澄清或查询安全功能目录和脱敏系统数据，但浏览器、执行和提案工具必须有已确认目标。新目标默认关闭代理、完整运行默认保存为 `general`。用户明确要求变更设置后，统一通过 `update_site_config` 逐项核对精确变更；代理及可信来源不属于目标确认的附带授权，详见「站点设置变更」。
5. 先采集当前页面证据。需要登录时，可按下一节在 VNC 人工完成；或在统一执行授权且凭据来源可用时，用 `execute_step` 测试一次。缺少执行权限时由宿主请求交互确认，不要求预先操作设置。签到、通用点击、ALTCHA 和滑块需要的副作用权限由宿主从统一执行授权自动派生，无需再勾选。比较执行前后 DOM 快照，并重新导航/观察确认状态，不把“已提交”当作登录或签到成功。
6. 展开工具结果中的完整提案 JSON，审核 `proposal.draft` 的 `steps`、`groups`、`signals`、说明和待确认问题，并核对 `required_site_settings` 的 `credential_mode`、`credential_provider_id`、`lane_policy`。这里的运行车道独立于浏览观察代理；`trusted_origins` 只是观察来源说明，不自动推导或保存凭据授权 `trusted_urls`。跨源提示的 `trusted_url_pattern` 只是候选正则，不能直接当作凭据授权；用户明确要求后，可通过 `update_site_config` 精确审核已保存目的站点的 `trusted_urls`，或在正常编辑器另行审核。凭据和 Cookie 不在提案内。用户要求导入/测试时，模型可在同一轮继续，缺少工作流权限由宿主交互请求，批准后原调用恢复，不要求预先打开设置或另发消息；只生成提案也可结束。更换目标会改变目标修订，须在当前目标下重新校验提交，不能直接导入旧提案。导入必须引用宿主返回的已保存 `proposal_message_id`，不能把提交提案说成已经保存。
7. 使用下文的授权导入与完整测试流程，或在正常站点编辑器中人工复核、保存、校验并决定是否运行。助手页没有把任意 JSON 直接“一键应用”的入口；聊天中的工具调用只可导入本会话成功保存的原提案。手动复制时只使用工作流集合，不把整个工具响应当作站点导入数据，也不能使用脱敏占位 URL。校验或单步成功不是完整任务成功保证。

认证方式只是凭据来源声明，不能替代执行授权，也不会凭空提供凭据。`manual` 未绑定站点时仍可授权浏览和非认证测试；自动登录需先在站点管理保存凭据并绑定完全同源的站点，或选择 Bitwarden，再通过目标交互重新确认。凭据只在服务端私下传递，不进入模型。不要在聊天、标题、URL 路径、证据、选择器、说明或提案中放密码、Cookie、API Key、TOTP 秘钥/验证码等秘密。

标题/状态操作区和底部输入区固定保留在聊天面板中，只有消息时间线滚动；移动端同样保留输入与停止入口。安全提示可关闭，关闭状态仅存本浏览器 `localStorage`（`siteflow.assistant.safety.v1`），不是服务端授权、撤销、账号偏好或安全检查开关。

### 交互与授权

`request_user_interaction` 用于目标、能力授权和通用问题；可信来源、代理的旧 purpose 仅保留兼容，新设置变更统一使用 `update_site_config`。通用 `purpose: "question"` 可用 `kind: "authorization"` 做普通确认、`choice` 做单选/多选、`input` 收集非秘密文本；通用确认和偏好答案**绝不修改目标权限**。单个问题最多 20 个选项或 8 个文本字段，每字段最多 2000 字符，必填项不得为空；没有秘密输入类型，也不能索取密码、Cookie、Token、OTP/TOTP 或验证码。已知秘密及敏感提问会被拒绝，过滤仍不是通用 DLP。

通用问题默认 `required: true`，拒绝或超时会阻止本轮剩余批次及后续模型轮次的工具调用，助手只能说明缺少的前提并停止。确实不影响继续处理的偏好问题可以显式指定 `required: false`；字段的 `required` 则仅控制该输入项是否必填。不同问题按完整内容区分，不会复用另一道确认题的批准；代理成功选择按作用范围区分，拒绝后不能通过更换范围再次弹出。

所有交互均在输入框上方内联显示，不是模型文本伪造的弹窗；详情/SSE 的 `pending_interaction` 驱动核对面板。每次等待最多 **180 秒**，不按本轮剩余活动时间缩短；活动预算已耗尽时不再弹出。仅实际等待用户的时间暂停本轮活动计时，并等量顺延共享截止时间及外层超时；审批处理、网络请求和批准后的执行仍消耗剩余活动预算，不重置预算，也不改变提供商单请求超时、单步上限或浏览器 TTL。停止和关闭服务仍立即取消等待。批准只由登录 owner 经 CSRF 保护的响应接口提交，等待中的原调用复查目标修订、指纹和轮次绑定后才应用权限并继续。

拒绝、超时、取消、失效均不授予权限；同一轮同一 subject 的决定/结果被缓存，不能换措辞、拆分可信来源或重发工具来重复询问。所需授权或必填信息未取得时，停止依赖它的操作，说明缺失内容，不猜测、不绕过；下一轮有新的明确需求时才可重新请求。停止或重启取消 pending，不自动恢复。已明确授予的目标/会话权限可在后续轮次复用，不应每次工具调用都重新询问。

## 站点设置变更

助手不得主动提出或修改任何站点设置，包括启用调度、代理和可信网址；仅在用户明确要求对应变更后，才可提出 `update_site_config`。不得从 DOM、浏览失败或模型建议推断用户需要变更设置。**每次设置写入都必须由真实用户审核并批准本次精确差异**，包括只改观察设置；聊天中的泛化同意、历史工作流权限和全局 `auto_authorize_workflow` 均不能跳过。后端不使用自然语言猜测或模型提供的 `user_requested` 布尔值作为授权，真正授权来自当前 owner 经认证和 CSRF 保护的交互响应。

- 参数为稳定的 `operation_id` UUID、可选 `patch`、可选 `observation` 和仅启用时可用的可选 `successful_run_id`，另有公共 `title`；`patch` / `observation` 至少一项非空，无实际差异则拒绝。每次新变更使用新 UUID，仅相同请求重放复用它。未知字段、宽松类型转换和越界值均拒绝。只修改已确认目标的 `workflow_site_id`，不能提供任意站点 ID，也不能把凭据源 `site_id` 当作配置目的地。
- `patch` 仅允许下表 **10 个字段**，省略保留原值，仅 `checkin_after` 接受显式 null。不开放 `base_url`、模板、凭据来源/提供商、凭据/Cookie 或 `steps` / `groups` / `signals` 工作流数组的修改。
- `observation` 只包含 `proxy` 和 `trusted_origins`。来源列表替换完整列表而非隐式追加，仅用于观察，不授权发送凭据或完整运行跨源访问。尚未导入站点时可用空 `patch` 单独审核这些会话设置；不创建站点。观察代理不自动改变保存运行车道。
- 内部 `purpose: "site_config"` 不能通过公共 `request_user_interaction` 直接调用。模型统一使用 `update_site_config`；旧 `trusted_origins` / `proxy` 交互保留既有持久化兼容行为，但已弃用，不再由提示词推荐。
- 公共审核对象为 `{name, base_url, site_id?, changes: [{field, label, before, after}], warnings, successful_run_id?}`。UI 以可读名称/地址、逐项「变更前 / 变更后」及风险提示展示，不要求用户审核原始 JSON。标签和风险提示由服务端生成。旧备注不展示，旧可信正则和标签仅显示数量；新可信正则精确展示、不以脱敏后的变形正则保存。`trusted_urls` 是本站点的凭据/TOTP 信任正则，不是观察白名单；Python 正则全匹配完整 HTTP(S) URL（含路径、查询和片段），宽泛规则可能泄露凭据。`observation.trusted_origins` 则只授权观察/导航，不授予凭据或完整运行访问权。已知秘密、敏感 URL 参数或脱敏占位值拒绝，过滤不是通用秘密检测。
- 每次调用等待最多 180 秒，实际等待不消耗活动预算。准备时冻结目的站点历史身份、修订、设置及精确补丁；批准后由原等待调用复查，而非响应接口立即写入。活跃任务、未决完整运行或单步不确定性阻止站点写入，不会被设置修改清除。
- 站点 CAS 写入、`assistant` 操作者的加密历史、新的目标/凭据绑定、目标修订、旧提案/摘要清除、重试授权失效及加密 `AssistantWorkflowAction(kind="site_config")` 回执在同一事务提交；工作流行和凭据保持不变，不确定性事实保留。提交后才关闭观察浏览器。相同 operation ID 和相同内容返回已存结果，不再修改；不同内容返回静态冲突。拒绝、超时、取消、重启或复查失败不会自动写入或重做。
- `enabled: true` 必须是唯一补丁字段，且不能带任何观察设置。准备与应用两次均要求当前 owner、当前会话的已完成 `kind="run"` action 关联持久化完整运行：`Run.trigger="assistant"`、`Run.status="success"`、已结束且未请求取消，整个 Run **有且仅有一个** SiteJob，属于该站点、已结束且 `status="success"`，严格守卫仍匹配当前站点历史身份、配置修订及有效配置指纹。可用 `successful_run_id` 指定证据，省略时服务端查找。排队/运行中、跳过、失败、未知、取消、孤立单步成功、手动运行、其他会话/用户或旧配置运行均不算。更改调度等设置后保守地要求重新完整测试，不沿用旧证据；完整测试本身不会启用调度。该门禁仅约束助手工具，正常编辑器和手动 API 的启用行为不变。

| `patch` 字段 | 含义与边界 |
| --- | --- |
| `name` | 站点名称，去除首尾空白后 1-128 字符 |
| `trusted_urls` | 最多 20 条精确审核的凭据信任正则，每条 1-1024 字符；拒绝首尾空白，空数组撤销额外信任 |
| `enabled` | 布尔值；true 启用调度须满足上述独立审核及完整成功证据要求，false 禁用也须审核 |
| `lane_policy` | `auto`、`general`、`interaction`、`proxy_general`、`proxy_interaction`；`auto` 当前解析为 `general` |
| `support_resign` | 是否允许补签，不开放助手实时补签能力 |
| `resign_max_days` | 最大补签天数，严格整数 1-365 |
| `checkin_after` | `HH:MM` 签到起始时间；null 明确清除 |
| `timezone` | 有效时区名，1-64 字符 |
| `tags` | 最多 50 个标签，每个 1-128 字符 |
| `notes` | 最多 4000 字符的备注，不得放秘密 |

## 会话标题

- `auto_title=true` 时，未锁定的新会话仅在**前 3 条已接受的用户消息**对应的主对话成功完成后，尝试一次独立、无工具的小型标题模型调用。它复用同一连接、模型及本轮 Token 策略，不是另配小模型；输入仅为截至当时的前几条用户消息，不发送 DOM 或工具结果用于命名。
- 用户消息计数不是成功轮次计数。主对话失败或取消仍消耗前三条窗口，不会补到第 4 条以后；标题调用失败保留当前标题，不重试该次命名，不影响已经生成的答案。后续仍在前三条内的成功轮次可以再次命名。
- 标题调用最多 10 秒，且只使用本轮配置的总预算（默认 180 秒）的剩余时间，不追加预算。创建、读取、刷新或 SSE 重连不会触发命名。
- 空闲时可点「重命名」人工修改。保存后永久停止该会话的自动命名，没有解锁入口；通过创建 API 明确提供非空标题也会锁定。`title_revision` 单调增加，避免较旧的 SSE/列表响应覆盖新标题。

## 数据查询

这些工具读取站点、模板、运行和状态的专用安全投影，不是直接把管理端 API 响应交给模型。它们不需要浏览器目标确认，也不查询外部凭据；`get_system_status` 仅可读取 Bitwarden 的浅层健康状态，不查保险库条目。

| 工具 | 返回范围 |
| --- | --- |
| `list_sites` | 可按名称查询；最多 100 个站点的非秘密元数据，含 ID、模板/车道/凭据来源标识等，不含账户值 |
| `get_site_config` | 指定站点的脱敏本地与解析后步骤、分组、信号，以及是否存在已保存凭据；不读取凭据明文 |
| `list_templates` / `get_template_config` | 最多 100 个模板元数据，或指定模板的脱敏本地/解析配置与信号 |
| `get_system_status` | 集成配置来源、Bitwarden 浅层健康状态和车道状态；其他集成仅返回配置元数据，不返回服务密钥或连接地址 |
| `list_recent_runs` | 最多 20 次运行元数据和任务状态计数，可按站点筛选 |
| `get_run_summary` | 指定运行摘要及最多 100 个站点任务元数据；不含原始日志、消息、结果或截图附件 |

`get_system_status` 的 Bitwarden 状态与系统设置共用 `BitwardenService.view(force=False, deep=False)`，优先使用约 15 秒的浅层健康缓存，缓存失效时可请求 `/health`，不强制刷新，也不调用 `/check` 或 `/lookup`。它只返回 `enabled`、`enabled_setting`、`available`、`configured`、`auto_detected` 等布尔状态及 `source`、`enabled_source`、`url.source`、`token.configured`、`token.source` 和 `sources` 来源元数据；来源包括 `env`、`db`、`auto`、`unset`。默认地址自动检测的 URL 来源为 `auto`，启用来源另按实际配置解析。`available` 表示浅层健康可达，`configured` 表示服务报告保险库已配置并就绪，`enabled` 是有效启用状态；显式禁用会被尊重，未探测时 `configured` 也可能为 false，与设置页一致。可选包装服务 Token 未设置不代表不可用，不能据此要求用户补 Token。状态不是站点凭据匹配或登录成功的保证。

Bitwarden 项的 `health_checked: true` 表示已使用上述健康视图，可能来自缓存，显式禁用时也不保证发出新请求；其他集成的 `health_checked: false`、`available: null` 表示未探测而非不可用。顶层 `health_checked: false` 配合 `health_scope: ["bitwarden"]` 表示没有对全部集成做健康检查。后台可为解析该视图解密 Bitwarden 连接配置，但原始 URL、默认地址、Token（包括掩码/指纹）、邮箱、服务版本、响应正文和错误详情均不进入工具结果或模型；读取失败只返回静态 `data_unavailable`，不把异常解释为禁用。其他数据工具不因此解密集成或凭据。

本地配置、继承结果和默认值均先脱敏：移除内联填充值、静态表单字段、敏感键及模型提示等，URL 按各工具的专用安全投影处理，保留审核过的选择器/字段名和提供商标识。这不意味着浏览器观察会统一删除查询与片段，完整 URL 的处理见下文。这不是任意自由文本的通用 DLP；名称、标签、选择器和路径仍可能敏感。单次输出最多 128 KiB，超限返回静态错误。没有任意 SQL、Shell、JavaScript、文件读取、密钥读取或通用网络请求工具。

## 单步验证

目标确认只授予浏览观察。首次需要执行且尚无有效权限时，宿主暂停 `execute_step` 请求统一执行授权；明确批准或显式开启 `auto_authorize_execution` 后，API 派生 `execution_consent`、当前受审核的 `execution_features` 清单，以及签到、`action.click`、`challenge.altcha`、`challenge.slider` 所需的 `allow_sign`；凭据来源可用时才派生认证所需的 `credential_consent`。**执行能力是目标内统一授权，不是逐功能反复确认**；截图、工作流、可信来源和代理不包含在内。这些字段是后台校验元数据，不是用户要逐项填写的选项。即使验证选择器也可能触发真实业务操作；DOM、模型参数、工作流条件或聊天中的同意都不能扩大权限。

宿主在生成执行核对面板时冻结当前支持且凭据来源允许的 `execution_features`，并展示凭据使用及副作用权限；批准只授予这份冻结清单，不因等待期间代码或功能目录变化扩大范围。可选 `feature_type` 只说明本次请求的触发功能，不把授权缩成单功能。去重 subject 为整个 `authorization:execution`：同轮拒绝、超时、取消或失效后，换另一个功能也不能再次请求执行能力。

旧目标保留原先明确保存的权限，不因升级自动扩权；后续轮次可复用有效目标权限，或应用用户显式保存的全局默认值。没有相应权限时通过宿主交互明确批准。新执行授权只覆盖当时审核清单，不自动包含未来新增功能。

当前审核过的实时执行清单仅有以下 **10 项**，不同于更广的提案功能目录：

| 类别 | 支持功能 |
| --- | --- |
| 导航与等待 | `flow.open`、`action.navigate`、`action.wait` |
| 认证 | `auth.form_login`、`auth.password_verify` |
| 签到与点击 | `sign.button`、`sign.unit3d_claim`、`action.click` |
| 挑战 | `challenge.altcha`、`challenge.slider` |

- `manual` 认证测试必须先在站点管理中创建站点并保存凭据，再绑定与目标 **完全同源**（scheme、hostname、有效端口一致）的持久化站点。API 冻结站点 ID、`history_key` 和 `config_revision`，执行前重新核对；站点删除、替换或修订变化需重新确认目标，不接受模型挑选站点或凭据。
- `manual` 未绑定已有站点不阻止确认目标、浏览观察或非认证测试，但不授予认证功能；遇到 `credentials_unavailable` 应绑定已保存凭据的同源站点或改选 Bitwarden，再确认目标，不向聊天提供账号密码。
- `bitwarden` 可用于尚未保存的新域名，统一授权会派生认证和凭据使用权限，实际执行仍要求集成及匹配凭据可用。API 私下按目标的完整域名匹配，不继承已有配置中的主域名/自定义匹配或插件提供商。已有站点绑定如存在，也必须通过同源和修订检查。
- `cookie` 模式不读取/导入站点存储的 Cookie 用于认证测试，应在同车道独立标签页人工登录后观察；`cookie` / `none` 均不能授权认证功能。没有聊天输入密码或临时手输凭据入口。
- `execute_step` 接收一个启用、无条件的完整步骤（`condition` 只能为空或 `always`）和稳定的 `operation_id` UUID，不运行分组、信号条件、跳转或完整工作流。API 根据当前功能策略补齐默认值、校验配置并固定导航重试为 0；Worker 在**当前助手页面**执行，不重新申请车道或新页面。
- 单步活动预算最多 90 秒，受较小的步骤超时和剩余浏览器 TTL 限制，不自动重试。返回静态开始/结束日志、安全结果标记及 `before` / `after` **结构化 DOM 状态快照**，不是 PNG 截图、录像、完整 HTML 或原始运行日志；异常时快照可能为空。每份执行快照的完整 JSON 分页响应最多 **24 KiB**，两份共最多 48 KiB，为执行结果外层留出空间，不是两份各 32 KiB 挤满 API 的 **64 KiB Worker 响应读取上限**。页面在单步结束后保留，可继续人工检查或观察。
- **执行签到会发生真实签到；登录会实际提交账户表单，点击可能消费或更改状态。** 必须先确认未签/待操作状态及权限，比较前后证据。`submitted: true`、工具成功或按钮消失不等于业务成功；孤立步骤测试也不证明最终工作流可用。
- 每个新操作使用独立 UUID，发起后保持稳定。API 在派发/释放凭据前把 UUID 记入会话加密账本；重复 ID 被拒绝。Worker 将同 ID 绑定完整请求指纹，只能返回缓存终态或在途状态，不能再次执行；不同内容同 ID 被拒绝。不要把更换 UUID 当作重试机制。
- 超时、取消、断线、响应丢失或 `unknown` 不代表网站未收到提交。结果不明时停止副作用操作，先只读核验；确需重试时走下文「允许重试一次」的宿主授权，不换 UUID 绕过。重开浏览器本身也不能解除不确定性。每浏览器最多 20 个操作，每持久化聊天会话账本最多 256 个 ID；改目标、重开浏览器或 API 重启不清空该账本。

当前没有把图片验证码、Turnstile、2FA、iframe 签到、购买、补签、插件或任意填充接入该单步工具。独立截图工具只提供图像证据，不是验证码解题或动作工具。某功能能用于提案或正常工作流，不代表能在这里实时测试；不支持的挑战应交给人工，不猜测成功。

### 表单登录就绪

`auth.form_login.success_wait_seconds` 默认 **10 秒**，只接受 **1-120 的严格整数**；布尔值、小数（包括 `10.0`）、字符串和 null 均不接受。它控制提交后的成功证据等待，不是步骤总超时；`timeout_seconds` 需要另行覆盖凭据/秘密查询、定位、填写、点击提交及成功等待，助手单步还受 90 秒活动上限、浏览器剩余 TTL 和本轮剩余预算约束。调整此字段不会自动延长外层超时，也不修改已保存的站点配置；不能仅靠延长等待宣称修复。

配置 `success_selector` 后，提交一次，再在同一等待期限内只读轮询主页面及**可见同源 iframe** 中各候选选择器的匹配元素，所有祖先 iframe 也须可见且同源，`about:blank` / `srcdoc` 沿父链继承来源；凭据 `trusted_urls` 不扩大成功证据范围。**任一匹配可见即可，不只检查第一个匹配**。实现有界：每轮最多检查 100 个 frame、每个选择器在各 frame 中最多 100 个匹配，随页面变化重新读取 frame 和匹配。隐藏节点仅存在不算登录成功；留空只报告已提交（`submitted: true`、`verified: false`），不证明已登录。等待期间不自动刷新、导航或重新提交；证据未出现也不证明网站拒绝了登录。

工作流信号的包含/排除选择器默认是**存在性**检查，隐藏节点也可命中，与登录成功元素的**可见性**要求不同；需要可见证据时，可在工作流的 Playwright 选择器中显式使用 `:visible`，系统不自动追加或改写已保存配置，不新增信号数据库列或改变默认语义。这不适用于文本规则：`include_texts` / `exclude_texts` 匹配页面标题和各 frame 的 body `innerText`，通常不包含 body 内隐藏后代的文本，不是读取全部隐藏节点的 `textContent`。助手 `browser_check_selector` 仅支持 CSS，不能直接传 Playwright `:visible`，应检查其返回的 `visible_count`。

稍后 `is_logged_in` 为 true 不能倒推提交步骤当时已满足可见成功条件。排查须区分首个匹配隐藏、后续匹配可见、延迟渲染及两种检查语义，不能只加长等待。超时后返回的原因及匹配/可见计数是**超时后的有界只读采样**，不是等待期间的历史证据或原子快照；页面可能在各项采样间变化。选择器索引对应原步骤 `config.success_selector` 的配置索引（从 0 开始），不是 DOM 匹配序号；按原配置核对，不回显选择器值、表单值或凭据。通用修复不是特定网站适配或实际生产认证验证。任务 329 的时间线、同 URL 导航跳过及截图证据限制见 [登录时序与误判](assistant-discovery.md#登录时序与误判)。

### 凭据与请求边界

已保存凭据仅由 API 私下解析并传给 Worker 的受限认证上下文，**不进入模型、聊天或提案**。Worker 验证当前源及原始元素：用户名/密码/提交按钮须唯一可见，属于同一个原始表单；密码必须为可编辑的 `input[type=password]`，用户名为可编辑的 text/email 输入。保留并重复核对原始节点及原始 form 身份，拒绝选择器重新绑定到替换节点、不同表单、跨源 action/formaction 或非当前窗口目标。**不要求 form 声明 `method=POST`，也不要求逐表单批准某个 POST action 端点。** 省略 method（隐式 GET）或声明 GET 的表单可由页面原有 JS 阻止默认提交，再用 fetch POST 到原始 origin 的其他路径；这不是开放模型编写或执行任意 JS，也不授权 `trusted_urls` 或 SSO。

助手页默认只允许 GET/HEAD。额外可信来源仅用于导航与观察，**单步执行及凭据使用仍限于原始目标 origin**，不能在额外可信来源页面测试登录、点击或其他步骤。只有已授权的非只读单步活动期间，Worker 的 `writes_authorized` 才临时允许 POST，可到原始 origin 的任意合规路径，而非仅 form action；此时受约束请求和重定向限于原始同源，跨源 POST 即使指向可信观察源也拒绝。`flow.open`、`action.navigate`、`action.wait` 是只读步骤，执行期间也不开放 POST；PUT/DELETE 等方法不因此开放。

普通查询参数保留原始编码，包括原生表单或 JS POST 的 `/api/auth/login?redirect=%2F`，不会删查询来“修复”登录。**已知账号/密码等秘密不得出现在任何请求 URL 中**，编码或嵌套编码也检查；原生 GET 表单若把凭据放入查询，会在网络边界被阻止，DOM 校验通过不代表允许此传输。步骤结束立即关闭 POST 窗口，并保留原始同源限制，防止延迟脚本或残留输入值向外源泄露；增加 `trusted_origins` 不绕过这个限制。静态日志和结果经安全投影、已知秘密过滤后返回；这仍不是完整浏览器沙箱。

运行时 `diagnostics.blocked_requests` 最多列 5 个被阻止请求的安全投影，含 `code`、HTTP `method`、投影后的 `url` 及脱敏标记；普通查询可保留，敏感参数值被擦除，含已知秘密的地址可整体显示为 `[redacted]`。它不含 POST body、请求头、凭据、浏览器能力令牌或重试授权密钥，不能据此还原请求或判断原操作成功与否。旧版 `browser_credential_endpoint_not_approved` 一类诊断针对请求端点，不等于缺少站点 ID 或 Bitwarden 未配置；当前通用实现没有逐表单 POST 端点审批要求，不应增加特定网站补丁来绕过边界。

## 人工登录

自动登录采用上一节的通用原始节点/同表单检查与运行时请求边界，不把 POST 绑定到某个冻结 action 端点。普通同源查询参数允许保留；需要跨源认证或不能满足这些检查时，使用独立人工标签页，不要求放宽规则。

单步结果为 `outcome_uncertain` 时，页面仍保留，禁止自动重复有副作用的步骤，但可继续 `browser_observe`、子树查看和选择器检查。结果中的 `diagnostics.reason` 是执行或策略原因，`diagnostics.evidence_errorcode` 说明 after 快照为何未能取得。读取当前安全页面时，历史被阻止的请求以 `warnings` 返回，不再仅因旧拒绝记录关闭页面；跨源候选仍展示完整非敏感目标信息以供确认。真正不安全的当前地址、失效授权或响应身份错误仍会终止会话。

`proxy=false` 固定使用 `interaction`，`proxy=true` 固定使用 `proxy_interaction`，不使用 `general` 或 `proxy_general`，也不自动换车道。`browser_open` 会通过车道租约按需自动启动所选交互车道，无需先手动启动；`get_system_status` 中通用车道停止与助手能否打开浏览器无关。需要人工登录时，打开「车道状态 / VNC」并进入助手返回的同一车道，不能在另一条车道登录后期待共享状态。

目标中的 `proxy` 字段只控制浏览观察及当前页面的单步验证，新目标默认 false；保存后的完整工作流另用 `run_lane_policy`，默认 `general`，旧/API 的 `auto` 同样解析为 `general`。用户明确要求后，通过 `update_site_config` 分别审核 `observation.proxy` 和已保存目的站点的 `patch.lane_policy`；失败不构成自动切换的理由。完整五种车道均可明确审核，但观察浏览器始终使用交互基础设施。

旧版 `purpose: "proxy"` 交互仅为持久化兼容保留，以下描述其既有行为，不是新调用推荐入口。该交互为 **`kind: "choice"` 单选**，宿主提供 `general`（直连）和 `proxy_general`（代理）两个选项，批准响应还须带 `selections: ["general"]` 或 `["proxy_general"]`。`scope` 为 `browser`、`workflow` 或 `both`，默认 **`both`**。模型传入的 `enabled` 只是建议，不授予权限，也不能覆盖用户选择。

| `scope` | 用户选择的作用 |
| --- | --- |
| `browser` | `general` 将目标 `proxy` 设为 false，`proxy_general` 设为 true；只改发现浏览器及当前页单步，不改保存运行车道 |
| `workflow` | 将目标 `run_lane_policy` 设为所选 `general` / `proxy_general`；只改后续导入/完整运行的车道策略，不改发现浏览器代理 |
| `both`（默认） | 按同一用户选择同时更新上述两个独立字段 |

选择名称不等于浏览器实际基础设施车道：发现浏览器仍必须使用 `interaction` / `proxy_interaction`，不能改用 `general` / `proxy_general` 打开助手页。改变浏览器模式后需安全重开，不自动重试旧操作；改变工作流策略也不等于已经导入、修改站点或触发运行，仍须按当前目标修订校验提案并走独立工作流权限。旧宿主接口仍可明确选择四种保存车道，但模型、页面或聊天偏好不能自行代选。完整运行正常的 `general -> interaction` 或 `proxy_general -> proxy_interaction` 同代理模式回退不算配置漂移，不允许借此切换直连/代理模式。

**人工登录时，在该车道中新建一个独立、由你控制的浏览器标签页，不要在助手观察标签页提交登录表单。** 助手页在单步活动窗口之外只允许 GET/HEAD，连人工提交的 POST 登录也会被阻止。独立人工标签页不受这套助手页限制，你应自行核对地址及登录行为；不要为方便人工操作而扩大单步授权。

同车道使用共享 profile/context，人工标签页登录后的 Cookie 可供助手标签页使用。完成后返回聊天，明确要求模型先调用 `browser_navigate`，例如 `path: "/"`、已知的同源账户页路径，或 `url` 指定的原始源/已确认可信源完整 URL，再调用 `browser_observe`。`path` 与 `url` 必须且只能提供一个，可保留非敏感查询与片段。即使地址与当前页相同，导航也会重新加载，使共享 Cookie 生效；仅观察旧 DOM 不保证页面已刷新。

认证页需要跨源 SSO 提交、敏感令牌或未获授权的 POST 时，应在独立人工标签页完成，不要要求模型绕过限制。普通非敏感查询与片段不需要因此改用人工标签页；跨源导航与观察仍须先由用户确认精确 origin。人工登录不扩大助手的目标授权。授权观察可能把已登录页面的个人资料发送给配置的模型；不愿披露时不要授权或继续观察。

## 完整 URL 与可信来源

`browser_open` 使用宿主确认的完整 `base_url`，模型不另传打开地址；显式 `browser_navigate` 也支持完整 URL。观察结果的 `url` 和元素 `href` 保留非敏感的查询与片段，包括参数顺序、重复参数、空值、`+`、百分号编码大小写及片段路由，不因展示而拆掉或重新编码这些部分。源的 scheme、hostname 和默认端口可规范化，但不会因此改写公开路径、查询或片段的原始编码。

- 识别到 `token`、`access_token`、`password`、`session`、`code`、`state`、`sig`、`signature` 等敏感参数键时，仅把值替换为 `[REDACTED]`；也处理片段参数、编码后的键及受支持的敏感键变体。页面 URL 标记 `url_redacted` 和 `redacted_parameters`，链接分别标记 `href_redacted` 和 `href_redacted_parameters`。
- 普通 `return_to` / `redirect` 不因名称或包含 URL 就被整体视为秘密。无秘密的嵌套 URL 保留原始编码；有敏感参数时只擦除嵌套敏感值，保留其余公开内容。嵌套 URL 含用户名/密码或超过脱敏深度边界时会更保守地隐藏对应值。
- **脱敏 URL 只能作证据，不能作工作配置、导航地址或可执行提案。** 不得把 `[REDACTED]`（包括编码形式）保存或执行，也不能猜测、补写秘密。确需敏感参数时在聊天之外处理；已知凭据匹配还可能使整个 URL 隐藏。按参数键脱敏不是通用 DLP，公开键的值、路径和文本仍须人工检查。

例如 `https://example.com/login?tab=foo&next=%2fhome#/login?tab=foo` 完整保留；`https://example.com/login?tab=foo&token=SECRET#details` 展示为 `https://example.com/login?tab=foo&token=[REDACTED]#details`，并标记已脱敏。嵌套的 `?return_to=https%3a%2f%2fother.example%2flogin%3ftab%3dfoo%26token%3dSECRET` 仅将 `SECRET` 换成 `%5BREDACTED%5D`，不是删掉整个 `return_to`。这里的 `SECRET` 仅为说明占位，不应实际发送秘密。

未批准的公共跨源导航或重定向被阻止时，工具返回 `code: "browser_trust_required"`，不是已成功访问。结果包含完整但按上述规则脱敏的 `source_url`、`target_url`，各自的 `source_url_redacted`、`target_url_redacted`，以及 `redacted_parameters`、`source_origin`、`target_origin`、`user_action: "confirm_trusted_origin"` 和 `trusted_url_pattern`。例如目标源为 `https://auth.example.com` 时，建议模式为 `^https://auth\.example\.com(?:[/?#].*)?$`；该模式由精确 origin 转义生成，不接受模型自行提供的宽泛正则。

前端工具卡片展示当前与目标完整 URL、待核对 origin 及脱敏警告，不再提供打开目标设置的添加按钮。用户明确要求变更观察来源后，助手通过 `update_site_config(observation={trusted_origins: [...]}, operation_id=UUID)` 单独请求核对完整来源列表；不自动信任，不因全局默认值而跳过。批准后原调用恢复、替换观察来源，改变目标修订并释放旧浏览器；这本身不导航、执行或重试，模型可在同一轮安全重开/导航，无需再发消息。旧 `purpose: "trusted_origins"` 仍保留原来的合并行为供持久化兼容，不再推荐新调用。脱敏地址仍不能因为来源已获批准就变成可运行地址。

`trusted_origins` 默认空，最多 20 个公共 HTTP(S) 精确 origin（scheme、hostname、可选非默认端口），不含路径、查询、片段、用户信息或正则。交互/API 接收规范 origin，例如 `https://auth.example.com` 或 `https://auth.example.com:8443`，不是完整路径 URL；旧目标编辑器曾按行输入、接受并移除末尾 `/`，不是当前聊天页的预填步骤。原始目标源始终保留，额外来源仅由用户在宿主 UI 确认，模型参数、链接和聊天不能扩权。Worker 对原始源和额外源检查公共 DNS，并在导航、重定向和观察时继续校验目的地。**这只是观察/导航授权，不是额外来源的执行或凭据授权，也不会修改已保存站点的 `trusted_urls`。**

## 浏览器边界

公共非敏感查询参数与片段可用于打开、显式导航和重定向，例如首页跳转到 `/login?return_to=...`。观察不会统一去除这些内容，而是按上一节擦除敏感值。未批准跨源先返回可信来源确认要求；非公共地址、URL 用户名/密码及携带已知凭据的 URL 继续拒绝。`general` 停止不会阻止助手使用 `interaction`。

- 目标仅接受公共 HTTP(S) URL，可包含非敏感查询与片段，不允许 URL 用户名/密码、本地/私网地址、受限主机名、控制字符、反斜线及其编码逃逸；Worker 还检查 DNS 是否解析到公共地址。
- `browser_navigate` 在公共 `title` 字段之外，必须且只能提供 `path`（最多 2048 字符）或 `url`（最多 4096 字符）一个地址字段。`path` 是相对于目标 `base_url` 解析的引用，可含查询与片段，不得携带 scheme、authority 或 `//` 等源逃逸；`url` 是完整 HTTP(S) URL，只能导航到原始目标源或用户明确确认的 `trusted_origins`。scheme、hostname 或有效端口变化就是新源，不能由模型自动信任。
- 助手页默认对受路由约束的请求只允许 GET/HEAD，授权非只读单步活动期间才临时允许原始同源 POST；打开、导航和等待步骤从不开放 POST。观察阶段主框架文档导航及重定向限于原始源和用户确认的额外源，单步期间及结束后则限于原始源。阻止 WebSocket，并尝试关闭弹窗。单步之前公共子资源可能来自其他源，因此这不是“所有流量始终只到目标域名”的保证；单步后保留同源子资源限制。
- 观察和选择器检查使用固定的隔离世界只读脚本，模型只能传入受限参数，不能提供 JavaScript、执行任意代码、发起网络请求或按 ARIA role 操作。`browser_check_selector` 只查询匹配，不点击、填写、提交或派发事件；经授权的内置点击/认证仅能走上述单步工具。
- DOM 快照采集通用 HTML、自定义元素及可读的 open shadow DOM，不按登录/挑战元素白名单筛选，也不为特定站点或挑战提供专用规则。**隐藏节点保留并标记 `visible: false`，隐藏不等于不存在；表单值被省略/脱敏，不是删除隐藏节点。** DOM 工具不提供完整 HTML、Cookie、存储、网络响应或图像；独立截图工具见下文。
- 浏览器授权窗口从 Worker 创建会话起最多 **15 分钟**，不是每次观察续期；Worker 每约 5 秒回收过期资源。模型需重新 `browser_open` 才能恢复过期浏览器，已保存的目标本身不会因此删除。
- 修改目标会释放旧浏览器；显式取消、删除会话和服务关闭也会尝试清理。网络或关闭失败由 Worker 回收器继续处理；清理未确认时保留车道占用，不冒险复用。清理助手页不代表清除同车道 profile、Cookie 或人工标签页。

**这不是完整浏览器网络沙箱。** Chromium 独立解析 DNS，检查结果未固定到实际连接，存在 DNS rebinding 残余风险；既有共享 profile 的 service worker 不能靠 page routing 完全禁用；弹窗关闭前可能已经发出首个请求。代理车道仍需要 **Worker 本地 DNS** 能解析目标，解析失败会拒绝，并非完全由代理端解析。建议在浏览器及代理的网络层设置出站策略，阻断内网、环回、链路本地和云元数据等目标；不要把应用层检查当作完整 SSRF/出站隔离。即使 GET 也可能触发站点副作用，只访问你有权检查且确认可安全读取的路径。

## DOM 证据

`browser_observe` 返回扁平的 `elements` 数组，用 `parent_id` 重建层级，不是嵌套 HTML。每个节点含 `node_id`、`parent_id`、`frame_id`、`tag`、布尔 `visible` 和经过过滤的 `attributes`；可能另含 `text`、`has_shadow_root`，以及经采集时验证的 `selector`、`selector_source`（`id` / `name` / `dom_path`）、`selector_matches: 1`。节点 ID 只在对应 `snapshot_id` / `frame_id` 内有意义，父节点可能在前一页或所检查子树之外，不能因本页没看到父节点就认定其不存在。

`text` 仅是元素的直接子文本，规范空白后最多 300 字符，不聚合后代文本；按钮文案可能在其子 `span` 中。保留隐藏元素的普通文本，但不返回 script/style 等可执行或样式正文、template/noscript 正文、input/textarea/select/option 的文本和值，或可编辑区域正文。属性不是固定 id/name/type/role 白名单：在数量和长度限制内保留通用属性，过滤事件处理器、含 value 的属性名、敏感键及 style/srcdoc 等内容，URL 属性另行净化。每节点最多 24 个属性，普通属性值最多 512 字符，URL 属性最多 4096 字符，节点最多 8 KiB；已知凭据过滤还可能擦除文本/属性并移除受影响的选择器证明。这不是通用 DLP，隐藏普通文本、可见个人资料、属性及路径仍可能敏感。

| 工具 | 读取语义 |
| --- | --- |
| `browser_observe` | 可传 `frame_id`、`offset`、`limit`；默认主 frame、`offset: 0`、`limit: 100`。0 创建新快照，非零 offset 翻阅该 frame 最新的已捕获快照，不重新扫描 |
| `browser_inspect` | 必传 `snapshot_id`、`node_id`，可传 `offset` / `limit`；包含指定根节点，只分页读取该快照的不可变 **`captured_subtree`**，不是实时子树，也不接受选择器重新定位 |
| `browser_check_selector` | 必传 `selector`，可传 `frame_id`；读取该 frame 的实时 DOM，返回 `match_count`、`visible_count`、净化后的 `matches` 及 `truncated`。匹配包含隐藏节点；最多计数 10000，最多 10 个样本，样本还受响应字节限制 |

每次快照有界扫描最多 **5000 节点、深度 64、2 MiB 快照字节预算**，每浏览器会话最多缓存 **4 份**快照（各 frame 共用此数量）。普通 observe/inspect 每页最多 **100 节点且完整 JSON 最多 32 KiB**，所以第一页可能不足 100 个；`limit` 为 1-100，`offset` 为 0-5000。响应带 `snapshot_id`、`frame_id`、`offset`、`next_offset`、`total`、`truncated` 和 `limits`。`total` 是捕获集合的节点数，inspect 时是捕获子树的节点数，不是网站完整 DOM 总数；`next_offset` 非 null 表示还有已捕获节点可翻页，必须使用返回值而不是固定加 100。`truncated` 表示采集或 frame 元数据达到边界，不等于“还有下一页”；即使 `next_offset: null`，也可能仍有未捕获节点。

**inspect 无法恢复原始有界扫描之外的节点**，不能绕过节点数、深度或字节上限。新的 observe 可以刷新某 frame，但不是针对遗漏子树的深挖或无限扫描。observe 的非零 offset 跟随该 frame 的最新快照；若中间另有采集，先核对 `snapshot_id`。需要固定版本分页时，用原快照的文档根节点调用 inspect。缓存淘汰、导航或同 URL 重载均可能使引用失效；`browser_snapshot_stale` 时重新 observe，不能猜节点 ID。动态 DOM 更新不使缓存内容自动变成实时证据。

响应的 `frames` 列出有界的 frame 元数据（最多 64 个、12 KiB），含 `frame_id`、可选 `parent_frame_id`、净化 URL、`readable` 及不可读时的明确 `reason`，另有 `frames_truncated`。只允许读取原始同源或用户已批准观察来源且通过公共 URL/DNS 检查的 frame；不可读、未批准或不可用 frame 只提供元数据，**不能解释为其 DOM 或登录/挑战元素不存在**，元数据截断也不能证明未列出的 frame 不存在。读取 iframe 须使用实际返回的 `frame_id`，不会自动穿透，也不因此开放 iframe 单步执行或凭据使用；执行开始后的原始同源限制仍适用。

选择器检查仅支持 CSS 和显式 ` >>> ` 分段穿过 **open** shadow root，不支持闭合 shadow root、任意 Playwright 选择器引擎、JS 或自动穿透 iframe。`selector_matches: 1` 只证明采集时准确匹配该节点，不能从 id/name 重新拼接或猜测。写配置或做单步前，用 `browser_check_selector` 在正确 frame 复核数量、可见性及样本身份；隐藏匹配计入 `match_count`，`visible_count: 0` 不是零匹配。实时检查之后 DOM 仍可能变化，执行端仍会独立验证。`browser_selector_invalid` 应修正 CSS，`browser_frame_unavailable` 应刷新 frame 元数据；这两类错误和快照过期错误保留页面。

这里的 DOM 快照不是图像；不能仅凭 DOM 工具结果声称已看到截图。独立 JPEG 截图也不能因为密码被遮罩就视为完全安全，具体见下节。分页和无 ID 登录按钮的证据用法见 [发现指南](assistant-discovery.md#dom-分页与选择器核验)。

## 截图与恢复

### 截图证据

- 空闲时可点「截图预览」，需要当前目标的独立 `screenshot_consent: true` 及可用的助手浏览器；权限不足时应通过聊天让助手请求截图能力，不去预填目标设置。它不调用模型，只在当前 UI 内存显示；关闭预览即清除，不作为聊天图像持久化。统一执行授权、聊天中的“同意”或模型参数不能代替截图授权。
- 模型调用 `browser_screenshot` 时，宿主在缺少目标截图权限且未显式开启全局截图默认值时自动发起独立交互；用户批准后恢复同一调用，不需另发消息。还要求本轮配置 `supports_vision=true`。普通对话仍可使用文本模型；没有视觉能力返回 `model_vision_required`，不得假装已经看过像素。
- 两个入口均只截当前 viewport 的有界 **JPEG**，不是全页、PNG 或录像；最多 **1600 × 1200** 像素、**384 KiB（384 × 1024 bytes）**。遮罩表单输入区域（非按钮/复选框/单选框 input、textarea、select、可编辑区域）及所有 iframe/frame（包括已批准观察来源），不是遮住整个 form 的所有文本。API 独立校验图像并重新编码像素，移除 EXIF、注释、ICC 等嵌入元数据。尺寸、MIME、`masked`、图像 ID 和来源 URL 等证据元数据仍可返回。
- 遮罩不是通用图像 DLP，表单/iframe 之外仍可能有个人资料（PII）、账户文本或其他秘密。截图不能证明操作已失败、尚未提交或没有副作用；转圈也不是失败证明。可据此**询问用户是否确认刷新或重试**，不能据图自动刷新、重复提交或宣布成功。
- 模型截图的工具结果和 SSE 只携带文本/图像元数据与 owner 图片地址，不携带 base64 像素。完整一批工具结果之后，宿主才追加独立的 user 多模态证据消息，使用 `data:image/jpeg;base64,...` 给模型看图；图像及规范消息加密保存。图片不放进工具文本、摘要或历史摘录，不把 data URL 截断成不完整图像；大小预算仍有效。
- 撤销截图同意或目标修订变化后，历史图像像素在后续模型输入中被省略，即使关闭 `auto_compact` 也如此；重新同意不恢复旧修订像素。原始加密审计不删除，已发送的图像也无法撤回。owner 仍可通过受登录/归属保护的图片 GET 读取历史 JPEG；撤销控制的是后续模型重放，不是删除历史或撤销 owner 的读取权。UI 工具卡片只展示元数据，不自动加载历史图片地址。

### 刷新与重试

本节审批只针对 `execute_step` 的不明单步，不适用于完整 `run_site`；完整运行未知状态没有对应批准/核销 UI，见 [导入与完整测试](#导入与完整测试)。

「刷新会话」只读聊天状态；「刷新网页」需确认后对当前归属的助手页发起**新的 GET**，模型对应工具为 `browser_refresh`。实现不是 `reload()`，不会重放 POST；为确保发出 GET，使用当前 URL 去掉片段后的地址，保留查询，并清除旧 DOM 缓存。它仍检查 URL、公共 DNS、origin 及已知秘密，不能刷新任意模型指定地址。GET 本身也可能有业务副作用，不能仅因截图有 spinner 就自动刷新。刷新保留结果不明状态、账本及原页面归属，不证明旧操作失败，也不解除重试门禁。

结果不明时先保留页面做只读观察。用户明确要求重试时，正常流程是在**同一运行轮次、同一个工具调用内等待宿主批准并恢复**，不是让模型拒绝重试或要求批准后再发消息：

1. 模型调用 `retry_step`，除公共 `title` 外只传原 `operation_id`。若模型调用 `execute_step`，只有其规范化步骤与当前绑定下唯一一个可恢复的不明原操作**完全相同**时，宿主才将它转入同一审批流程；改步骤、匹配不唯一或仅换 UUID 不能绕过门禁，返回 `retry_step_mismatch` 时应使用原 ID 的 `retry_step`。
2. 宿主冻结服务端保存的规范化原步骤，暂停这个工具调用。会话和工具保持 `running`，详情/SSE 返回安全的 `pending_approval`，UI 在输入框上方内联显示风险确认，显示原操作 ID、功能和截止时间，可批准、拒绝，运行中仍可点输入区「停止」。这不是模型聊天生成的授权弹窗；聊天中说“同意”、模型参数、DOM 或摘要都不能签发授权。
3. 每次审批等待最多 **180 秒**，独立于本轮剩余活动预算；活动预算已耗尽时不弹出并返回超时。仅实际用户等待暂停活动计时、等量顺延共享截止时间及外层超时，不重置默认 180 秒活动预算。审批处理、网络请求和批准后的执行仍只使用剩余活动时间；提供商单请求超时、单步上限和浏览器 TTL 不变，停止及关闭服务仍立即取消。
4. owner 经登录和 CSRF 校验批准后，宿主立即恢复**原来暂停的调用**，生成关联重试 ID，先消费单次授权再私下解析凭据/派发，精确执行冻结步骤一次；无需再发用户消息，也无需模型另起一个执行调用。原始 origin、当前浏览器、目标修订、凭据绑定和所有当前权限仍须有效。批准不是结果成功证明，也不是“始终允许重试”权限，最初的统一授权范围、跨源及秘密边界均不变。
5. 拒绝返回 `retry_denied`，等待到期返回 `retry_approval_timeout`，授权/浏览器/目标/步骤绑定失效返回 `retry_approval_invalidated`；这些路径均不执行步骤。同一轮对同一原操作的决定/结果被缓存，反复调用不会重复询问或再次派发。下一轮用户**明确再要求**重试时，可重新请求一次审批，不是永久拒绝，也不自动重新请求。
6. 「停止」或 API 重启会取消未完成审批并清除 pending 状态，不自动恢复或执行；取消不能撤回已经派发的网站请求。刷新、SSE 重连和重新打开页面都不签发批准。下一轮明确要求重试仍需当前有效绑定及新的宿主批准。

可选的旧版空闲预授权入口仍保留：owner 在空闲恢复区域点「允许重试一次」，核对风险后签发 **5 分钟、当前浏览器绑定、单次使用**的原步骤授权。此入口本身不执行或自动发消息，之后可发消息让模型调用 `retry_step` 使用它；这不是上述运行中审批的必需前置步骤。稳定 `request_id` 仅幂等核对，不签新授权或续期。5 分钟是授权的**准入有效期**，不是审批等待时间或额外轮次预算；到期前已消费且绑定仍有效的结果可在到期后接收，不会再次派发。没有可安全恢复的旧步骤记录时不能授权；新目标/浏览器不清除不确定性，原 origin/凭据绑定不变且当前权限允许时才可能重新明确批准。

只有关联的、确实已派发的终态 `success` 重试能解除对应不确定性门禁，不证明原操作究竟成功还是失败。`failed`、`error`、元素缺失或批准本身均不能证明原操作失败；已知失败终态可再次明确请求批准，绝不自动续授权，重试仍 `unknown` 则针对新的不明重试记录请求批准。无关不明操作仍受阻。原始 `unknown` 历史、账本及受保护安全事实始终保留；历史 `no_retry: true` 或当前 `requires_host_approval: true` 的含义是**禁止自主重复，必须宿主批准**，不是永久禁止人工批准的重试。模型应使用当前宿主授权与关联 resolution，不因旧文字拒绝请求或要求批准后再发消息；最终权限始终由服务端校验。

只读观察/截图遇到 DNS 解析或读取策略失败时，可能返回 `page_retained: true`，**没有返回证据**但保留页面；不代表已读到 DOM/像素或操作失败。历史阻止记录可作为 warnings，不能把旧警告当作当前页面必然不安全。含已知秘密的当前 URL 拒绝仍属隐私致命错误，会关闭会话，不因“保留页面”策略放行。

## 历史与状态

- 聊天按登录用户名归属，不绑定某次登录会话。退出、登录过期或关闭页面不会删除聊天；同用户名重新登录后可继续。更换用户名不会自动转移记录，重新使用旧用户名也应考虑其历史访问权。
- 标题、标题控制字段、目标、执行 UUID 账本、上下文摘要及其边界/修订信息、结果不明操作的安全记录、模型用量和消息载荷（含工具标题、参数、结果与提案，以及供模型重建历史的规范消息）加密保存；owner、ID、角色、状态、时间和请求 UUID 等索引元数据不全是密文。站点修订绑定和完整操作账本不进入公开目标/模型上下文；结果不明操作的必要安全事实会单独提供给模型，以保留禁止重试提示。浏览器能力令牌仅在 API 内存中，不返回 UI 或模型，不持久化。
- 会话列表只返回按最近更新排列的最多 **100** 条；详情/SSE 只返回最新 **200** 条消息。这是读取窗口，不是保留数量上限；当前无旧消息分页、自动归档或聊天 TTL，删除会话才会删除其数据库消息，备份另行管理。
- 每轮按原始消息顺序重建模型历史，不再固定只取最近 100 条。`auto_compact=true` 时可使用「有效摘要 + 边界后历史」，达到整理条件时才压缩规范历史；关闭时忽略已有摘要及边界，从原始记录重建，不做有损工具投影。具体整理与读取边界见下文。
- 消息提交返回 `202` 后由 API 后台任务执行。切换会话、关闭标签页、SSE 断线乃至登录过期都不会自动取消；要停止助手轮次请在运行中的会话点「停止」。取消不能撤回已发送给模型或网站的请求，也不等于取消已经提交共享 executor 的完整任务；后者需在运行 UI 单独检查或取消，仍不能撤回已生效操作。
- 页面通过 SSE 接收整份会话快照，不是逐 token 输出；约每 0.5 秒检查一次，运行中发送更新，空闲未变化时发 heartbeat。模型请求明确使用 `stream: false`，所以要等每次完整响应，工具开始/完成仍可分别显示。
- SSE 会重新检查登录失效/撤销及归属，但不延长登录活跃期。原生 EventSource 可重连，页面不会自动重发消息或失败的修改请求。结果不明时先刷新核对，避免手动重复发送。
- 每条发送携带 `request_id` UUID；同一会话重复该 UUID 只返回现有状态，不追加消息、不重新运行，即使之前已取消或重启中断。UI 每次主动发送生成新 UUID，不能把新的手动发送当作旧请求重放。
- API 重启会把遗留助手轮次与工具日志标为中断/失败并恢复空闲，不自动续跑或重发；这不证明网站操作失败。已派发的单步保留 unknown 安全事实，未完成的工作流 action 保守记为 unknown，完整任务中断仍需人工核验。浏览器引用不跨 API 重启恢复，需重新打开；Worker 的 TTL 是残留资源清理后备。

工具卡片显示模型提供的短操作标题、工具名、状态和结果；它们是供用户阅读的操作/原因摘要，不是私有思维链。上游独立 reasoning 字段不会作为答案、历史或工具指令保存；普通答案和标题仍是模型生成的非可信内容，不能因此假定绝无敏感信息。

### 稳定请求历史

主对话的每次请求都是无状态的完整请求：代码维护的助手系统提示和当前宿主目标系统消息各出现一次，工具定义仍随请求发送。它们不会作为聊天消息反复追加或保存到历史中；不能因为前一次已发送就从下一次请求省略。用量账本也不会发送给模型。

新记录保存经过校验的规范模型消息，仅含允许的 `role`、`content`、`tool_calls` / `tool_call_id` 等对话字段；工具调用 ID、规范化参数字符串及序列化结果用于后续重建，而不是把 UI 工具卡片或整个加密载荷当成模型历史。不会保存或重发提供商原始响应、独立 `reasoning` / `reasoning_content` 等私有推理字段；下文的 `reasoning_tokens` 仅为数字计数。

设置、宿主目标/系统提示和工具定义保持不变、没有实际摘要或压缩且没有中断修复时，新规范记录的后续 `messages` 保持前次请求的精确前缀，只追加已完成的答案、用户消息和整批工具调用/结果。`auto_compact=true` 且低于整理阈值时同样保留这一前缀；实际摘要/压缩必须改变前缀，不能同时承诺压缩和逐字不变。

中断批次仅在模型输入投影中为缺失结果补静态失败记录，维持调用/结果配对，不重放已执行或尚未派发的旧调用，也不为修复改写审计记录。已持久化的旧版记录仍按安全的历史文本包装读取，不暴露私有参数或加密信封；旧记录若未保存原始调用 ID/规范消息，无法精确恢复当时的请求，也不会伪造迁移出原始 ID。已有摘要及边界可继续按整理规则读取，但迁移不能让旧历史获得新记录的精确前缀保证。

稳定前缀只是缓存的必要输入条件之一，不保证提供商缓存命中。实际结果还取决于模型/路由、缓存有效期、请求头，以及提供商对工具定义和提示的规范化等规则；以后台实际返回的缓存计数为准，不把本地 schema 缓存当作上游缓存或费用节省证明。

## 模型用量

详情/SSE 可选返回 `usage`，尚无已记录调用的旧会话可不含此字段；会话列表不携带逐调用账本。标题旁的上下文百分比及「上下文与累计用量」中的当前读数是**最近一次有效 `conversation` 报告的 `prompt_tokens + completion_tokens`**，不使用累计值或上游 `total_tokens` 作为分子。输入包含该次历史、系统提示及工具定义，输出是该次实际生成量；缓存命中另列为 `last_context_cached_tokens`。分母是该请求的 `context_max_tokens` 预算快照，不是后来修改的预算。`summary` / `title` 不覆盖当前读数，但仍进入累计消耗。

这不是实时测量：该次 completion 已包含在读数中，随后工具结果和未来输入仍需下一次真实对话报告。缺失/无效的 prompt、completion 或预算时跳过本次占用更新，不用本地估算或 0 补齐；保留整份最后有效读数及其原预算/修订，设置 `last_context_usage_missing: true`，前端明确标为最后已知、最近请求未上报，不能冒充最新值。从未有有效报告则显示 `--`；下一次有效对话报告更新读数并清除此标记。缺失报告仍进入调用明细和累计已知值，不从账本中丢弃。

整理或目标/上下文修订变化会使当前读数失效，显示 `--` 等待新报告，而不是保留旧百分比或宣称刚整理就测得占用下降；直到下一次匹配当前修订的真实对话报告才恢复读数。这与单纯缺失 usage 时保留最后有效值不同。旧版只有 prompt、没有分母的账本不得解释成新分子或当前百分比。`max_tokens` 仅限制输出，不代表实际输出、剩余上下文或模型容量。

展开「用量明细」可看会话累计已知值和最近 **100 次**调用，类型为 `conversation`（包括工具往返的每次模型请求）、`summary`、`title`。后端仅读取 Chat Completions 响应顶层 `usage`，不从工具结果中采集，也不估算：

| 公开计数 | 上游来源与含义 |
| --- | --- |
| `prompt_tokens` | 输入 Token，包含该请求发送的系统消息、历史、工具结果和工具定义 |
| `completion_tokens` | 输出 Token，包括提供商计入其中的推理 Token |
| `total_tokens` | 上游报告的总数，缺失时不以输入加输出推算 |
| `cached_tokens` | 优先取 `prompt_tokens_details.cached_tokens`；缺失/无效时回退 DeepSeek 的 `prompt_cache_hit_tokens`，两者不相加；0 是有效值 |
| `reasoning_tokens` | `completion_tokens_details.reasoning_tokens`，仅计数，不保存推理正文 |

缓存命中是输入的子集，推理是输出的子集，**不能再加到输入、输出或总计上重复计数**。`prompt_cache_miss_tokens` 不用于拼出缺失的输入计数；`input_tokens` / `output_tokens` 等其他协议别名不自动换算。计数须为有效非负整数；缺失或无效字段保留 null，明细 UI 显示 `--`（未返回），不是 0，不按文本长度或字节估算。当前占用只要求有效 prompt、completion 和预算；缺少 total 不妨碍两项相加的占用读数，但累计 total 仍不补算。

每次实际尝试发送模型 HTTP 请求只记一次；HTTP 错误、网络失败、超时、取消或无法安全解析响应仍计请求数，无法取得的计数为 null。安全解析出的用量可在后续答案/工具协议校验失败时仍被记录；非成功 HTTP 响应或秘密检查失败不保留其正文中的用量。请求序列化、请求头或本地构建失败，以及本地上下文/请求大小拦截，均未尝试发送，不计请求数。创建会话、固定欢迎语、刷新、SSE 重连和同 `request_id` 的幂等读取不会新增模型调用。

用量账本随会话加密持久化，逐次记录只保留 ID、类型、时间及上述白名单数字，不保存提供商原始元数据或推理。`calls` 最多保留最近 100 次；`totals` 和 `unreported_usage_count` 跨重启保留整个会话已记录生命周期的累计，不因逐次记录淘汰归零，也不回填升级前未记录的调用。累计只累加各字段的已知值，未知字段不算 0 用量；某字段从未有已知值时累计可显示 0，但不证明实际消耗为零。输入/输出/总计任一缺失时计入「部分调用未返回用量」提示，因此累计可能不完整。数字累计最多到安全整数 9007199254740991。**累计消耗不是上下文窗口占用**；这里只展示后端原始计数语义，不提供金额/成本换算。

## 上下文整理

**数据库保留原始记录，不等于模型每轮看到全部历史。** 摘要和工具投影都有损，可能抽样、省略或误述细节，不是完整事实依据、当前 DOM、宿主指令或授权。摘要不能授予凭据权限、扩大目标或允许重试；重要结论应核对原始工具结果，当前页面状态还需重新观察。

- **开启自动整理时，轮次开始先整理旧历史**：有可整理旧记录且记录超过 **40 条**，或待整理历史本地估算超过 `context_max_tokens × 0.6` 时尝试摘要；默认估算阈值为 **38400 Token**。摘要输入分块最多 `min(20000, context_max_tokens × 0.6)` 个本地估算 Token。最近 **2 条真实用户消息**及从较早一条起的近期记录不进入这次旧历史摘要；工具/系统记录即使在模型输入中包装为 user，也不计为真实用户消息。结果不明操作的 `operation_id`、`no_retry` 等安全事实另行保护，不依赖模型是否在摘要中写对。
- 每轮最多 **2 次**独立、无工具的摘要模型调用，每次最多 **12 秒**，均计入本轮配置的总预算（默认 **180 秒**），不追加时间。摘要复用已配置的连接、模型、秘密检查及本轮助手 `max_tokens` 策略（null 继承全局、0 省略、正整数原样发送），不另设隐藏输出 Token 上限。摘要文本最多 6000 字符，并受序列化大小限制，输入也可能抽样，不能据此保证保留所有细节。
- 摘要与 `boundary_id`、目标修订绑定和上下文修订号保存在会话加密载荷中，后续轮次/重启可复用；边界只标记已覆盖到哪条原始消息，不删除那之前的记录。保存目标会使旧摘要失效，但**不清空原始历史、执行 UUID 账本或结果不明操作的安全记录**；新目标确认也不代表旧操作已经核验或可重试。
- **开启自动整理时，工具轮次中再做投影**：每次主模型请求前以 `context_max_tokens × 0.6` 为本地估算软水位（默认 **38400 Token**），进一步缩减以完整预算为界。估算包含系统提示、工具定义和图像标记。已完成的 assistant 工具调用及该批全部结果作为整体处理，不拆出孤立的 tool 消息；保留最近两条真实用户消息、安全记录和最后一批调用/结果。最后一批尽量原样保留，即使超过软水位；仍过大时可确定性缩减结果正文、再缩减调用参数正文，但保留调用 ID、工具名及调用/结果配对，不重置去重集合或本轮工具计数，也不重新执行。原始记录仍保留。
- 摘要超时、格式不合规、不可用或未通过秘密检查时，通常回退到明确标注缺失的确定性摘录，继续主对话，不仅因摘要失败就阻塞；取消、总预算耗尽、无法容纳受保护内容或其他安全/请求边界仍会终止轮次。这不是“任何上下文都一定能继续”的保证。

`auto_compact=false` 跳过新的模型摘要、轮次开始和轮中的自动适配/缩减，**忽略已有摘要及其边界，从保留的原始历史重建输入**；也关闭旧版工具结果的有损正文投影。已有摘要、边界、上下文修订和原始记录仍保存在数据库中，不因关闭而删除或改写；重新开启后可按有效性规则复用。安全包装、禁止重试事实及中断调用的静态配对修复仍保留，不发送私有信封或提供商推理。旧记录无法找回从未保存的原始调用 ID，因此这不是恢复旧版精确线协议的保证。完整重建输入超过本地估算 Token 预算时以 `[context_limit]` 终止，超出线协议字节上限则受请求大小检查阻止，不暗中摘要、裁剪、改写历史或重放工具。

`get_tool_result` 可按当前用户、当前会话中的原始工具 `message_id` 读取已保存的结果正文，不要求该消息仍在最新 200 条详情窗口内。除公共 `title` 外，参数为 `message_id`、`offset`（默认 0）和 `limit`（默认/最多 **10000 字符**，最少 1）；offset/limit 计 Unicode 字符，不是节点数、字节或 Token。返回 `content`、`total`、`next_offset` 及工具名/标题/状态，按返回的下一偏移继续，单页可能只是 JSON 片段，拼接后才是完整 JSON。它不返回原始调用参数、私有绑定或加密信封，不访问浏览器、不调用网站、不重放执行，也不会另启一次专用模型调用；结果进入正常工具对话流程，仍消耗本轮工具/后续主模型请求预算。历史 DOM 结果只是旧快照，读取不能恢复浏览器缓存或使旧元素引用变成实时证据。

会话列表和详情在有已保存摘要时显示「较早上下文已整理，完整记录仍保留」，提示中包含上下文修订号。公开 `context` 含 `revision`、`summary_through_message_id`、`compressed`，不包含摘要正文；它不是 Token 使用率或费用仪表。标题修订和上下文修订相互独立；目标变更可清除摘要但不增加上下文修订号，不能只凭修订号相等就认定旧摘要仍有效。详情/SSE 仍只展示最新 200 条，数据库保留其余记录，当前没有通用旧聊天分页 UI。

`[context_limit]` 表示本地估算 Token/受保护内容预算仍无法满足，**不是提供商精确分词计数，也不是上游上下文窗口探测**。`context_max_tokens` 默认 **64000**、范围 **16000-1000000**；预检包含消息框架、系统文本、工具定义及图像标记。本地估算对 ASCII 按约 `ceil(chars / 3)`、非 ASCII 按 UTF-8 字节保守计数，图像使用低细节估算而非 base64 长度；它不写入用量账本，也不替代真实 usage。旧设置的 `ceil(bytes / 4)` 仅是迁移换算，不是当前估算算法。

线协议字节限制独立有效：含工具定义的整个主请求固定最多 **1536 KiB**，主响应 **256 KiB**；工具参数 **64 KiB**、结果 **128 KiB**，DOM、执行和截图另有各自边界。图像 data URL 不可截断，必要时以省略标记替代完整图像。JSON 转义、语言、工具 schema、图像和输出预算都会影响实际提供商 Token。低于本地估算预算不保证上游接受，也不保证历史完整保留。遇到提示先缩小本轮问题、聚焦选择器或局部子树、降低浏览分页 `limit`，必要时新建会话；不要通过重复登录/签到来恢复被压缩的细节。

用户可明确要求只读某个 frame、已捕获子树或选择器，并按需分页读取指定旧工具结果；系统不会为每次提问自动增加一次「全量重读历史」的模型调用。应在本轮复用已查询的功能 schema。缓存 schema 只能减少本地重复构造的 CPU 开销，不能据此免除仍随请求发送的工具定义/结果的输入 Token；实际用量及缺失值见 [模型用量](#模型用量)，不能把整理标记或缓存命中解释为已测得的成本节省。

## 工具与限制

当前 `assistant_prompt.tool_definitions()` 共 **28 个工具**，完整名称如下；提示和响应校验从代码定义取得工具名，不依赖文档中的固定计数。每次调用都需 1-120 字符的描述性 `title`，宿主分发前移除该公共字段。没有向模型返回凭据、修改集成或任意 JS/填充的工具；站点设置只能通过用户明确要求且逐项审核的 `update_site_config` 修改，导入及完整执行仍走独立授权的工作流工具。

| 系统数据（7） | `list_sites`、`get_site_config`、`list_templates`、`get_template_config`、`get_system_status`、`list_recent_runs`、`get_run_summary` |
| 历史结果（1） | `get_tool_result` |

### 导入与完整测试

`workflow_consent` 默认 false；用户要求导入/测试时，若没有已保存的目标权限或显式启用的全局 `auto_authorize_workflow`，宿主自动请求独立工作流授权，批准后恢复原调用。无需预填目标设置或批准后另发消息。旧会话、目标观察确认、执行授权或升级本身均不授予此权限；它覆盖导入和绑定站点完整测试，不只是保存草稿。确认目标/授予权限本身不导入、不创建任务。目标中的 `site_id` 只绑定凭据来源，`workflow_site_id` 才是配置导入/完整运行的目的站点，不能混用；目的站点必须与原始目标完全同源，空值表示导入时新建。

manual 模式导入也要求有效的同源凭据站点绑定，不能仅靠聊天声明或空 `site_id` 创建自动登录配置；绑定不意味着复制其凭据到新站点，完整运行仍按目的站点实际存储检查。

- `import_workflow_draft` 除公共 `title` 外只接受 `{proposal_message_id}`，不接受 `draft`、站点 ID 或配置覆盖。ID 必须来自当前 owner、当前会话、当前目标修订下成功保存的 `submit_workflow_draft` 工具消息，且 `unresolved_questions` 为空。导入精确读取该加密原提案，并按当前 schema、功能策略、继承配置和 URL 边界重新校验，不导入模型另传的 JSON。
- 更新已有目的站点时，用冻结的 `history_key` / `config_revision` 做 CAS 防覆盖，只替换本地 `steps`、`groups`、`signals` 和宿主确认的运行车道；保留名称、基础地址、模板、启用状态、调度、可信网址、凭据及其他站点元数据。真实配置变更会通过共享保存服务生成递增版本和不可变历史，不改写旧版本。已有本地步骤含模型不能还原的隐藏/受保护配置时返回 `protected_config_changed`，必须用人工编辑器处理，不能以脱敏占位值覆盖或静默丢弃。
- 新建站点默认 **`enabled: false`**，不启用调度、不复制凭据或助手浏览器 Cookie。用户可在正常编辑器自行启用，或在当前配置完整成功测试后明确要求 `update_site_config` 单独审核启用，后者不受全局工作流默认授权绕过。明确授权的助手完整测试可通过私有 `_allow_disabled` 入口测试该禁用站点，测试不会把它改为启用；这不是公开运行 API 的 force/绕过禁用参数。导入已有站点仍保留 enabled 与调度；调度/今日未成功筛选会跳过存在未核清助手运行结果的站点，不能自动重放来补结果。
- `run_site` 的业务参数只能是 `{}`，没有任意 `site_id`、批量/全部站点或 `force`。它只运行当前宿主绑定且修订仍匹配的单个已保存目的站点，创建持久运行记录后提交给共享 executor，不把发现页单步拼成完整运行。运行使用目的站点实际保存的凭据来源与 Cookie，并核对目标认证策略；manual 必须绑定该目的站点且确有已存密码，Cookie 模式须目的站点确有已存 Cookie，不能拿发现页人工登录的 Cookie 代替。Cookie / none 不允许认证步骤，Bitwarden 使用已保存站点的提供商策略，不把任何凭据交给模型。
- 完整运行仍拒绝 `post.*`、插件功能/提供商和 `action.fill`，包括从模板继承的步骤；继承不是绕过机制。工作流 URL（含继承步骤）必须为原始目标同源的公共、无敏感值地址，保留公开的完整路径、查询及片段；不同 origin 即使已列入 `trusted_origins` 也不开放完整运行 URL。此检查是静态配置边界，不是完整运行的重定向/网络沙箱保证。
- 提交时创建 `assistant_run_guards` 守卫，使用新解析的本地配置、解析后配置、祖先模板依赖及功能设置/策略快照计算哈希；executor 执行前再次检查当前值。身份、修订或这些配置漂移会以静态 `assistant_configuration_changed` 拒绝执行，而不是运行已变化配置。正常通用到交互的同代理模式回退仍允许，不误判为配置改变。
- 导入和运行都有持久 action 幂等记录。同一提案重复导入只重放原结果；同一绑定身份、修订及提案重复 `run_site` 返回原 `run_id`，不重新 submit。提交 executor 的确认丢失时返回 `ok: false`、`code: "run_submission_uncertain"`，保留 run ID 和 unknown action 状态；`submitted: false` 不是证明任务未到达 executor，后续调用只重放该结果，不自动补投或创建新任务。
- 新的助手导入通过共享保存服务新建或更新工作流时，保存 actor 的精确值为 `assistant`，所生成配置历史的 `created_by` 也为 `assistant`；新的助手完整运行保存 `Run.created_by: "assistant"` 和 `trigger: "assistant"`。真实人类身份仍由助手会话的 owner 及关联 `assistant_workflow_actions.owner` 保留并校验，不再存放在新运行的 `created_by` 中；会话/消息及 action 载荷加密保存，但 owner 等索引元数据本身并非全是密文。
- 运行列表创建人显示英文 `assistant`，tooltip 为「来源：智能助手」，不是显示实际人类发起人；通知的 `trigger_label` 同样是英文 `assistant`。助手工具卡仍提供站点/运行入口。这些规则仅用于新的助手操作，不迁移旧运行或配置历史。已有运行 329 保持 `trigger: "manual"`、`created_by: "admin"`，不能称为助手来源运行，也不能仅凭助手曾参与配置就改写来源。

**结果不明不是已知失败。** Worker 收到私有 `assistant_run` 标记后，可能已产生副作用的步骤发生异常/超时时记为 `unknown` / `outcome_uncertain`，不能降为普通 fail 再重复。传输失败也可能返回 `assistant_outcome_uncertain`。此时禁止新完整运行，也不能切换到主动单步登录/签到/点击来重做；先只读核验并交给人工。当前没有完整运行的宿主审批/核销 UI，单步 `retry_step` 审批不能解除完整运行门禁；不能承诺点“批准”即可恢复。需人工在运行 UI、网站或 VNC 核清实际业务状态，持续未决时由管理员排查；普通手动运行不会自动核销旧未知状态，任何人工再运行也应先防止重复副作用，不能作为助手绕过门禁的建议。

已完成且证据明确的失败，可依据下节安全诊断修正草稿，重新 validate、submit、import，保存新修订后再测试；同一修订重复调用不会得到“再跑一次”。未知结果不能通过改提案、改修订、换会话或换工具恢复缺失证据。

### 完整运行反馈

两个反馈工具只允许读取**当前 owner、当前会话关联创建的完整运行**，知道 `run_id` 或 `snapshot_id` 不能取得其他运行权限。普通历史运行查询工具的安全摘要范围不因此扩大。

| 工具 | 参数与安全投影 |
| --- | --- |
| `get_run_results` | `{run_id, cursor: 0, limit: 50, wait_seconds: 0, snapshot_id?}`；cursor 为非负索引，limit 1-50，wait_seconds 为整数 0-20。返回运行/任务/步骤状态，以及代码维护白名单内的 `code`、`reason`、`errorcode`、`field`、`stage`、`cause`、布尔结果和有界计数，不返回任意结果正文 |
| `get_run_log` | `{run_id, offset: 0, limit: 16000, snapshot_id?}`；offset 为非负字节偏移，limit 1-16000。`content` 是安全结构化诊断事件的分页序列，不是原始 artifact 日志；按 `next_offset` 继续，整体最多 65536 字节，可能截断 |

步骤行运行中可能原地更新，不是只追加的事件流。`snapshot_id` 是当前安全投影的 SHA-256 哈希（64 位小写十六进制），cursor/offset 只相对于该投影有效，不是永久事件 ID，也不是保留不可变运行快照的句柄。首页从 0 读取并取得 ID；非零 cursor/offset 必须携带该 ID。投影变化或 ID 不匹配时返回 `ok: false`、`run_snapshot_changed`、新 ID 和从 0 重启提示，不能把不同快照的页拼接成完整结果。结果最多投影 1000 步，注意 `truncated`；状态尚未结束不等于失败。

建议用 `wait_seconds: 10` 或 20 有界等待，避免密集零等待轮询；等待仍占本轮预算。工具在本轮内可继续读取，但**轮次结束后没有自动监看、再次调用模型或主动回来汇报的后台助手**。任务可能继续执行，用户可在运行 UI 查看，或下一条消息请助手读取结果；用 run ID 和当前状态说明未完成，不承诺任务结束后自动回答。

安全反馈只取应用自身产生的诊断枚举与类型受控计数，不把页面文本、运行时标签、完整站点 URL、原始错误/异常 dump、任意 data 或日志 artifact 当成可信模型证据。`get_run_log` 是 **curated structured diagnostic**，不是“脱敏后直接返回全部日志”；`raw_log_available_in_ui` 仅表示可在私有运行 UI 检查原始日志。完整原始日志仅供用户私下排查，不是模型安全输入，不要把密码、Cookie、完整日志或原始异常粘贴到聊天。可信观察来源也不授予额外凭据权限。

### 草稿修复诊断

`validate_workflow_draft` 失败返回顶层 `ok: false` 和最多 **10 项** `diagnostics`；`submit_workflow_draft` 重新校验时使用同一安全诊断投影。每项有代码维护的 `code`、`message` 和 `path` 数组；能安全定位本地步骤时另有 `step_key`、受审核的 `feature_type`，配置字段另有 `field`，边界错误可带 `hint`，例如 `ge=0`、`min_length=1`。`hint` 只说明允许的数值/长度约束，不给出管理员默认值或实际输入。路径可含从 0 开始的数组下标，但不回显未知属性名；无法安全定位时路径可为空，附加字段也可省略。

例如，缺少条件引用的信号时可返回以下假设响应；键仅用于定位本地草稿，不包含条件原文、信号内容或秘密：

```json
{
  "ok": false,
  "diagnostics": [{
    "code": "signal_missing",
    "message": "Define the signal referenced by this condition or change the condition.",
    "path": ["draft", "steps", 0, "condition"],
    "step_key": "test_login",
    "feature_type": "auth.form_login"
  }]
}
```

若当前策略要求 `submit_selector`，而有效配置中仍缺失，可在另一轮校验得到：

```json
{
  "ok": false,
  "diagnostics": [{
    "code": "field_required",
    "message": "Supply this required field; omission or null cannot satisfy the current policy.",
    "path": ["draft", "steps", 0, "config", "submit_selector"],
    "step_key": "test_login",
    "feature_type": "auth.form_login",
    "field": "submit_selector"
  }]
}
```

这不是缺失选择器的实际值，也不会把私有默认值、凭据、原始异常、Pydantic `input`/错误正文或管理端 local/resolved 预览交给模型。已知语义规则有具体修复反馈，例如 `flow.jump` 的目标含冒号时为 `flow_jump_target_invalid`，定位到 `config.target_step_key`，提示移除冒号并使用工作流步骤 key；不能仅回报笼统“配置错误”，也不回显有问题的目标值。未知校验规则使用静态 `field_invalid`，未知工具故障使用 `tool_failed` 等静态兜底，不从异常文本猜路径或提取秘密。

**最多 10 项是首个失败校验阶段的有界反馈，不是一次扫描所有步骤、所有阶段的全部错误。** 模型应按路径查看受控 schema，修复草稿并反复校验，直到通过后再提交；修复一项后可能才出现下一阶段错误，仍受原轮次预算限制。工具失败文字和日志也不得附带实际输入、秘密或管理员默认值；管理端原有可读错误字符串不因此变成模型安全输出。完整共享协议见 [Validation Diagnostics](config-ai.md#validation-diagnostics)。

| 边界 | 当前值（可调项列默认值，其余为固定限制） |
| --- | --- |
| 输入 | 重命名标题/站点名 1-128 字符；目标 URL 1-512；导航 `path` / `url` 1-2048 且二选一；`trusted_origins` 最多 20 个精确公共 origin；消息 1-12000；未知字段拒绝；宿主交互明确批准，消息 API 的发送同意仍必须是字面量 `true` |
| 修改接口原始请求体 | 最多 128 KiB，按实际流入字节计数；读体超时 10 秒 |
| 并发 | 每会话一轮；每 API 进程最多 2 个助手轮次，无队列或跨进程协调 |
| 每轮（可调） | 活动预算默认 180 秒（30-1800），不含实际等待用户确认的时间；主对话默认最多 12 次模型请求（1-100）、20 次工具调用（1-200），单响应默认最多 4 次调用（1-8），始终顺序执行；可另有最多 2 次摘要请求和一次下述标题请求，全部共用活动预算 |
| 上下文整理 | `auto_compact` 默认 true；有旧记录可整理且超过 40 条或预算 60% 本地估算时先摘要；摘要每次固定最多 12 秒；轮中软水位默认 38400 估算 Token，随预算缩放；不是提供商精确计数 |
| 自动标题 | `auto_title` 默认 true；仅前 3 条用户消息内的成功轮次且未锁定；独立、无工具调用固定最多 10 秒且计入配置的总预算；用户内容序列化预算约 8 KiB，响应最多 16 KiB，无重试 |
| 单步 | 活动最多 90 秒，受步骤超时/浏览器剩余 TTL 和本轮活动预算约束；不自主重试；每浏览器 20 个操作、每聊天会话账本 256 个 UUID；每次审批等待最多 180 秒，不消耗活动预算，批准后的执行仍计入；宿主重试授权 5 分钟准入、单次使用 |
| DOM | 扫描 5000 节点 / 深度 64 / 2 MiB，每浏览器缓存 4 份；普通分页 100 节点 / 32 KiB，执行前后每份 24 KiB；普通 Worker 响应读取上限 64 KiB，不等于通用工具结果上限 |
| 截图 | viewport JPEG 最多 1600 × 1200、384 KiB；截图内部 Worker 响应读取上限另为 544 KiB，以容纳 base64 及外层，不扩大普通 DOM/执行限制 |
| 模型 I/O | 主对话 HTTPX 超时 `min(vision_timeout, turn_timeout_seconds)` 秒，并受整轮剩余预算限制；不自动重试、不跟随重定向、不使用环境代理 |
| 模型请求 | 上下文预算默认 64000 Token（可调 16000-1000000），本地估算含系统提示、工具定义和图像标记；整个序列化请求固定最多 1536 KiB |
| 宿主交互 | 每次最多等待 180 秒，实际等待不消耗本轮活动预算，等量顺延截止时间；活动预算已耗尽不弹出，停止/关闭服务立即取消；同轮同 subject 不重复请求；通用问题最多 20 选项/8 字段，每字段最多 2000 字符，仅非秘密输入 |
| 模型响应 | 最多 256 KiB；要求 identity 编码，拒绝压缩；普通答案最多 24000 字符 |
| 工具 | 单次参数最多 64 KiB；单次结果最多 128 KiB；提交提案必须是该响应中唯一的调用 |
| 原始工具结果读取 | `get_tool_result` 限本用户/本会话的工具消息；offset/limit 按字符，limit 1-10000、默认 10000；不执行或重放 |
| 完整运行反馈 | 限本会话关联运行；结果 limit 1-50、等待 0-20 秒；结构化诊断日志 limit 1-16000 字节；非首页须携带当前 snapshot_id，变化后从 0 重启 |
| 提案 | 最多 50 steps、20 groups、30 signals；explanation 1-4000 字符；最多 20 个各 1-1000 字符的问题 |

异步超时不能硬中断同步校验或数据库阻塞，不是每个操作都能保证的硬墙钟截止时间。模型服务连接不走 SiteFlow 浏览器代理车道；目标 `proxy` 只控制发现浏览器车道，保存后的工作流另用 `run_lane_policy`。用户明确要求后，通过 `update_site_config` 分别审核 `observation.proxy` 与 `patch.lane_policy`，不从失败推断需要改设置；旧代理交互的 `scope` 仅描述兼容行为。

## API 与排查

所有路径以前缀 `/api/v1/assistant` 开始，要求登录；聊天接口按用户名校验归属，`/settings` 则是所有用户共用的全局设置。修改接口还要求登录会话绑定的 CSRF cookie 与 `X-CSRF-Token`。认证不更新登录活跃时间，响应使用 `Cache-Control: no-store`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /settings` | 读取全局 `{revision, source, values}`；无记录时 revision 为 0、source 为 `default`，不写数据库 |
| `PUT /settings` | `{expected_revision, values}`，CAS 保存全局设置，返回递增的 revision 及 source `db`；values 是替换而非 patch，省略的值字段按 schema 默认值补齐 |
| `POST /settings/reset` | `{expected_revision}`，CAS 写入全部默认值并递增修订，不清理聊天、标题锁或损坏记录 |
| `GET /sessions` | 会话列表 |
| `POST /sessions` | 直接创建，UI 发送 `{}`；可选 `title`、`consent_to_send`（默认 false）；非空显式标题锁定自动命名，创建不调用模型 |
| `GET /sessions/{uuid}` | 详情及最新消息 |
| `PUT /sessions/{uuid}/title` | `{title: "新标题"}`，去除首尾空白后 1-128 字符；仅空闲可改，永久锁定自动命名，返回更新详情 |
| `PUT /sessions/{uuid}/target` | 保留的旧宿主接口，非当前聊天 UI 前置步骤：`{authorized: true, name, base_url, credential_mode, site_id, workflow_site_id, proxy, run_lane_policy, trusted_origins, workflow_consent, screenshot_consent}`；两个站点 ID 可省略或为 null，可信源默认 `[]`，两个独立同意均默认 false，运行车道默认 `auto` |
| `POST /sessions/{uuid}/interactions/{interaction_id}/response` | 运行中 owner/CSRF 保护的宿主决定；`{decision: "approve"}` / `{decision: "deny"}`；选择问题批准附 `selections`，输入问题附 `values`，拒绝不带答案；绑定有效才由原等待调用应用结果，相同响应幂等、冲突拒绝 |
| `POST /sessions/{uuid}/messages` | `{content, consent_to_send: true, request_id: UUID}`，返回 202 |
| `POST /sessions/{uuid}/browser/screenshot` | 空对象 `{}`；空闲、owner、CSRF、截图同意检查后返回有界 JPEG 的 base64 及安全元数据，供临时 UI 预览，不调用模型或持久化此预览 |
| `POST /sessions/{uuid}/browser/refresh` | 空对象 `{}`；空闲、owner、CSRF 检查后以新 GET 刷新当前助手页，返回会话详情；不重提 POST 或解除不确定性 |
| `POST /sessions/{uuid}/retry-approvals/{approval_id}/decision` | `{decision: "approve"}` 或 `{decision: "deny"}`；运行中、owner、CSRF 检查后决定 pending 审批；批准立即恢复原调用一次，拒绝不执行，同决定重放幂等、冲突决定拒绝 |
| `POST /sessions/{uuid}/retry-authorizations` | 可选旧版空闲预授权：`{operation_id: UUID, confirmed: true, request_id: UUID}`；owner、CSRF 校验后批准冻结步骤一次，返回含公开 `retry_authorizations` 的详情，此入口不执行或自动发消息 |
| `GET /sessions/{uuid}/images/{image_id}` | 登录 owner 读取加密历史图像解密后的 JPEG，`no-store`、`nosniff`；不公开给其他用户，不是无鉴权图片地址 |
| `GET /sessions/{uuid}/events` | `event: update` 的 JSON 全量快照及注释 heartbeat |
| `POST /sessions/{uuid}/cancel` | 显式取消并释放助手浏览器 |
| `DELETE /sessions/{uuid}` | 删除空闲会话及消息，返回 204；运行中需先取消 |

列表/详情包含 `title`、`title_locked`、`title_revision`。目标请求中的 URL 和认证方式字段分别名为 `base_url`、`credential_mode`，`base_url` 可保留查询与片段；公开目标若含敏感参数会投影为脱敏地址，并标记 `base_url_redacted`、`redacted_parameters`，不能把该投影回填为可运行配置。`trusted_origins` 仅接受最多 20 个规范公共 origin，不接受完整路径 URL 或正则。`site_id` 默认 `null`，非空须为正整数的已保存站点 ID，必须与原始目标完全同源，额外可信源不能用于绑定；宿主冻结并复查身份与配置修订。模型可提出受类型约束的目标候选，但只有宿主明确确认才成为目标，不能直接提交权限补丁。

`workflow_site_id` 同样须为原始目标完全同源的正整数站点 ID，单独冻结目的站点身份/修订；它不从 `site_id` 自动推导。`workflow_consent` 不由旧 `authorized` 派生，旧目标缺字段按未同意处理；有效交互或用户明确启用的对应全局默认值才可授予。旧目标 API 的 `run_lane_policy` 允许 `auto`、`general`、`interaction`、`proxy_general`、`proxy_interaction`，默认 `auto` 实际为 `general`；新聊天目标默认 `general`。用户明确要求变更已保存目的站点车道后，用 `update_site_config` 的 `patch.lane_policy` 审核全部五种策略，与发现 `observation.proxy` 独立。四个工作流能力和设置工具都是模型工具，不是开放任意 JSON 保存或任意运行的公共 API 旁路；正常手动编辑/API 不受新增助手启用证据门禁影响。

详情/SSE 的 `pending_approval` 为 null 或仅包含 `id`、`operation_id`、`feature_type`、`status`、`created_at`、`expires_at`、`title` 的安全对象；不含冻结步骤、私有授权密钥、指纹或浏览器身份。通用 `pending_interaction` 另只公开 `id`、`kind`、`purpose`、`title`、`description`、`expires_at`、`options`、`multiple`、`fields`、`review`，不公开私有冻结参数/指纹。等待时会话仍运行，核对面板在输入框上方，可用「停止」取消；失效/拒绝/超时不执行，重启取消 pending 而不自动续跑。

新 UI 通过类型化宿主交互确认目标及执行/截图/工作流权限；设置变更统一由 `update_site_config` 生成内部 `site_config` 审核，不能从公共交互直接伪造该 purpose。通用问题不授予权限。统一执行权限派生凭据、副作用和冻结的当前功能清单，不包含截图/工作流，拒绝按整个执行能力去重。`manual` 且有站点绑定、或选择 `bitwarden` 时单步清单可包含上述 10 项；`manual` 未绑定及 `cookie` / `none` 排除两项认证功能，仍可浏览和测试其余受支持功能。绑定不保证凭据实际存在，执行时仍会检查。工作流权限独立控制导入及完整运行，不以单步执行授权为前提，也不能跳过设置差异审核。

旧接口的 `confirmed` / `browser_consent` 及细分权限字段仍用于已有调用和已保存目标；旧显式权限保持有效，不因迁移自动扩权。缺少权限时由宿主交互请求，或使用用户明确启用的对应全局默认值，不能由模型或后台迁移代为同意。

旧 `PUT /target` 替换宿主授权并释放旧浏览器，不是合并保留旧权限，运行中不可调用；当前 UI 没有目标设置弹窗。运行中目标交互可在绑定校验后建立新目标。仅为兼容保留的旧可信来源交互合并来源，旧代理交互按用户单选和 `scope` 更新目标字段；新调用一律使用 `update_site_config`，其观察来源替换完整列表，非空 patch 则对绑定站点实际 CAS 保存。目标修订改变后旧摘要/提案引用失效，旧浏览器需安全重开；不能把更换浏览器当作解除不确定性。能力授权保存在当前目标内，不要求重新确认整个目标。目标/能力确认本身不导航、导入、执行、重试或保存站点配置；设置批准则只保存已审核差异，不触发运行。旧目标修订的提案不能直接导入，应重新校验并提交。运行中人工改标题或删除仍被拒绝。

Worker 的 `/assistant-browser/*` 是 API 持有能力令牌调用的内部接口，不是公开工具分发器，不应暴露公网。新增内部接口 **`POST /assistant-browser/{session_id}/execute`** 接收 `token`、`operation_id`、`site_origin`、一个 `step`、`execution: {feature_types, allow_sign}`，仅认证步骤可带 API 私下提供的 `credentials`。返回绑定会话/车道/操作 ID 的状态、静态日志、前后 DOM 快照和安全结果。

职责分界：前端发送消息并提交宿主交互决定，也可显式请求截图预览、刷新或单步重试批准；API 核对用户归属、当前授权、站点修订，规范化步骤、登记持久 UUID/单次重试授权，并私下解析凭据；Worker 校验令牌、源、受控功能、原始表单能力与操作指纹，在现有页面执行单步并保留页面。完整工作流则由 API 的导入/运行 action 账本及配置守卫约束，经共享 executor 派发给 Worker，不走发现页的单步执行接口。内部截图/刷新分别走 `POST /assistant-browser/{session_id}/screenshot`、`POST /assistant-browser/{session_id}/refresh`；这些内部 HTTP POST 不等于允许目标网站 POST。**前端不直接调用 Worker `/execute`，模型也不获得 Worker URL、能力令牌、重试密钥或凭据参数。**

请求错误返回静态 `detail.code`，例如 `generation_disabled` / `model_unavailable` / `assistant_settings_invalid`（503）、`assistant_busy`（429）、`session_running` / `assistant_settings_conflict`（409）、`session_not_found`（404）、`invalid_request` / `secret_input`（422）、`request_limit`（413）、`request_timeout`（408）；登录和 CSRF 保留 401/403。已接受的后台轮次失败通常写入系统消息，例如 `[provider_timeout]`、`[provider_network]`、`[invalid_response:truncated]`、`[context_limit]`，不是把 202 改成错误响应。

遇到中断先「刷新会话」核对状态和工具结果，再决定是否发送新消息；这不是刷新网站或重试步骤。`browser_reopen_required` 需请模型重新打开，`target_confirmation_required` 需让助手发起目标交互并由用户在 UI 确认；`browser_trust_required` 需按工具卡片核对完整 URL 与 `target_origin`，只有用户明确要求变更来源后，才用 `update_site_config` 审核完整观察来源列表，不允许模型主动扩权或自动重试。`redacted_url_not_usable` 表示脱敏证据不能当作工作配置。持续 `browser_unavailable` 应检查配套 Worker 版本、交互车道占用、代理及 Worker 本地 DNS。`credential_binding_changed` 需重新核对并绑定当前站点，`operation_already_used` 不能靠换 UUID 重试不明操作，`outcome_uncertain` / `retry_authorization_required` 需先人工核验并走宿主重试批准。`screenshot_consent_required` 需独立图像同意，`model_vision_required` 需支持视觉的本轮配置，不能据此推断登录失败。不要通过向聊天粘贴凭据排障。已配置模型 Key 的泄露检测只覆盖已知字符串，不是通用 DLP；请求、DOM、链接和模型输出均须自行审核脱敏。

浏览器打开失败的工具结果返回安全的 `code`、`lane_key` 和 `reason`，例如 `code: "browser_unavailable"`、`lane_key: "proxy_interaction"`、`reason: "browser_dns_denied"`。按实际返回值排查，不把 Worker 原始异常、响应正文、凭据或未净化 URL 发送给模型：

| `reason` | 排查含义 |
| --- | --- |
| `browser_dns_denied` | Worker 本地 DNS 解析失败或解析结果不符合公共地址限制；代理车道也受此限制，不证明需要代理。读取失败若 `page_retained: true` 则无证据但保留页面，不是登录失败结论 |
| `browser_credential_endpoint_not_approved`（旧结果） | 旧端点策略诊断，不是缺少站点 ID、Bitwarden 故障或需网站专用适配；当前实现不要求逐表单批准 POST action |
| `browser_url_denied` / `browser_redirect_denied` | URL 或导航/重定向违反公共地址、原始源执行等边界；不要绕过限制。可供用户确认的公共跨源候选另以 `browser_trust_required` 返回 |
| `browser_lane_busy` | 所选交互车道占用或获取容量超时；核对该车道，不是通用车道 |
| `browser_lane_unavailable` | 所选车道租约、启动或浏览器上下文不可用；检查该车道及 Worker 配套版本 |
| `browser_access_denied` | Worker 返回 403，但未提供可识别的更具体安全原因；不能据此断言 DNS、代理或车道停止 |

此前生产环境观察到两次 `browser_open` 返回 403；没有证据表明由 `general` 停止导致，具体根因尚未确认。明确交互车道及增加安全诊断不等于已经完整修复该生产问题，也不能把离线测试通过当作生产复测成功。缺少具体原因时应明确原因未知，保留安全诊断供排查。
