# 智能助手

菜单「智能助手」（`/assistant`）提供持久化对话、脱敏系统数据查询、受限网站观察、显式授权的单步验证和待人工审核的工作流提案；另行明确授权后，可导入已保存提案并运行绑定站点的完整测试。站点编辑器中的独立「AI 生成配置」入口已移除，AI 辅助配置统一使用智能助手；共享协议及仍保留的单次生成后端接口见 [AI 配置协议](config-ai.md)。生成提案本身不会保存站点、运行任务或启用调度。**目标确认只授权浏览观察；统一执行授权才涵盖受支持的登录、签到、点击和挑战单步验证，会实际提交请求，可能产生费用或其他副作用，不是模拟运行。** 截图与工作流导入/完整测试分别受独立权限控制；购买/补签仅通过已保存完整工作流逐次消费审核，`action.fill` 仅填公开非秘密文本，不开放插件或任意代码执行。

当前共 **23 项内置功能**可编写提案并用于授权完整运行；单步为其中 **18 项**，普通交互工具为 **38**，另有 **1 个接管专用工具** `submit_takeover_conclusion`，注册表合计 39 个。另支持绑定站点 Cookie 私有注入与人工审核清除、审核后从绑定站点保存模板、全局调度变更、精确取消任务、历史版本与 artifact 读取，以及独立持久授权的失败接管。自动接管只暴露受限子集及专用结论工具，不是开放全部 39 个工具，也不能清除 Cookie。目录与 schema 按当前代码及服务端策略提供，能力可用不代表生产站点验证或业务成功保证。

外部 Agent 或 MCP 接入的独立审批、异步恢复和策略预授权建议见 [授权设计调研](assistant-agent-mcp-authorization.md)。该方案尚未实现，当前接口不是通用外部 Agent/MCP 服务。

## 启用与升级

- 设置 `SITEFLOW_CONFIG_AI_ENABLED=true`（默认关闭），复用「系统设置 / 大模型支持」中的 OpenAI 兼容连接、API Key、模型和模型超时，没有独立助手提供商配置；助手预算及可选的 `max_tokens` 覆盖在「助手设置」中调整。
- 模型必须支持 function/tool calling；普通文本或图片自测成功不代表工具调用可用。普通对话和 DOM 工具不要求视觉能力；`browser_screenshot` 另要求本轮模型配置 `supports_vision=true` 及宿主明确的实时截图同意。历史 `read_artifact_image` 同样要求视觉模型，但使用独立的历史资料发送授权，不要求实时浏览器截图同意；手动 UI 实时截图预览不要求视觉模型。
- 助手 `max_tokens` 默认为 null，继承全局模型配置；全局配置中 `SITEFLOW_VISION_MAX_TOKENS` 包括 0 在内会覆盖数据库设置。助手也可显式覆盖：正整数原样发送，0 省略参数、使用上游默认值，不代表无限输出。主对话、标题和摘要调用均使用本轮解析后的策略。思考模型也需留足最终答案和工具调用预算，系统不自动切换模型，见 [模型设置](vision-feature-settings.md#vision-integration)。
- 此功能需配套升级 **Web 前端、API、Worker 三个组件**。仅更新前端或 API 不会补齐 Worker 的浏览器接口；升级前停止助手轮次、工作流和人工浏览器会话。
- 当前以单 API 进程、单 Worker、持久化 SQLite 为部署前提。API 注册模型并通过 `Base.metadata.create_all()` 创建 `assistant_sessions`、`assistant_messages`、`assistant_workflow_actions`（操作幂等账本）、`assistant_run_guards`（运行配置守卫）及下文接管/通知记录表；工作流授权字段保存在加密目标 JSON 中，不需为其新增旧表列。`create_all()` 不是已有列的迁移机制，不承诺迁移历史开发版助手表结构。
- 标题锁定、标题修订号和命名尝试标记保存在现有加密 JSON 载荷中，本次标题功能不需要新增列或数据迁移。缺少这些字段的旧会话按标题已锁定、修订号 0 读取，不会自动改写旧标题。
- 备份数据库，并单独安全备份 `SITEFLOW_MASTER_KEY`；丢失密钥无法恢复加密聊天。不要把模型密钥、浏览器令牌、密码、Cookie 或未脱敏页面内容写入日志、工单或公开备份。

## 助手设置

页面顶部依次提供「助手接管」「助手设置」「新建会话」，无需先创建会话。打开、刷新、保存或恢复助手设置默认值均不调用模型。助手设置是所有用户、所有助手会话共用的全局配置，持久化在 `AppSetting` 的 `assistant.settings` 记录中，不是会话偏好；数据库备份应包含它。失败接管使用下文独立的持久委托，不沿用这些默认授权。

| 字段 | 默认值 | 范围与含义 |
| --- | --- | --- |
| `max_tool_calls` | 20 | 1-200，每条用户消息对应轮次的工具调用总数 |
| `max_model_rounds` | 12 | 1-100，主对话模型请求次数；不含独立标题/摘要调用，但它们共用总时间预算 |
| `max_parallel_tool_calls` | 4 | 1-8，模型一次响应最多发回的工具调用数 |
| `max_auth_uses_per_turn` | 3 | 1-20，助手单步及完整保存运行共享发起真实用户轮次的 auth 登录/密码验证尝试总数，含重试；解析凭据前预留，失败也计次；完整运行按实际新租约计次，条件跳过不计；2FA 属于 challenge，不占此额度 |
| `turn_timeout_seconds` | 180 | 30-1800，整轮活动时间预算，单位秒；不含等待用户确认 |
| `context_max_tokens` | 64000 | 16000-1000000，本地预检的上下文 Token 预算，不是提供商上下文容量声明 |
| `max_tokens` | null | null 继承全局；0 不向提供商发送该参数；正整数上限为 9007199254740991 |
| `auto_compact` | true | 自动生成旧历史摘要及轮中上下文整理；关闭后的具体边界见 [上下文整理](#上下文整理) |
| `auto_title` | true | 自动生成会话标题；仍受前三条用户消息窗口和标题锁约束 |
| `auto_authorize_execution` | false | 显式勾选后默认授予目标内统一执行能力，不是逐功能默认值 |
| `auto_authorize_screenshot` | false | 显式勾选后默认允许截图发送；不替代视觉能力检查 |
| `auto_authorize_workflow` | false | 显式勾选后默认允许提案导入与绑定站点完整测试，不只是生成提案 |

UI 的「每轮并行工具调用数」标签容易误解：它只限制**模型一次发回的最多工具数，不是并行执行数**。服务端始终逐个、顺序派发工具，不因调高该值并行操作网站。「模型输出上限」勾选「继承模型配置」发送 null；取消继承后留空或填 0 都发送 0，不是恢复继承。数字输入只接受范围内的十进制整数，不接受小数或科学计数法；API 数值必须是整数，开关必须是布尔值，未知字段拒绝。

每条新消息被接受时读取设置快照，**同一旧会话的后续消息也会使用新设置，正在运行的轮次保持原快照不变**。标题和摘要同样使用该快照中的 Token 覆盖及剩余总时间预算。关闭 `auto_title` 不改写最后的标题，也不解除人工重命名或显式创建标题的永久锁；重新启用或恢复默认同样不会解锁，也不会补做已错过的命名窗口。

对话框显示 `source`（`default` / `db`）及 `revision`。记录不存在时只读返回默认值、修订 0；保存与「恢复默认」均携带 `expected_revision`，通过原子比较并交换（CAS）防止覆盖其他客户端修改。成功后修订递增；恢复默认将默认值写入数据库，不是删除记录或把修订归零。冲突返回 409 `assistant_settings_conflict`，UI 保留草稿、不自动重试，需核对后刷新并重新编辑；刷新会丢弃草稿。请求失败或响应丢失不证明未保存，应先刷新核对。

持久化记录损坏、缺字段或越界时返回 503 `assistant_settings_invalid`，新消息也不能以默认值静默继续；读取、保存和恢复默认都不会覆盖损坏记录，**「恢复默认」不是损坏数据修复入口**，需管理员排查数据库。

三个全局授权默认值均关闭，只有用户明确勾选并保存才生效；它们相互独立，不能跳过目标身份、额外可信来源或代理的显式宿主确认。执行开关只控制发现浏览器中的单步能力；第三个工作流开关是原有的组合权限，**同时涵盖提案导入和绑定站点完整运行，不是仅保存，也不依赖单步执行开关**，不拆分为两个权限。界面明确显示「默认授权导入保存配置并触发真实完整工作流运行」及其业务风险。新轮次可对已确认目标应用对应默认值，已保存的目标/会话显式权限仍有效；关闭默认值不会追溯撤销已经授予目标的权限。认证仍需可用的私有凭据来源，不因默认授权扩大 origin、凭据或受支持功能范围。

仅对完整匹配已发布旧版结构的持久化设置，读取时将 `context_max_bytes` 按 `ceil(bytes / 4)` 近似换算，再钳制到新范围 16000-1000000；旧字段原有合法范围为 64000-1000000 bytes。三个新增授权默认值补为 false，不迁移出新权限。读取不写库、不改修订；下一次成功 CAS 保存/恢复默认才持久化新结构，仍比较原始旧记录。其他损坏或不完整结构不静默迁移。

这些设置仅影响持久化助手，不修改提供商 URL、API Key、模型连接，也不改变单次「AI 生成配置」接口及其限制。整个模型请求 **1536 KiB**、主模型响应 **256 KiB**、单步活动 **90 秒**、人工助手浏览器准入/创建起固定 **15 分钟 TTL** 等仍是固定边界，不是可调设置；消息不会续租，自动接管结束则提前释放本轮浏览器，见[排队与所有权](#排队与所有权)。调高 Token 预算不能绕过序列化线协议字节上限，也不保证上游模型接受百万 Token。

## 页面操作

1. 打开「智能助手」，点击「新建会话」即直接创建并选中会话，**没有标题或同意弹窗，也无需预填目标设置**。初始标题为「新会话」，第一条 assistant 欢迎语由服务端固定写入，不调用模型；创建不代表已访问网站。也可从左侧选择旧会话继续；刷新列表和刷新会话均只读取状态。
2. 先提供不含秘密的站点 URL 和期望流程，请助手先用 `check_site` 检查是否已配置，再澄清站点名称、认证方式、代理偏好和需求。该工具按 hostname 检查，只返回最多 20 个匹配站点的名称和净化后的基础地址，不读取工作流或凭据，也不进行网络探测；需要配置线索时可另外调用下文的脱敏数据工具。
3. 助手在聊天中收集名称和公共 URL，必要时澄清认证来源（`manual`、`bitwarden`、`cookie`、`none`），再用 `request_user_interaction` 的 `purpose: "target"` 发起宿主确认。输入框上方的目标核对面板只以可读字段展示网站名称和完整公共地址，不展示原始 JSON；同源凭据绑定 `site_id`、独立配置目的 `workflow_site_id`（空为新建）及授权字段保留在私有载荷中。用户核对后「确认并继续」，原调用即恢复，无需再发消息。模型提供的是候选，聊天中说“确认”不能代替宿主决定。即使开启全局授权默认值，目标仍必须明确确认。
4. 直接发送消息（支持 Ctrl+Enter）；发送即同意将消息、有限历史和已授权观察结果交给配置的模型，UI 不再要求发送前勾选。确认目标后请模型调用 `browser_open`，再 `browser_observe`；确认本身不会打开浏览器。无需目标也能先聊天、澄清或查询安全功能目录和脱敏系统数据，但浏览器、执行和提案工具必须有已确认目标。新目标默认关闭代理、完整运行默认保存为 `general`。用户明确要求变更设置后，统一通过 `update_site_config` 逐项核对精确变更；代理及可信来源不属于目标确认的附带授权，详见「站点设置变更」。
5. 先采集当前页面证据。需要登录时，可按下一节在 VNC 人工完成；或在统一执行授权且凭据来源可用时，用 `execute_step` 测试一次。缺少执行权限时由宿主请求交互确认，不要求预先操作设置。签到、点击、公开填充及挑战所需的副作用权限由宿主从统一执行授权派生，无需再勾选。比较可用的前后 DOM 证据，不把“已提交”当作成功；验证码处理后仍可观察、核验选择器、按独立授权截图及继续授权单步，不要求重开浏览器，输入值始终省略，见 [私有验证边界](#私有验证边界)。
6. 展开工具结果中的完整提案 JSON，审核 `proposal.draft` 的 `steps`、`groups`、`signals`、说明和待确认问题，并核对 `required_site_settings` 的 `credential_mode`、`credential_provider_id`、`lane_policy`。这里的运行车道独立于浏览观察代理；`trusted_origins` 只是观察来源说明，不自动推导或保存凭据授权 `trusted_urls`。跨源提示的 `trusted_url_pattern` 只是候选正则，不能直接当作凭据授权；用户明确要求后，可通过 `update_site_config` 精确审核已保存目的站点的 `trusted_urls`，或在正常编辑器另行审核。凭据和 Cookie 不在提案内。用户要求导入/测试时，模型可在同一轮继续，缺少工作流权限由宿主交互请求，批准后原调用恢复，不要求预先打开设置或另发消息；只生成提案也可结束。更换目标会改变目标修订，须在当前目标下重新校验提交，不能直接导入旧提案。导入必须引用宿主返回的已保存 `proposal_message_id`，不能把提交提案说成已经保存。
7. 使用下文的授权导入与完整测试流程，或在正常站点编辑器中人工复核、保存、校验并决定是否运行。助手页没有把任意 JSON 直接“一键应用”的入口；聊天中的工具调用只可导入本会话成功保存的原提案。手动复制时只使用工作流集合，不把整个工具响应当作站点导入数据，也不能使用脱敏占位 URL。校验或单步成功不是完整任务成功保证。

认证方式只是凭据来源声明，不能替代执行授权，也不会凭空提供凭据。`manual` 未绑定站点时仍可授权浏览和非认证测试；自动登录需先在站点管理保存凭据并绑定完全同源的站点，或选择 Bitwarden，再通过目标交互重新确认。凭据只在服务端私下传递，不进入模型。不要在聊天、标题、URL 路径、证据、选择器、说明或提案中放密码、Cookie、API Key、TOTP 秘钥/验证码等秘密。

标题/状态操作区和底部输入区固定保留在聊天面板中，只有消息时间线滚动；移动端同样保留输入与停止入口。安全提示可关闭，关闭状态仅存本浏览器 `localStorage`（`siteflow.assistant.safety.v1`），不是服务端授权、撤销、账号偏好或安全检查开关。

### 交互与授权

`request_user_interaction` 用于目标、能力授权和通用问题；可信来源、代理的旧 purpose 仅保留兼容，新设置变更统一使用 `update_site_config`。通用 `purpose: "question"` 可用 `kind: "authorization"` 做普通确认、`choice` 做单选/多选、`input` 收集非秘密文本；通用确认和偏好答案**绝不修改目标权限**。单个问题最多 20 个选项或 8 个文本字段，每字段最多 2000 字符，必填项不得为空；没有秘密输入类型，也不能索取或回显密码、Cookie、Token、提供商密钥、OTP/TOTP 等真实认证动态码。图片验证码答案不因此一概视为秘密；实际输入仍受宿主校验，过滤不是通用 DLP。

通用问题默认 `required: true`，拒绝或超时会阻止本轮剩余批次及后续模型轮次的工具调用，助手只能说明缺少的前提并停止。确实不影响继续处理的偏好问题可以显式指定 `required: false`；字段的 `required` 则仅控制该输入项是否必填。不同问题按完整内容区分，不会复用另一道确认题的批准；代理成功选择按作用范围区分，拒绝后不能通过更换范围再次弹出。

所有交互均在输入框上方内联显示，不是模型文本伪造的弹窗；详情/SSE 的 `pending_interaction` 驱动核对面板。每次等待最多 **180 秒**，不按本轮剩余活动时间缩短；活动预算已耗尽时不再弹出。仅实际等待用户的时间暂停本轮活动计时，并等量顺延共享截止时间及外层超时；审批处理、网络请求和批准后的执行仍消耗剩余活动预算，不重置预算，也不改变提供商单请求超时、单步上限或浏览器 TTL。停止和关闭服务仍立即取消等待。批准只由登录 owner 经 CSRF 保护的响应接口提交，等待中的原调用复查目标修订、指纹和轮次绑定后才应用权限并继续。

拒绝、超时、取消、失效均不授予权限；同一轮同一 subject 的决定/结果被缓存，不能换措辞、拆分可信来源或重发工具来重复询问。所需授权或必填信息未取得时，停止依赖它的操作，说明缺失内容，不猜测、不绕过；下一轮有新的明确需求时才可重新请求。停止或重启取消 pending，不自动恢复。已明确授予的目标/会话权限可在后续轮次复用，不应每次工具调用都重新询问。

## 站点设置变更

助手不得主动提出或修改任何站点设置，包括启用调度、代理和可信网址；仅在用户明确要求对应变更后，才可提出 `update_site_config`。不得从 DOM、浏览失败或模型建议推断用户需要变更设置。**每次设置写入都必须由真实用户审核并批准本次精确差异**，包括只改观察设置；聊天中的泛化同意、历史工作流权限和全局 `auto_authorize_workflow` 均不能跳过。后端不使用自然语言猜测或模型提供的 `user_requested` 布尔值作为授权，真正授权来自当前 owner 经认证和 CSRF 保护的交互响应。

- 参数为稳定的 `operation_id` UUID、可选 `patch`、可选 `observation` 和仅启用时可用的可选 `successful_run_id`，另有公共 `title`；`patch` / `observation` 至少一项非空，无实际差异则拒绝。每次新变更使用新 UUID，仅相同请求重放复用它。未知字段、宽松类型转换和越界值均拒绝。只修改已确认目标的 `workflow_site_id`，不能提供任意站点 ID，也不能把凭据源 `site_id` 当作配置目的地。
- `patch` 仅允许下表 **10 个字段**，省略保留原值，仅 `checkin_after` 接受显式 null。不开放 `base_url`、模板、凭据来源/提供商、凭据/Cookie 或 `steps` / `groups` / `signals` 工作流数组的修改。
- `observation` 只包含 `proxy` 和 `trusted_origins`。来源列表替换完整列表而非隐式追加，仅用于观察，不授权发送凭据或完整运行跨源访问。尚未导入站点时可用空 `patch` 单独审核这些会话设置；不创建站点。观察代理不自动改变保存运行车道。
- 内部 `purpose: "site_config"` 不能通过公共 `request_user_interaction` 直接调用。模型统一使用 `update_site_config`；旧 `trusted_origins` / `proxy` 交互保留既有持久化兼容行为，但已弃用，不再由提示词推荐。
- 公共审核对象为 `{name, base_url, site_id?, changes: [{field, label, before, after}], warnings, successful_run_id?}`。UI 以可读名称/地址、逐项「变更前 / 变更后」及风险提示展示，不要求用户审核原始 JSON。标签和风险提示由服务端生成。旧备注不展示，旧可信正则和标签仅显示数量；新可信正则精确展示、不以脱敏后的变形正则保存。`trusted_urls` 是本站点的凭据/TOTP 信任正则，不是观察白名单；Python 正则全匹配完整 HTTP(S) URL（含路径、查询和片段），宽泛规则可能泄露凭据。`observation.trusted_origins` 则只授权观察/导航，不授予凭据或完整运行访问权。已知秘密、敏感 URL 参数或脱敏占位值拒绝，过滤不是通用秘密检测。
- 每次调用等待最多 180 秒，实际等待不消耗活动预算。准备时冻结目的站点历史身份、修订、设置及精确补丁；批准后由原等待调用复查，而非响应接口立即写入。活跃任务、未决完整运行或单步不确定性阻止站点写入，不会被设置修改清除。
- 站点 CAS 写入、`assistant` 操作者的加密历史、新的目标/凭据绑定、目标修订、旧提案/摘要清除、重试授权失效及加密 `AssistantWorkflowAction(kind="site_config")` 回执在同一事务提交；工作流行和凭据保持不变，不确定性事实保留。提交后才关闭观察浏览器。相同 operation ID 和相同内容返回已存结果，不再修改；不同内容返回静态冲突。拒绝、超时、取消、重启或复查失败不会自动写入或重做。
- `enabled: true` 必须是唯一补丁字段，且不能带任何观察设置。准备与应用两次均要求当前 owner、当前会话的已完成 `kind="run"` action 关联持久化完整运行：`Run.trigger="assistant"`、`Run.status="success"`、已结束且未请求取消，整个 Run **有且仅有一个** SiteJob，属于该站点、已结束且 `status="success"`，严格守卫仍匹配当前站点历史身份、配置修订及有效配置指纹。可用 `successful_run_id` 指定证据，省略时服务端查找。排队/运行中、跳过、失败、未知、取消、孤立单步成功、手动运行、其他会话/用户或旧配置运行均不算。更改调度等设置后保守地要求重新完整测试，不沿用旧证据；完整测试本身不会启用调度。该门禁仅约束助手工具，正常编辑器和手动 API 的启用行为不变。

| `patch` 字段 | 含义与边界 |
| --- | --- |
| `name` | 站点名称，去除首尾空白后 1-128 字符 |
| `trusted_urls` | 最多 20 条精确审核的凭据信任正则，每条 1-1024 字符；拒绝首尾空白，空数组撤销额外信任 |
| `enabled` | 布尔值；true 启用调度须满足上述独立审核及完整成功证据要求，false 禁用也须审核 |
| `lane_policy` | `auto`、`general`、`interaction`、`proxy_general`、`proxy_interaction`；`auto` 当前解析为 `general` |
| `support_resign` | 是否允许补签；助手补签仅限逐次消费审核的完整运行，不支持孤立单步 |
| `resign_max_days` | 最大补签天数，严格整数 1-365 |
| `checkin_after` | `HH:MM` 签到起始时间；null 明确清除 |
| `timezone` | 有效时区名，1-64 字符 |
| `tags` | 最多 50 个标签，每个 1-128 字符 |
| `notes` | 最多 4000 字符的备注，不得放秘密 |

## 会话标题

- `auto_title=true` 时，未锁定的新会话仅在**前 3 条已接受的用户消息**对应的主对话成功完成后，尝试一次独立、无工具的小型标题模型调用。它复用同一连接、模型及本轮 Token 策略，不是另配小模型；输入仅为截至当时的前几条用户消息，不发送 DOM 或工具结果用于命名。
- 用户消息计数不是成功轮次计数。主对话失败或取消仍消耗前三条窗口，不会补到第 4 条以后；标题调用失败保留当前标题，不重试该次命名，不影响已经生成的答案。后续仍在前三条内的成功轮次可以再次命名。
- 标题调用最多 10 秒，且只使用本轮配置的总预算（默认 180 秒）的剩余时间，不追加预算。创建、读取、刷新或 SSE 重连不会触发命名。
- 空闲时可点「重命名」人工修改。保存后永久停止该会话的自动命名，没有解锁入口；通过创建 API 明确提供非空标题也会锁定。`title_revision` 单调增加，避免较旧的 SSE/列表响应覆盖新标题。

## 数据查询

这些工具读取站点、模板、运行和状态的专用安全投影，不是直接把管理端 API 响应交给模型。它们不需要浏览器目标确认，也不查询外部凭据；`get_system_status` 仅可读取 Bitwarden 的浅层健康状态，不查保险库条目。

| 工具 | 返回范围 |
| --- | --- |
| `list_sites` | `{query?, offset: 0, limit: 100}`，limit 1-100；按名称筛选并按 name、id 升序分页；非秘密元数据含 `id`、`history_key`、配置修订、模板/车道/凭据来源标识，不含账户值 |
| `get_site_config` | `{site_id}`；站点元数据含 `history_key`，并返回脱敏本地与解析后步骤、分组、信号及是否存在已保存凭据；不读取凭据明文 |
| `list_templates` / `get_template_config` | 列表同样接受 `{query?, offset: 0, limit: 100}`，limit 1-100，按 name、id 升序分页，含 `history_key`、`version`；详情按 template_id 读取脱敏本地/解析配置与信号 |
| `get_system_status` | 集成配置来源、Bitwarden 浅层健康状态和车道状态；其他集成仅返回配置元数据，不返回服务密钥或连接地址 |
| `list_recent_runs` | `{site_id?, offset: 0, limit: 20}`，limit 1-20；按 created_at、id 降序分页，返回运行元数据和整次运行的任务状态计数 |
| `get_run_summary` | `{run_id, offset: 0, limit: 100}`，limit 1-100；按 SiteJob.id 升序分页的是 `jobs`，不是运行；`run` 的元数据、`job_count` / `job_counts` 仍覆盖整次运行，不随页缩小；不含原始日志、消息、结果或截图附件 |

上述分页工具的 `offset` 是非负严格整数（默认 0），`limit` 也是严格整数；可选 `query` 最多 200 字符，仅对名称做不区分大小写的子串筛选，不搜索秘密 URL。响应含 `offset`、`limit`、`next_offset`，到本次读取末尾为 `next_offset: null`；列表以 `truncated`、运行任务页以 `jobs_truncated` 表示本次读取是否还有后续行，**不承诺返回 `total`**。应跟随实际 `next_offset`，不要把一页当完整清单，也不要把运行的 `job_count` 当作所有列表都支持的总数契约。

这些列表是**实时 offset 分页，不是冻结快照**。排序字段和 ID 提供确定的次序，但并发新增、删除、改名或更新仍可能令跨页结果重叠或遗漏；客户端应按对象 ID 去重并刷新核对，不保证一次遍历恰好覆盖全部对象。这与下文 DOM 缓存快照及完整运行反馈的 `snapshot_id` 契约不同。

历史发现可先从 `list_sites` / `get_site_config` 的 `history_key`，或模板列表/详情的同名字段取得稳定 UUID，再调用 `list_workflow_versions` / `get_workflow_version`；不要以可能复用的整数 ID 代替历史身份。它来自站点安全投影 `_SITE_FIELDS`，不是凭据读取或新增授权。

`get_system_status` 的 Bitwarden 状态与系统设置共用 `BitwardenService.view(force=False, deep=False)`，优先使用约 15 秒的浅层健康缓存，缓存失效时可请求 `/health`，不强制刷新，也不调用 `/check` 或 `/lookup`。它只返回 `enabled`、`enabled_setting`、`available`、`configured`、`auto_detected` 等布尔状态及 `source`、`enabled_source`、`url.source`、`token.configured`、`token.source` 和 `sources` 来源元数据；来源包括 `env`、`db`、`auto`、`unset`。默认地址自动检测的 URL 来源为 `auto`，启用来源另按实际配置解析。`available` 表示浅层健康可达，`configured` 表示服务报告保险库已配置并就绪，`enabled` 是有效启用状态；显式禁用会被尊重，未探测时 `configured` 也可能为 false，与设置页一致。可选包装服务 Token 未设置不代表不可用，不能据此要求用户补 Token。状态不是站点凭据匹配或登录成功的保证。

Bitwarden 项的 `health_checked: true` 表示已使用上述健康视图，可能来自缓存，显式禁用时也不保证发出新请求；其他集成的 `health_checked: false`、`available: null` 表示未探测而非不可用。顶层 `health_checked: false` 配合 `health_scope: ["bitwarden"]` 表示没有对全部集成做健康检查。后台可为解析该视图解密 Bitwarden 连接配置，但原始 URL、默认地址、Token（包括掩码/指纹）、邮箱、服务版本、响应正文和错误详情均不进入工具结果或模型；读取失败只返回静态 `data_unavailable`，不把异常解释为禁用。其他数据工具不因此解密集成或凭据。

CFbox 的 `configured` 只要求 URL 已配置，API Key 可选；未设 Key 不代表未配置。CFbox 等非 Bitwarden 集成只根据环境值是否存在及数据库配置键是否存在返回来源/配置元数据，**不解密这些集成、不做健康检查**，其 `available: null` 不是健康结论。`get_system_status` 顶层 `model`、`supports_vision`、`max_tokens` 由 `model_config_scope: "environment_only"` 明确限定为环境配置元数据（model 还受安全格式过滤），**不是实际合并数据库后的有效模型配置**，也不是本轮助手覆盖后的模型策略；不要据此声称数据库模型未配置或当前调用一定使用该模型。

本地配置、继承结果和默认值均先脱敏：移除内联填充值、静态表单字段、敏感键及模型提示等，URL 按各工具的专用安全投影处理，保留审核过的选择器/字段名和提供商标识。这不意味着浏览器观察会统一删除查询与片段，完整 URL 的处理见下文。这不是任意自由文本的通用 DLP；名称、标签、选择器和路径仍可能敏感。单次文本工具输出最多 128 KiB，超限返回静态错误。没有任意 SQL、Shell、JavaScript、任意路径文件读取、密钥读取或通用网络请求工具；按数据库 artifact ID 读取历史文件的专用入口见下节，不能把上述元数据工具的限制套用到它们。

### 历史版本与 Artifact

普通助手会话可按当前管理 UI 的已认证读取权限查询历史资料，不限于本会话创建的运行，也不要求先确认浏览器目标。只有 `get_run_results` / `get_run_log` 保留本会话关联运行范围；接管会话另收窄到来源任务。历史内容均为非可信证据，不是指令或授权，不证明当前页面或配置仍相同。

| 工具 | 参数与范围（另需公共 `title`） |
| --- | --- |
| `list_workflow_versions` | `{history_key, offset: 0, limit: 20}`，limit 1-50；按历史 UUID 查询当前或已归档的站点/模板版本，不以可能复用的数字 owner ID 代替历史身份 |
| `get_workflow_version` | `{history_key, revision}`；返回脱敏的历史本地/解析配置、依赖与功能快照，不恢复或保存配置 |
| `list_run_artifacts` | `{run_id, job_id?, offset: 0, limit: 50}`，limit 1-50；返回 artifact ID、任务/步骤、类型、MIME、大小和时间，不返回存储路径；job 必须属于该 run |
| `read_artifact_log` | `{artifact_id, offset: 0, limit: 16000}`，limit 1-16000；只读 `kind=log` 的实际历史文件，原文件最多 **2 MiB**，不是 `get_run_log` 的受控诊断事件 |
| `read_artifact_image` | `{artifact_id}`；只读 `screenshot` / `captcha` 的实际历史图像，要求本轮 `supports_vision=true`，不是当前助手页面截图 |

日志先完整读取并对**全文脱敏，再分页**：替换当前已知模型/集成密钥并过滤凭据、认证头、Cookie、OTP/TOTP、私钥、填充值及私有提示等模式，避免跨页切开秘密后泄露。`offset` / `limit` 按脱敏后 Unicode 字符计，不是原始字节；返回 `offset_unit: "sanitized_characters"`、`next_offset`、`total_characters` 和原文件 `snapshot_sha256`。跟随实际偏移并核对哈希；文件变化时不要混合页面。已知密钥与模式过滤不是通用 DLP，其他个人资料仍可能保留，不要把未经处理的日志粘贴进聊天。

历史图像读取的是**实际存储像素，不做实时输入遮罩**，`provenance.masked=false`，可能含个人资料或凭据。输入限 PNG/JPEG、2 MiB、2000 万像素，宿主解码、按比例缩小到最多 **1600 × 1200**，重新编码为最多 **384 KiB JPEG** 并移除 EXIF/注释等嵌入元数据；移除元数据和缩图不等于像素脱敏。用户明确要求发送历史图片后由宿主追加多模态证据，工具文本/SSE 仅有 ID、来源、owner 图片 URL 和尺寸，不以只有元数据的结果冒充看过图。图像与消息加密保存，历史资料授权独立于实时 `screenshot_consent`，更改浏览器目标或撤销实时截图同意不会撤回此历史授权或已发送像素；owner 图片 GET 仍受归属校验。

文件入口只接受数据库 artifact ID，并核对 Run/SiteJob 关联；路径由宿主从记录解析，限制在 artifact 根目录内，拒绝绝对路径、路径逃逸、符号链接、特殊文件、读取中变化和超限文件。它们不是任意路径或任意文件读取工具。

## 从站点保存模板

人工入口在「模板管理」的新建/编辑器中，点击「从站点导入配置」，选择来源站点并确认替换。`GET /api/v1/templates/import-from-site/{site_id}` 只读返回来源的**本地** `steps`、`groups`、`signals`，将来源 `template_id` 映射为目的 `parent_id`，不是把解析结果拍平。只替换表单的这三集合和父模板，保留当前名称、描述、启用状态；不复制站点凭据、Cookie、调度或其他元数据，不改变来源站点，**不会自动保存或运行**，仍需人工校验并保存。会造成循环继承、来源工作流无效/为空（无父模板且无步骤）、有活动任务或结果不明时拒绝。

助手入口为 `create_template_from_site`，仅在用户明确要求后使用。除公共 `title` 外，参数为 `{operation_id, name, description?, destination_template_id?, expected_revision?, expected_history_key?}`：UUID 对每次新操作唯一，name 为无首尾空白的 1-128 字符，description 最多 4000 字符。来源只能是宿主已确认的已保存 `workflow_site_id`，不是凭据 `site_id`，也没有任意来源 ID 参数。**有效、无活动/不明任务的已配置站点不要求先有一次成功的助手完整运行**；不要把启用站点的成功证据门禁误用于此工具。

省略目的 ID 时新建模板；替换已有模板时必须同时提供当前 `expected_revision` 和历史 UUID `expected_history_key`，由当前模板证据取得。替换使用来源父模板和完整本地三集合，不做隐式合并；保留目的名称、描述和 enabled，不能用请求的名称/描述改写这些元数据。**助手替换必须保留目的原有分组及已有步骤的相对顺序**：不能删除、重命名或重排原有分组，不能删除已有步骤、改变其所属分组或重排已有步骤；允许更新步骤配置，允许新增分组及步骤并插入原结构之间。宿主比较替换前后解析结构，连同继承项一起检查；不兼容的来源候选直接拒绝，不静默补回、移动或重写配置。人工编辑器原有被引用模板限制继续生效，不等同于此助手额外约束。新建沿用模板模型默认 `enabled=true`，不复制源站点 enabled；模板启用不等于运行站点。来源站点始终不变，不复制秘密或站点设置，不自动运行。

每次都通过宿主 `template_import` 面板审核实际候选及配置差异，已有工作流权限或全局自动授权均不能跳过。面板可展开查看本地步骤、分组、信号以及父模板；替换显示新增/修改/删除项及安全字段前后值，原有分组和步骤的保留约束仍由后端执行，不能靠点击批准绕过。公开审核不包含受保护配置值；无法安全展示的候选拒绝，不能以截断的差异冒充完整审核。准备时冻结来源绑定/快照、目的身份/修订/快照及双方祖先依赖；批准后复查原绑定与快照，以条件更新序列化来源、目的及模板依赖，再校验和 CAS 保存。来源/目的/依赖漂移、循环继承、隐藏受保护配置、拒绝、超时或取消均不写入。模板历史和加密 `template_import` action 回执同事务提交；相同 operation ID/相同请求且来源绑定仍有效只重放原结果，不重复保存，不同内容同 ID 冲突。人工导入表单没有这项助手持久审核/来源冻结事务，不应混同。

公开候选保留来源本地三集合的精确数组顺序及 `position` / `step_anchor` 原值，`before` 为目的原**本地**三集合及父模板（新建为 null），不是继承展开后的有效工作流。UI 按步骤/分组/信号 key 展示字段前后值及共有项的数组相对顺序，不把插入新项当重排；旧持久审批缺少 `before` 时明示基线不可用，不推测旧工作流。后端在准备和应用时均检查解析结构；数值位置及锚点可变，只须原分组/步骤的相对顺序保持。受保护配置无法安全展示时 fail closed，不用隐藏标记冒充精确审核；人工编辑器导入行为不变。

## 调度与取消

`get_scheduler_settings` 除公共 `title` 外无业务参数，不需要站点目标，返回 **全局**调度的有效值、来源、`editable`、`revision`、时区及 `next_run_at`。它不是本站点的 enabled、checkin_after 或 timezone。

仅在用户明确要求全局调度变更后调用 `update_scheduler_settings({operation_id, patch})`。patch 为非空稀疏补丁，省略保留原值，显式 null、未知字段或无实际差异均拒绝；只允许 `enabled`（布尔）、`mode`（cron/interval/random）、`cron`（最多 128 字符的有效五字段表达式）、`interval_seconds`（严格整数 60-2592000）和 `ranges`（最多 20 个当日 `HH:MM-HH:MM` 时间段，结束晚于开始，random 至少一项）。模式和值组合仍由共享调度服务校验。

每次精确变更均展示 `scheduler_config` 宿主审核，自动授权不能跳过；最多等待 180 秒，实际用户等待暂停活动预算。任何调度配置环境覆盖（enabled/mode/cron/interval/ranges）锁定全局调度编辑，不是只锁某一字段；时区仅由 `SITEFLOW_SCHEDULER_TIMEZONE` 环境管理，**不在补丁内，单独设置时区不锁定其他调度字段**。准备时冻结配置修订、原始配置及环境绑定；批准后复查锁与绑定、CAS 修订并只写实际补丁，设置与加密 action 回执同事务提交。动态 `next_run_at` 不属于配置绑定/CAS 冲突依据，正常调度推进不会使审核过期；成功变更会重新计算下一次运行。相同 UUID/请求只重放结果，拒绝、超时、取消、环境/配置漂移不自动写入或重试。

用户明确要求取消时，`cancel_run({run_id})` 对精确运行展示宿主 `run_cancel` 面板，含来源、状态及最多 50 个站点任务；不局限于本会话发起的运行。批准后先提交取消状态，再对仍活动的运行调用真实共享 `executor.cancel(run_id)`。排队任务原子标为 canceled；运行中只设 `cancel_requested` 并尝试通知 executor。按实际返回的 `status`、`cancel_requested`、`finished`、`worker_cancel_delivered` 报告，**取消已请求/通知已送达不等于 Worker 已停止**，更不能撤回已完成动作。终态读取只返回现状，不重新停止。拒绝/超时不取消；失败或断线后先核对状态，不能声称必然未取消。

聊天底部「停止」只停止助手轮次/等待并清理助手浏览器，不自动取消已提交任务；任务取消需上述独立确认或运行 UI。取消也不清除未知结果门禁。

## 失败接管

顶部「助手接管」在「助手设置」之前，可不创建会话直接打开。新策略默认 `enabled=false`、`live_access=true`、`mode="analysis"`、`site_ids=[]`、`max_attempts=1`。接管整体仍默认关闭，空列表不接管任何站点；`live_access` 是严格布尔值，对应唯一的「授权无人值守浏览与单步验证（权限保留供后续对话）」复选框，没有另一个浏览器功能开关。默认勾选不等于已授权，须核对风险并保存策略才生效。选择 ID 列表仅覆盖所选且当前启用的站点，**null 明确授权所有当前及未来启用站点**。`max_attempts` 只能为严格整数 **1-3**，限制接管模型轮次尝试，不是业务任务自动重跑次数。

`TakeoverValues.conclusion_ttl_days` 默认 **7**，只接受 **1-30 的严格整数**；字符串、布尔值、小数（包括 `7.0`）、null 或越界值均拒绝。接管面板提供「结论复用有效期（1..30 天，默认 7 天）」输入，并在保存确认中展示；这是结论复用期限，不是浏览器租约、聊天保留期限或任务重试次数。

仅对**完全匹配旧版已存结构**的策略，允许缺少 `conclusion_ttl_days`、`live_access` 或两者：读取时缺 TTL 补 7，缺 live_access 补 false，不写库、不改修订、owner、授权/生效时间，也不扩张旧委托；已有明确 live_access 保持原值。旧用户须重新勾选并确认保存才能新增实时能力，其他损坏/不完整结构仍拒绝。下一次显式 CAS 保存才持久化完整结构；启用策略的 API 请求必须在 `values` 中显式提供 `live_access`，不能靠新模型默认值取得权限。

每次新的复用判断读取**当前已保存**的 TTL，不沿用原结论创建时的策略值。更改 TTL 仍走原有策略保存流程：`expected_revision` CAS、修订递增，并更新 `authorized_at` / `effective_from`；不是绕过生效时间的独立更新入口。保存本身不调查旧任务，也不改写已有 reused action 或冻结通知，精确年龄规则见[相同失败去重](#相同失败去重)。

这是独立全局持久委托，保存在 `AppSetting` 的 `assistant.takeover.settings`，不从助手设置的三个自动授权开关继承。保存前 UI 明确核对开关、实时能力、模式、站点范围和尝试上限，并提示失败报告、日志和**未遮罩历史图像**可能发送给配置的模型；实时授权还涵盖页面内容、输入遮罩截图及私有凭据参与的真实登录、签到和点击风险。`GET /api/v1/assistant/takeover/settings` 读取；`PUT` 必须提交 `{expected_revision, confirm: true, values}`，字面量 true 才有效。宿主用当前登录用户名写入 `authorizing_owner`、`authorized_at`、`effective_from`，不接受模型/调用方代选 owner。修订 CAS 冲突为 409 `takeover_settings_conflict`；损坏为 503 `takeover_settings_invalid`，不以默认值覆盖。保存或响应不明先刷新核对，不自动重试；刷新会丢弃草稿。打开、刷新和保存策略本身不调用模型、不启动浏览器或任务，也不立即为旧失败启动分析；后台只处理生效后符合条件的新失败。

`live_access=true` 且选择具体站点时，策略保存事务会冻结每个站点的 `history_key` 和规范 origin，写入独立 `AppSetting` 键 `assistant.takeover.site_grants`，结构为 `{revision, bindings: {"站点ID": {history_key, origin}}}`，与策略 CAS 同事务提交。准入复查策略修订、完整所选 ID 集合及当前身份/origin，不能把可复用的数字 ID 当作永久授权；所选站点不可用时保存失败。**旧 live 策略若缺少绑定记录，或绑定损坏、修订/范围不匹配，均 fail closed，不启动所选站点接管；须核对并重新保存策略**，读取不会替旧用户生成授权。`site_ids=null` 是对所有当前及未来启用站点的明确范围授权，不要求预存未来站点绑定，但每个实际 action 仍冻结具体站点历史身份、origin、策略修订及来源任务；导航不能改写或扩张这些范围。身份、origin 或相关绑定变化后须重新确认，不能沿用旧站点授权。

接管失败、错误和需要人工的任务；已推迟不接管。准入只覆盖 `effective_from` 之后创建、已结束且状态为 `fail` / `error` / `waiting_human` 的手动或调度 Run 及符合条件的 SiteJob，站点仍启用且在授权范围。取消请求、取消、中断、`unknown`、`deferred` 及未完成任务均排除；助手来源运行不再递归接管。`waiting_human` 不再一概排除，但也不等于已获准变更或重试，仍须通过当前来源及动态安全检查。**无历史任务回填**，每次保存策略更新生效时间。实际派发时捕获加密配置快照，不从后来配置猜测现场；缺失或过期快照不提供自动写入证据。

重启或重新部署不因新规则扩大准入而补扫旧终态任务。`AssistantTakeover.__init__` 在执行启动恢复之前固定 UTC `_scan_started_at`，周期 `reconcile()` 另要求 `Run.finished_at >= _scan_started_at`，不替换策略的创建时间条件；以 Run 结束时间而非创建时间或 SiteJob 结束时间为进程边界。因此启动前已开始、启动后才结束的运行仍可入队，启动前已结束且无 action 的旧任务不新建接管。边界在同一实例 start/stop 后不刷新，新进程重新构造实例才取新值。已有 queued action 仍按原授权及来源检查恢复处理；dispatched 若有精确已接受用户消息及有效同 owner 会话，则保留供持久证据完成恢复，否则启动回退仍按导入回执记 updated、无回执记 unknown，均不重放，详见[结论与通知](#结论与通知)。该边界只限制周期发现，不加入 `_eligible`，也不裁剪历史结论/去重查询；任务终态事务的显式通知规划入口不受此扫描边界限制，并非周期历史回填器。

**诊断准入与变更安全门禁分开。** 历史失败记录或与当前来源无关的 `unknown` 记录本身不会阻止符合上述条件的新故障入队、读取来源证据和分析；有效 `live_access` 下仍可浏览观察。它们本身也不是“已调查”的标记，只有已有有效的同版本同故障调查结论才抑制重复分析。当前来源自身的 `unknown`、中断、取消和 `deferred` 等状态仍不触发接管，不因此回填历史任务。

需要人工的挑战，可在有效 `live_access` 及宿主检查通过后尝试受限单步，不保证所有挑战或功能均可自动处理，也不保证没有网站副作用。历史 `unknown` 不一概阻止当前授权内、原始同源的受支持非 post 单步；auth 仍受每用户轮次共享额度限制。消费计划不自动重放，**配置保存/导入及完整运行的不确定性门禁继续有效**，不能用单步类别许可核销这些门禁。具体可用能力以当前宿主工具范围和检查为准。

以 Piggo 为通用示例：新的合格失败即使伴随无关历史 `unknown`，仍可进入调查；若已有有效同版本同故障结论，则直接复用，不新开浏览器或派发动作；若只有旧失败/未知记录，则不能据此跳过调查。此例只解释通用规则，不声明 Piggo 的生产配置、选择器或修复结果已获验证。

`analysis` 可读来源证据、查询 schema、校验/提交建议，但不能保存配置；`autofix` 仅可将成功保存且通过当前校验的提案**一次导入现有绑定来源站点的工作流**。导入要求失败的实际派发快照与当前历史身份、修订、attempt、车道、完整配置/依赖/策略指纹仍匹配，站点无活动或不确定任务；缺失/过期快照不能作为写入依据。自动接管不新建站点、不改车道、凭据、站点元数据、模板或全局设置，不取消任务，**绝不自动运行修复后的完整配置**。资料读取限来源 run/job，不能借普通会话的历史读取权限扩权；全局默认授权在接管中关闭。

**「仅分析」只表示不保存配置，不表示网站只读或没有真实副作用。** 两种模式都可由独立 `live_access=true` 委托取得浏览观察、支持视觉时的实时截图，以及当前冻结清单内最多 18 项孤立单步能力。用户不在线时也可能真实登录、提交表单、签到、点击或处理挑战；不是模拟运行，也不能保证识别所有网页消费。凭据由宿主按已绑定同源站点和可用内置来源私下解析，密码、Cookie、Token、OTP/TOTP、提供商密钥和浏览器能力令牌不交给模型或日志。输入值省略、截图输入遮罩、同源、功能策略、操作账本及未知结果门禁保持有效；插件功能、插件方法和插件凭据提供商仍拒绝。

实时浏览器按站点**已保存**车道策略派生代理：`proxy_general` / `proxy_interaction` 使用 `proxy_interaction`，其他策略使用 `interaction`，不自动 fallback 或切换代理。API 在首次 Worker `open` 请求中传入严格同源约束，Worker 在首次导航之前即应用，不是先打开再收窄；接管浏览器从**首次导航起**就严格绑定原始 origin，不自动批准其他 `trusted_origins`。打开、重定向、导航及单步均不能自行扩权，额外跨源挑战若需要另行信任，也不能靠接管授权自动打开。严格 origin 检查不等于完整网络沙箱，仍见 [浏览器边界](#浏览器边界)。

自动阶段不弹权限确认来扩权：`live_access=false` 时不浏览、不单步；true 时也不开放 `flow.jump` 或四项 `post.*` 孤立动作，不调用 `run_site`。当前自动接管门禁仍拒绝 `retry_step`，不能宣称该工具自动可用；新 `execute_step` 则按当前类别授权和 auth 额度检查，历史未知不构成一概拒绝理由，也不能借新调用冒充旧操作已核清。全局、站点、模板设置写入及取消任务仍须人工明确要求并逐次宿主确认；人工购买/补签完整运行每次新派发前须逐 post 步骤审核，全部批准后才启动。

每次自动工具派发及导入事务复查持久 action、授权 owner、策略修订/范围与当前来源；关闭或修改策略撤销旧修订的自动委托，不能靠会话文本/模型参数续权，但**不追溯撤销已明确授予该会话的人工后续权限**。撤销不能收回已发送的证据、已提交修改或网站副作用。确定的模型失败只在 1-3 次预算内重新分析，已有实时步骤派发后不自动再开分析尝试以重复动作；未知发送/执行结果不盲目重派。重启仅对精确已接受请求及有效同 owner 会话保留完成恢复机会，不能从聊天文字猜成功；其余已认领但未接受或缺有效会话绑定的 action 仍按导入回执记 updated、否则 unknown，不自动续跑。

对话框显示当前 owner 最近 20 条接管审计及「查看接管会话」。`GET /api/v1/assistant/takeover/actions?limit=100`（1-100）仅返回当前 owner 的 action，含来源 run/job/site、授权修订、模式、状态、原因、尝试次数、会话 ID 和时间；全局策略可读不等于能读取其他 owner 的聊天。状态 updated 只证明保存了工作流，completed_analysis 只证明有分析，不证明业务已修复或测试成功。

### 排队与所有权

自动接管浏览器排队由 API 和 Worker 协调，边界如下：

- 自动接管的 `browser_open` 使用 `wait_for_lane: true`；Worker 非阻塞返回状态，API 轮询 `queued` / `opening` / `ready`，仍在**同一个工具调用内 await 一次**直到就绪或终止，不向模型反复返回 busy 让其重试，等待期间不额外调用 LLM。
- 按 `interaction` / `proxy_interaction` **各车道 FIFO** 等待，最多 **1200 秒（20 分钟）**；实际排队等待不占本轮活动预算，不重置剩余预算，也不放宽模型请求或单步超时。排队截止不是浏览器准入后的 15 分钟 TTL。
- 不抢占人工助手浏览器、手动/调度活动任务、元素拾取器或 VNC viewer。来源活动任务与拾取器共享车道执行信号量；来源任务必须释放资源，人工租约须正常关闭/到期，viewer 须断开，自动接管才能获准使用车道。
- 超时、取消或策略撤销只移除本请求拥有的排队项、页面和租约，不关闭其他会话的浏览器、人工标签页或 viewer，不清空共享 profile。等待及准入后均须复查当前策略和来源，不能沿用排队前的授权判断。
- 服务端两条车道的队列相互独立，不代表接管可并行：当前主自动消费者仍逐个处理，一个自动轮次结束后才处理下一个，**不会同时运行两个自动浏览接管**，也不承诺跨车道并行接管。

自动接管无论成功、错误或取消，均在轮次 `finally` 中释放**本轮拥有的助手页面和租约，然后才将会话标为空闲 `idle`**；不等最后一条消息后的空闲计时，也不等 15 分钟到期。清理失败仍按 Worker 回收机制处理，不以误关其他资源换取释放。聊天历史和已授予的有效人工后续权限保留；会话空闲不等于整条车道进程已停止。

人工助手浏览器仍从 Worker 准入/创建起计**固定 15 分钟租约**，消息、观察及后续对话都不续租，不是「最后一条消息后闲置 15 分钟」。自动排队不提前消耗准入后 TTL。车道进程另由可配置 `idle_stop_seconds`（默认 **300 秒**，0 禁用）控制：仅在没有 lease 且没有 viewer 后开始空闲倒计时，有占用时不自动关闭。这不是助手租约 TTL，也不参与接管结果通知判断；配置入口见[空闲关闭](vnc.md#32-空闲自动关闭)。

### 相同失败去重

**去重可跨天，但仅在当前已保存的结论 TTL 内生效，不是无限期复用。** 没有每日清零或仅限当天的查询条件；同版本同故障且其他检查通过时，仍在有效期内的历史结论可直接复用，不新调模型、不打开浏览器、不创建新的每日接管会话。每日聊天路由不能覆盖结论年龄判断。

年龄只取**原始正式结论** `AssistantTakeoverConclusion.created_at`，以判断当下的 UTC 时间计算滚动天数：`now - timedelta(days=conclusion_ttl_days) < created_at <= now`。恰好到期即无效，未来时间也无效；不是按来源 Run/SiteJob 的 finished_at、action.updated_at、去重链接 created_at 或每日聊天本地日期计算。复用直接链接原始结论，不创建新正式结论，**不会续期或刷新原结论年龄**。

过期后，下一个符合当前准入的新来源按正常调查流程处理，即使配置和故障未变也不能用过期结论抑制调查；仍须通过授权、来源和安全检查，不保证模型或浏览器一定可用。到期及修改 TTL 均不自动回填、重排队已有 reused action 或删除记录。TTL 只约束**新的复用决定**，不按年龄隐藏历史：已有结论、reused 历史投影和冻结通知仍可读取；原有完整性、解密及绑定校验继续有效，不能把 TTL 到期当作证据损坏。

相同配置/相同故障去重仍适用于 `fail` / `error`。`waiting_human` 暂不复用旧挑战分析：同一配置下的新动态挑战也需要当前证据，不能因旧挑战已分析就抑制新分析。每日聊天路由可复用，不等于复用旧挑战结论或自动重放动作。

去重不是按站点永久静默，也不是按每日会话或相似文案猜测。`assistant_takeover_dedup.py` 在当前策略、来源资格、活动任务检查及 `_source_current` 复查通过后，匹配 **owner + 站点历史 UUID + 规范 origin + 实际派发配置完整指纹 + 配置修订 + v2 失败签名**。无关历史 `unknown` 不阻止已有有效结论的复用，因为复用不派发模型、浏览器或变更动作；这不解除变更单步或导入的安全门禁。来源快照必须能解密、完整性校验通过，且仍匹配当前站点、attempt 和实际车道；不能用后来重建的配置代替失败时的派发快照。

v2 签名以实际车道、任务状态和按 `step_key` 排序的全部失败步骤等事实取 SHA-256；步骤证据包含 key、功能类型、失败状态，以及可用的 `reason`、`code`、`errorcode`、`provider_error`、`cause`、`field` / `field_path`、`stage` 和空白规范化后的 message。失败身份的安全约束是：**即使已有失败步骤，也应同时区分完整 Run/Job 的终态原因和结果（包括明确 false 的结果）**，不能把相同失败步骤但最终原因不同的任务合并。时间戳、耗时、计数、URL、截图哈希等非白名单附加字段不参与；message 的其他差异仍会使签名不同，不做模糊归类。**去重元数据仅保存摘要和绑定，不保存原始 message、字段路径或页面证据**；这不改变原执行记录自身的保留规则，也不表示所有索引元数据加密。

缺少稳定失败事实、只有 stage/field、只有无 message 的通用 `execution_error` / `network_error` 等原因、失败数据无法解析或快照无效时，保守地不去重；宁可再次进入正常分析，也不把不同故障合并。存在签名仅表示已记录身份，不是“已成功处理”标记。候选来源必须是 `completed_analysis` 或 `updated`，并有可解密、绑定有效的正式结论及类型明确的成功轮次结果 `turn_outcome.ok === true`；updated 还须有效导入回执。排队、失败、unknown、缺失/损坏结论或仅有聊天文本均不能抑制新分析，确定失败后的仅保存事实也不等于可复用的成功分析。

复用的安全约束还包括**分析实际使用配置的来源一致性**：分析若在不同于失败派发版本的配置下运行，即使之后配置恢复成旧内容或旧指纹重新相同，该次过期分析也不得作为旧版本已处理的依据。不能仅凭 action 完成状态、清除了 stale 原因文字或当前配置碰巧匹配，就推断历史分析针对正确版本。明确未被接受的 busy/session-running/model-unavailable 发送应保留为可继续处理的排队工作，不得充当成功标记或抑制后续合格分析；是否收到请求与结果不明必须分开。这些是复用准入的安全要求，不声明新增公开字段或仅凭状态即可验证上述来源。

完整指纹覆盖本地及解析配置、祖先模板依赖、功能 schema/默认值/策略，不只哈希步骤或选择器。通过正常保存生成新站点修订，即使内容未变也不再匹配旧版本；实际修改快照内任意字段（包括名称、备注、调度等非步骤字段），或依赖/功能策略变化，同样失效。**此前 updated 的 action 属于修复前的失败配置，不能抑制修复后新版本的失败分析**。恢复旧内容但生成新修订也不等于原版本；仅重新保存接管策略或切换 analysis/autofix 不会把相同配置和故障自动变成新证据，且仍须满足当前授权。

匹配时仍为本次来源 job 保留新的审计 action，终态为 `reused`、reason 为 `same_config_same_failure`、`attempts=0`，不新派发模型、不打开浏览器、不生成新修复/导入回执或新的正式结论。去重链接直接指向原始有效 action，不串联复用链；原 owner 会话仍存在时关联旧 `session_id`，已删除则留空，不复活旧聊天。通常在解析模型运行时及创建会话前命中；派发认领前还有一次复查，以处理等待期间刚完成的分析。每日会话复用只决定聊天路由，与这里的跨日同版本故障去重不同。

UI 将 reused 标为「相同失败，复用已有分析」，结论区标为「历史结论（复用，非本次重新分析）」。公开结论及通知以「复用此前分析（任务 #来源 Run）：当前未重新分析/未修复。」说明出处；其中旧结论的保存或观察描述只属于历史，不代表本次重新检查、修复或执行成功。当前 Run/SiteJob 仍保留原失败状态、消息和统计。复用由任务结束、发送原任务通知前的本地规划/去重步骤完成；命中时历史结论直接进入该站点消息，不显示「助手复查中，结果稍后发出」，不启动新的复查，也不另发“开始复查”通知。规划时证据失效或缺失则不复用；已提交为 reused 后证据才失效，只隐藏历史结论，不自动重新排队调查。

### 性能与边界

当前静态实现通过 `assistant_takeover.py` 的 `_phase`（`asyncio.to_thread`）卸载协调器的启动恢复 `_recover`、周期完成恢复 `_recover_finalizations`、后台 `reconcile()`、`process_one()` 的 `_select`、模型运行时预检、会话创建 `create_takeover_session`、`_claim`、`_send_failed` 和 `_complete`。各数据库 helper 在工作线程内自行创建/关闭 session，阶段间只返回 ID、标量及已序列化证据，不跨线程传 ORM session/对象。模型发送、任务等待和唤醒仍由事件循环协调；取消会等待已启动的线程阶段退出，认领后未发送的清理由对应阶段处理，避免关闭时遗留数据库工作。

`executor.py` 的运行准备、终态落库及其中的通知注册，接管策略 PUT 保存，以及助手 SSE 认证复查、详情构造和 JSON 编码也移出事件循环；通知后台派发在线程中处理数据库和有界网络请求。这描述的是这些协调/数据库阶段的线程隔离，不将整套助手的所有工具或数据库操作概括为异步实现。

`assistant_takeover_performance.py` 提供 `TakeoverPhaseCache`，通知注册的 `plan_run_takeovers()`、协调器 `reconcile()`、选择 `_select` 及认领 `_claim` 各自创建新缓存，供 `_eligible` / `_site_uncertain` 在**同一同步事务阶段、同一 session 和策略视图**内复用按 run/site 读取的事实。缓存不持有 ORM 对象，不跨阶段、await、commit 或授权/配置变更保留，更不能代替实际执行、自动导入或权限复查；认领阶段重新读取策略和来源，不沿用选择阶段的授权判断。

SSE 仍约每 0.5 秒复查认证和归属、构造完整详情；只有编码快照变化才发 `event: update`，**running 未变化也只发 heartbeat**，不是持续重发全量聊天，也不是逐 Token 流。详情内消息解密结果仅在本次投影复用。前端工具 JSON 解析按消息内容缓存，完整格式化和 `<pre>` 等到展开才生成；缓存限当前选择、最多 200 条，内容变化失效，切换/卸载清理，不持久化工具或截图载荷。提案、工具原文、安全提示、审批/停止、图像遮罩及未知结果门禁未因此移除。

上述阶段隔离和缓存边界不保证任何负载下页面或事件循环绝不卡顿。

### 每日会话与知识

`DailyConversation` 对应实际表 `assistant_takeover_daily_conversations`，唯一键是 **owner + 站点历史 UUID `site_history_key` + `local_date`**。日期来自来源 **SiteJob.finished_at**，按站点 `timezone` 换算；时区无效时依次回退调度时区、UTC，不取后台处理/模型完成时间。同一 owner、同一站点历史身份、同一本地日复用一个聊天及其规范历史；跨午夜另建，不是每周同一星期几复用。路由还保存时区、来源结束时间及首个 action 锚点，不是委托或重放许可。

自动轮次结束清除本轮 action 委托及重试权限，但有效的 `live_access` 站点授权会保留在**同一个会话**，供 owner 后续人工聊天复用浏览、执行、可用凭据和截图权限；关闭接管策略也不撤销这些已授予的人工权限。**无论自动阶段是 analysis 还是 autofix，实时授权的人工后续目标均保留 `workflow_consent=true`**，可在用户明确要求后执行普通导入/完整运行，不受自动 analysis 模式永久限制。自动 analysis 的保存禁令仍由 action/工具门禁约束，不能据人工权限在无人值守阶段导入或完整运行。没有实时授权时，临时能力不保留，人工按正常交互取得所需权限；每日会话仍不借用全局自动授权默认值。仅询问能力不会新授权限或自动打开浏览器，身份、origin 或绑定变化须重确认。

自动接管结束即释放本轮浏览器，成功也不保留到 15 分钟到期；错误和取消同样在会话转为空闲前清理。owner 后续明确要求浏览时，可复用仍有效的已授予权限调用 `browser_open` **重新打开新页面**，无需重复授权，但不保证恢复原页面、DOM 或临时状态；历史截图不代表当前页面。重开后可按有效权限观察、截图或单步验证，**无需先手动跑完整工作流才能验证**。人工浏览器遵循准入/创建起固定 15 分钟租约，消息不续租；身份、origin 或绑定变化仍须重确认。人工明确要求导入/完整运行时走普通流程，消费动作仍需新的逐步骤精确审核，不明非 post 单步按当前类别策略重试，未知完整运行仍不能重跑。

跨日接管最多带入同 owner、同站点历史身份的 **3 条**以往正式结论，排除当前 action 和当前本地日；当天上下文由同一聊天历史提供。修复记录附宿主核对的导入回执、前后修订及有界字段级差异（步骤/分组/信号 key、增删改和变更字段名，不含字段秘密值）。这些是非可信历史证据，不是当前页面事实、可直接导入的提案或权限，也不证明修复后曾重跑成功。

### 结论与通知

注册原任务通知时，对已排队 action 重新核对当前策略修订、授权 owner、站点历史身份/origin、来源 job 绑定及准入；委托撤销或绑定变化则标为 revoked，不复用旧结论，也不添加复查中提示。历史复用还须通过活动任务、来源等待/不确定性及实际派发快照检查，签名相同不能代替当前授权。

自动接管在诊断及允许的保存后调用 `submit_takeover_conclusion({conclusion})`，另带公共 `title`；正文最多 **240 字符**、纯文本，不含 Markdown、图像、秘密或私有推理。它只提交本次 action/request 的加密候选，首个接受值不可改写；不改变任务结果，也不授予执行权。最终回复可更长，不能把整段长解释截断成结论。协调器按精确 action、request、owner、来源 run/job、站点历史身份及本轮确定结果核对后，才提升为正式结论；updated 还须有效导入回执。合规短最终答复可作后备，只有确证保存时也可保留「配置已更新，未重新运行验证」这一宿主事实；未知结果不提升。

**完成恢复只重试持久化收尾，不重新执行调查。** 启动 `_recover` 仅在 action 的精确 session/request 已有持久 `role=user` 消息、且会话仍属于该 owner 时保留 `dispatched`；其余已认领/未接受请求仍按导入回执记 updated、否则 unknown。周期 `_recover_finalizations` 在 `reconcile` 前通过 `_phase` 在线程执行，每批最多 100 条，只选择有效同 owner、idle 且无活动 task 的会话，并以 action 的 `updated_at` 做 **5 秒退避**。`_complete(..., recovery=True)` 再核对 action/session/request、owner 及空闲状态，要求该 request 的持久轮次结果中 `ok` 为真正布尔值；缺失或类型不符时保守记 unknown，除非导入回执证明已更新。恢复不重新排队，不重发用户消息、不调用模型或重放网站动作；明确失败也不借恢复启动新分析。完成状态、正式结论和通知登记同事务提交，提交/通知登记失败则回滚，action 保持 dispatched 供后续收尾重试；没有确定结果时不提升模型结论。这与下述通知已网络派发但结果不明的 unknown / 不重发规则不同。

原任务通知在任务结束后立即发送，不等待接管，也不额外调用模型。发送前，宿主仅本地规划来源 Run 中符合上述 `fail` / `error` / `waiting_human` 准入的 job 的接管 action 并做同故障去重，不调用模型或浏览器；`deferred` 不规划接管。需要新模型复查的 job 在该站点原始脱敏消息前添加「助手复查中，结果稍后发出。原任务结果：」；可复用的有效历史结论直接进入该站点消息并注明历史来源，不再发送第二条调查通知。事件、布局渲染正文和通道目标在注册时冻结加密保存为 `ready`，派发不重新读取之后的模型结论或设置。原任务自定义通知布局、数据库 Run/SiteJob 状态和原消息、统计及通道筛选不变：原失败仍是失败，原 `waiting_human` 仍是 `waiting_human`，不改写为 `success`。

实际接管结束后，只有状态为 `completed_analysis` 或 `updated` 且有有效简短结论时才发送**独立的助手调查通知**；它不是原任务通知的重发或改写。邮件/HTTP 各自的「接收助手调查通知」开关对应 `notify_assistant`，默认 true，只向已启用且该开关开启的通道发送，不依赖原任务通知的成功/手动筛选。读取或保存通知设置不调用模型，也不授予接管权限。`updated` 明确表示配置已保存、未重新运行验证，不把保存当签到成功；`completed_analysis` 只是分析结论。failed、unknown、revoked、queued、缺失或无效结论不发送。调查通知使用独立纯文本标题/简报，含站点、来源 run/job、原任务状态、调查状态及简短结论，不使用用户的任务通知布局；HTTP 事件为 `assistant.investigation`。

接管完成、正式结论及 `assistant_takeover_notices` 通知账本在同一事务提交；原任务通知先完成发送尝试，才派发对应调查通知，这不保证送达成功或收件顺序。调查通知以 action ID 唯一登记，独立于 `run_notification_intents`；网络前持久认领，最多一次尝试，重启遇已认领但结果不明的状态记 unknown、不重发，不保证恰好一次送达。每个通道独立投递，失败不阻塞另一通道，也不自动重试。升级时旧版已有等待意图保留冻结事件/消息并转为 ready 释放一次，不追补复查标记；载荷不可读则记 unknown，不为历史任务补建意图。详见[运行通知](run-notifications.md)。

### 记录存储

记录使用 `DATABASE_URL` 配置的数据库；Compose 默认 `sqlite:////app/data/siteflow.db`，位于 API 的 `siteflow_data` 持久卷，不是浏览器 profile 或模型服务端的知识库。

| 表 | 内容 |
| --- | --- |
| `assistant_sessions` / `assistant_messages` | 按 owner 归属的加密聊天、工具记录及上下文摘要 |
| `assistant_takeover_actions` | 来源 run/job/site、owner、授权修订、状态、request/session 关联及导入回执审计 |
| `assistant_job_config_snapshots` | 加密的实际派发配置/依赖快照及 attempt/车道绑定 |
| `assistant_takeover_daily_conversations` | 每日会话唯一路由、时区和来源结束时间锚点 |
| `assistant_takeover_conclusion_candidates` | 按 action + request 绑定的加密候选 |
| `assistant_takeover_conclusions` | 核对结果后提升的独立加密结论 |
| `assistant_takeover_failure_signatures` | owner/站点历史身份/origin、派发配置修订/完整指纹、签名版本及失败 SHA-256，不含原始失败 message |
| `assistant_takeover_dedup_links` | 本次 reused action 到原始有效 action 的直接链接及复用时间，不复制结论 |
| `assistant_takeover_analysis_provenance` | 原分析实际观察的来源配置一致性证据；缺失时不能作为有效历史分析复用 |
| `run_notification_intents` | 每 Run 一个即时任务结束通知意图、派发状态及加密发送快照 |
| `assistant_takeover_notices` | 每 action ID 唯一的独立调查通知、派发状态、加密事件/纯文本简报/通道目标及各通道布尔结果 |

`assistant_takeover_notices` 是独立持久化记录，不是原任务的已发送标志，也不依赖可删除的聊天；备份数据库时一并保留。

数据库备份还须包含 `AppSetting` 中的 `assistant.takeover.settings` 和 `assistant.takeover.site_grants`：前者保存规范的授权 owner、修订和授权/生效时间，后者保存同修订所选站点的历史身份与 origin 绑定。owner、每日规范会话路由及授权绑定属于持久元数据，不全是加密载荷；不能只备份聊天或在恢复时从当前数字 ID 重建委托。新增记录表由模型注册后的 `create_all()` 创建，`live_access` 和绑定使用现有 JSON/`AppSetting`，不新增旧表列；`create_all()` 不是已有列迁移机制，不提供历史开发版表结构迁移。

正式结论/接管审计独立于聊天保留，删除聊天不会删除这些总结，也不会重放旧 action；后续新接管可替换已删除聊天的每日路由。普通聊天内的上下文摘要随聊天保存，不应与独立接管结论混同。敏感载荷加密不代表 owner、日期、状态等索引元数据全是密文。恢复需备份数据库并单独保管 `SITEFLOW_MASTER_KEY`；只备份聊天或只保留密文而丢失密钥不足以恢复这些知识。

## 单步验证

目标确认只授予浏览观察。首次需要执行且尚无有效权限时，宿主暂停 `execute_step` 请求统一执行授权；明确批准或显式开启 `auto_authorize_execution` 后，API 派生 `execution_consent`、当前受审核的 `execution_features` 清单，以及签到、点击、公开填充和挑战所需的 `allow_sign`；凭据来源可用时才派生认证及 2FA 所需的 `credential_consent`。**执行能力是目标内统一授权，不是逐功能反复确认**；截图、工作流、可信来源、代理及购买/补签消费批准不包含在内。这些字段是后台校验元数据，不是用户要逐项填写的选项。即使验证选择器也可能触发真实业务操作；DOM、模型参数、工作流条件或聊天中的同意都不能扩大权限。

宿主在生成执行核对面板时冻结当前支持且凭据来源允许的 `execution_features`，并展示凭据使用及副作用权限；批准只授予这份冻结清单，不因等待期间代码或功能目录变化扩大范围。可选 `feature_type` 只说明本次请求的触发功能，不把授权缩成单功能。去重 subject 为整个 `authorization:execution`：同轮拒绝、超时、取消或失效后，换另一个功能也不能再次请求执行能力。

旧目标保留原先明确保存的权限，不因升级自动扩权；后续轮次可复用有效目标权限，或应用用户显式保存的全局默认值。没有相应权限时通过宿主交互明确批准。新执行授权只覆盖当时审核清单，不自动包含未来新增功能。

当前审核过的孤立单步清单有以下 **18 项**，即 23 项内置功能中除 `flow.jump` 和四项 `post.*` 之外的全部功能：

| 类别 | 支持功能 |
| --- | --- |
| 导航与等待 | `flow.open`、`action.navigate`、`action.wait` |
| 认证 | `auth.form_login`、`auth.password_verify` |
| 签到与点击 | `sign.button`、`sign.unit3d_claim`、`action.click` |
| 私有挑战与图像签到 | `challenge.2fa`、`challenge.turnstile`、`challenge.altcha`、`challenge.slider`、`challenge.image_captcha`、`challenge.grid_captcha`、`sign.iframe.image_captcha`、`sign.image_quiz` |
| 公开填充与结果 | `action.fill`、`flow.result` |

- `manual` 认证测试必须先在站点管理中创建站点并保存凭据，再绑定与目标 **完全同源**（scheme、hostname、有效端口一致）的持久化站点。API 冻结站点 ID、`history_key` 和 `config_revision`，执行前重新核对；站点删除、替换或修订变化需重新确认目标，不接受模型挑选站点或凭据。
- `manual` 未绑定已有站点不阻止确认目标、浏览观察或非认证测试，但不授予认证功能；遇到 `credentials_unavailable` 应绑定已保存凭据的同源站点或改选 Bitwarden，再确认目标，不向聊天提供账号密码。
- `bitwarden` 可用于尚未保存的新域名，统一授权会派生认证和凭据使用权限，实际执行仍要求集成及匹配凭据可用。API 私下按目标的完整域名匹配，不继承已有配置中的主域名/自定义匹配或插件提供商。已有站点绑定如存在，也必须通过同源和修订检查。
- 所有凭据模式均可在有效的显式已保存站点绑定下，于首次导航前私有注入已保存 Cookie，见[绑定站点 Cookie](#绑定站点-cookie)。这不是表单认证权限：`cookie` / `none` 仍不能授权两项认证及 `challenge.2fa`；无可用 Cookie 时可在同车道独立人工标签页登录后观察。没有聊天输入密码或临时手输凭据入口。
- `execute_step` 接收一个启用、无条件的完整步骤（`condition` 只能为空或 `always`）和稳定的 `operation_id` UUID，不运行分组、信号条件、跳转或完整工作流。API 根据当前功能策略补齐默认值、校验配置并固定导航重试为 0；Worker 在**当前助手页面**执行，不重新申请车道或新页面。
- 单步活动预算最多 90 秒，受较小的步骤超时和剩余浏览器 TTL 限制，不自动重派步骤。返回安全结果及可用的 `before` / `after` **结构化 DOM 状态快照**，不是 PNG、录像、完整 HTML 或原始运行日志；异常时快照可能为空。每份执行快照的完整 JSON 分页响应最多 **24 KiB**，两份共最多 48 KiB，为执行结果外层留出空间，不是两份各 32 KiB 挤满 API 的 **64 KiB Worker 响应读取上限**。挑战不再触发整会话证据锁；后续观察仍省略输入值，不开放原始私有运行数据。
- **执行签到会发生真实签到；登录会实际提交账户表单，点击可能消费或更改状态。** 必须先确认未签/待操作状态及权限，比较前后证据。`submitted: true`、工具成功或按钮消失不等于业务成功；孤立步骤测试也不证明最终工作流可用。
- 每个新操作使用独立 UUID，发起后保持稳定。API 在派发/释放凭据前把 UUID 记入会话加密账本；重复 ID 被拒绝。Worker 将同 ID 绑定完整请求指纹，只能返回缓存终态或在途状态，不能再次执行；不同内容同 ID 被拒绝。不要把更换 UUID 当作重试机制。
- 超时、取消、断线、响应丢失或 `unknown` 不代表网站未收到提交。先在当前权限内核验证据，再按下文类别策略决定新单步或精确重试，不以换 UUID 证明原操作失败。验证码本身不要求重开，重开也不能解除不确定性。每浏览器最多 20 个操作，每持久化聊天会话账本最多 256 个 ID；改目标、重开浏览器或 API 重启不清空该账本。

`action.fill` 只能向已确认用途的普通输入框填写显式公开、非秘密字面量，不能填写密码、账号凭据、Cookie、Token、OTP/TOTP 等认证动态码，也不能用占位符代替私有取密；具体字段和内容仍由宿主校验，图片验证码不等于 OTP。`flow.result` 孤立测试仅返回配置的布尔值，不调用模型判断；false 是该步骤的失败结果，不证明网站操作失败，更不能因此改成 true。完整工作流的结果判断仍按宿主既有策略执行；所需模型运行配置、提示词与提供商密钥由宿主私下传给 Worker，助手只接收安全布尔结果/状态，不接收原始模型答案、判断理由或密钥。

四项 `post.*` 的孤立测试**尚未实现**，原因是购买/补签依赖真实 SiteJob 的日期、库存、prepare/authorize/ACK 和消费检查点，不是用户拒绝了权限，也不能靠追加授权打开。应使用 [购买与补签审核](#购买与补签审核) 的完整运行。独立截图工具只提供图像证据，不是解题或动作工具；插件仍不开放。

### 私有验证边界

全部 `challenge.*` 以及 `sign.iframe.image_captcha`、`sign.image_quiz` 由宿主配置提供商并处理运行时数据，模型不能配置集成、选择插件提供商或索取秘密。**图片 CAPTCHA 的 OCR 文本和解题答案不因用于解题就被归类为秘密；2FA/OTP/TOTP 是真实认证动态码，仍须私有处理，绝不索取或回显。** 用户说“它不是秘密”可指图片验证码答案，不能据此解密或公开真实动态码、密码、Cookie、Token、提供商密钥或宿主私有提示词。TOTP 仅支持 `builtin.twofauth`，还需 `credential_consent`，并使用已绑定且凭据可用的完全同源 manual 站点或 Bitwarden 来源。配置的识别/视觉服务可能处理挑战图像；不声称任何模型都不处理图像，也不新增读取原始提供商回包的权限。

验证码执行不再设置阻止全部工具的会话锁。处理后可在同一页面继续 `browser_observe`、`browser_inspect`、`browser_check_selector`、独立授权的 `browser_screenshot`（及 UI 预览），以及导航、等待、登录、点击等已授权单步，**无需关闭/重开浏览器，也不因串接验证码而强制完整运行**。DOM/选择器证据仍省略所有表单输入值，不能通过子树、选择器或截图恢复输入值。未知结果、权限、原始同源和操作账本规则独立生效，不因验证码非秘密而放宽。

私有 Turnstile 单步要求用户明确批准 `https://challenges.cloudflare.com` 观察来源，并在当前助手页面找到唯一、可见的受支持 Cloudflare challenge iframe（HTTPS、`/cdn-cgi/challenge-platform/` 路径）。该信任只用于受限挑战目标，不授予向 Cloudflare 发送账户凭据的权限。Worker 固定 iframe、文档、来源及边界，行动前重新核对；CFbox 坐标必须落在该固定目标内部且命中该目标，否则不执行。非挑战坐标不触发动作，不开放任意全页坐标点击、桌面/X11 或其他标签页操作，也不以全页挑战识别结果代替唯一目标绑定。

私有提供商回包若回显已知提供商密钥会被拒绝，不能将其当作 OCR/答案填入网页或用于动作。私有输入在 focus 后重新核对原始节点、表单、同源及关联目标，再原子地校验并插入，防止焦点事件替换目标后接收秘密；这些约束不构成通用 DLP 或生产成功保证。

可以先处理图片验证码，再按页面证据和权限在同一助手页面继续登录/点击提交；仍须核实实际提交顺序，避免重复或未授权操作。完整工作流适合验证端到端编排，但不是连续验证码单步的强制前提。单步成功摘要或已填写/已提交标记都不等于网站验证通过。

### 表单登录就绪

`auth.form_login.success_wait_seconds` 默认 **10 秒**，只接受 **1-120 的严格整数**；布尔值、小数（包括 `10.0`）、字符串和 null 均不接受。它控制提交后的成功证据等待，不是步骤总超时；`timeout_seconds` 需要另行覆盖凭据/秘密查询、定位、填写、点击提交及成功等待，助手单步还受 90 秒活动上限、浏览器剩余 TTL 和本轮剩余预算约束。调整此字段不会自动延长外层超时，也不修改已保存的站点配置；不能仅靠延长等待宣称修复。

配置 `success_selector` 后，提交一次，再在同一等待期限内只读轮询主页面及**可见同源 iframe** 中各候选选择器的匹配元素，所有祖先 iframe 也须可见且同源，`about:blank` / `srcdoc` 沿父链继承来源；凭据 `trusted_urls` 不扩大成功证据范围。**任一匹配可见即可，不只检查第一个匹配**。实现有界：每轮最多检查 100 个 frame、每个选择器在各 frame 中最多 100 个匹配，随页面变化重新读取 frame 和匹配。隐藏节点仅存在不算登录成功；留空只报告已提交（`submitted: true`、`verified: false`），不证明已登录。等待期间不自动刷新、导航或重新提交；证据未出现也不证明网站拒绝了登录。

工作流信号的包含/排除选择器默认是**存在性**检查，隐藏节点也可命中，与登录成功元素的**可见性**要求不同；需要可见证据时，可在工作流的 Playwright 选择器中显式使用 `:visible`，系统不自动追加或改写已保存配置，不新增信号数据库列或改变默认语义。这不适用于文本规则：`include_texts` / `exclude_texts` 匹配页面标题和各 frame 的 body `innerText`，通常不包含 body 内隐藏后代的文本，不是读取全部隐藏节点的 `textContent`。助手 `browser_check_selector` 仅支持 CSS，不能直接传 Playwright `:visible`，应检查其返回的 `visible_count`。

稍后 `is_logged_in` 为 true 不能倒推提交步骤当时已满足可见成功条件。排查须区分首个匹配隐藏、后续匹配可见、延迟渲染及两种检查语义，不能只加长等待。超时后返回的原因及匹配/可见计数是**超时后的有界只读采样**，不是等待期间的历史证据或原子快照；页面可能在各项采样间变化。选择器索引对应原步骤 `config.success_selector` 的配置索引（从 0 开始），不是 DOM 匹配序号；按原配置核对，不回显选择器值、表单值或凭据。通用修复不是特定网站适配或实际生产认证验证。任务 329 的时间线、同 URL 导航跳过及截图证据限制见 [登录时序与误判](assistant-discovery.md#登录时序与误判)。

### 凭据与请求边界

已保存凭据仅由 API 私下解析并传给 Worker 的受限认证上下文，**不进入模型、聊天或提案**。Worker 验证当前源及原始元素：用户名/密码/提交按钮须唯一可见，属于同一个原始表单；密码必须为可编辑的 `input[type=password]`，用户名为可编辑的 text/email 输入。保留并重复核对原始节点及原始 form 身份，拒绝选择器重新绑定到替换节点、不同表单、跨源 action/formaction 或非当前窗口目标。**不要求 form 声明 `method=POST`，也不要求逐表单批准某个 POST action 端点。** 省略 method（隐式 GET）或声明 GET 的表单可由页面原有 JS 阻止默认提交，再用 fetch POST 到原始 origin 的其他路径；这不是开放模型编写或执行任意 JS，也不授权 `trusted_urls` 或 SSO。

助手页默认只允许 GET/HEAD。额外可信来源仅用于导航与观察，**单步执行及凭据使用仍限于原始目标 origin**，不能在额外可信来源页面测试登录、点击或其他步骤。只有已授权的非只读单步活动期间，Worker 的 `writes_authorized` 才临时允许 POST，可到原始 origin 的任意合规路径，而非仅 form action；此时受约束请求和重定向限于原始同源，跨源 POST 即使指向可信观察源也拒绝。`flow.open`、`action.navigate`、`action.wait` 是只读步骤，执行期间也不开放 POST；PUT/DELETE 等方法不因此开放。

普通查询参数保留原始编码，包括原生表单或 JS POST 的 `/api/auth/login?redirect=%2F`，不会删查询来“修复”登录。**已知账号/密码等秘密不得出现在任何请求 URL 中**，编码或嵌套编码也检查；原生 GET 表单若把凭据放入查询，会在网络边界被阻止，DOM 校验通过不代表允许此传输。步骤结束立即关闭 POST 窗口，并保留原始同源限制，防止延迟脚本或残留输入值向外源泄露；增加 `trusted_origins` 不绕过这个限制。静态日志和结果经安全投影、已知秘密过滤后返回；这仍不是完整浏览器沙箱。

运行时 `diagnostics.blocked_requests` 最多列 5 个被阻止请求的安全投影，含 `code`、HTTP `method`、投影后的 `url` 及脱敏标记；普通查询可保留，敏感参数值被擦除，含已知秘密的地址可整体显示为 `[redacted]`。它不含 POST body、请求头、凭据、浏览器能力令牌或重试授权密钥，不能据此还原请求或判断原操作成功与否。旧版 `browser_credential_endpoint_not_approved` 一类诊断针对请求端点，不等于缺少站点 ID 或 Bitwarden 未配置；当前通用实现没有逐表单 POST 端点审批要求，不应增加特定网站补丁来绕过边界。

## 绑定站点 Cookie

### 首次导航前私有注入

已确认目标并授予浏览观察后，`browser_open` 创建新助手浏览器时，若**显式绑定且校验有效的已保存站点**存有 Cookie，API 会私下解密并交给 Worker，在首次 `goto` 前注入。优先使用 `workflow_site_id` 的工作流目的绑定，仅在没有该绑定时使用凭据 `site_id`；两者不同也只用前者。校验包括当前站点历史身份、配置修订及与原始目标完全相同的 origin（scheme、hostname、有效端口）。**优先绑定过期或无效即失败，不回退到另一绑定；优先站点没有 Cookie 也不借用另一站点。** 不按 hostname 查找或选择其他站点，`check_site` 的同主机发现结果不构成绑定或 Cookie 使用授权。

- `manual`、`bitwarden`、`cookie`、`none` 均可使用这条私有注入路径，不要求先取得 auth 单步权限；但它不授予账号/密码登录、OTP、其他执行或完整运行权限。目标核对 UI 会提示此范围。复用已 READY 的浏览器不再次注入。
- 只接受原始目标精确主机的 `host` 或 `.host` domain Cookie；以 `url` 指定的 Cookie 必须与原始目标**完全同源**。更宽的父域及无关域 Cookie 跳过，额外 `trusted_origins` / `trusted_urls` 不扩大注入范围。API 和 Worker 分别校验，私有种子最多 **300 条、256 KiB 序列化 JSON**，这不是模型工具参数的额度。
- 原始 Cookie 仅走 **API 后端到 Worker** 的私有传输，不进入模型消息、工具参数/结果、聊天记录或持久化助手会话。没有读取、导出、任意写入或保存 Cookie 的模型工具；下节的破坏性清除是唯一 Cookie 变更工具。助手浏览器登录后不会自动导出 Cookie 或回写站点；正常保存任务成功后的 Cookie 保存机制是另一条路径。
- Cookie 属于**当前车道共享 profile/context**，不是助手标签页隔离的 Cookie jar；同车道相同主机的其他标签页可能受注入影响，不能把独立标签页误认为独立登录态。注入不改变固定 15 分钟助手浏览器 TTL、排队规则或车道空闲关闭计时。
- 为防止清除后旧种子再次导入，API 先取得 Worker 的当前车道/主机 **generation 握手**，再重新校验绑定并读取数据库 Cookie 明文快照；清除时 Worker 在同一车道/主机锁内先旋转 generation，失效排队中及在途打开的旧种子，导入前再核对。晚到的旧 HTTP open 也不能恢复旧 generation；不比较 API 与 Worker 的跨主机时钟。
- Worker 对私有导入的长、不透明高熵 Cookie token 保留指纹，并在**当前 Worker 生命周期内同一车道持久 profile**的助手证据/请求秘密检查中共享，不限于导入它的单个标签页；清除 Cookie、关闭会话或车道停止后重连均不抹掉这些已知秘密指纹。完整 Worker 重启不持久保存指纹，profile 中已有 Cookie 可能仍保留；短小偏好值刻意不做子串阻断，避免把普通文本误判为秘密。这不是通用 DLP，不保证识别 profile 中预先存在但未知的 Cookie，也不保证截图像素中的秘密被清除。

### 明确审核后清除

仅在用户明确要求清除时，调用 `clear_bound_site_cookies({operation_id})`，另需公共 `title`；`operation_id` 必须是新 **UUID4**。不接受任意站点 ID、domain、URL 或 Cookie 值。每次新操作都必须经当前 owner 的**全新内部 `cookie_clear` 宿主审核**；历史同意、执行/工作流权限和全局自动授权均不能跳过，也不能通过公共 `request_user_interaction` 伪造此 purpose。

- 前提是原始目标绑定有效，且已有属于本会话、正确车道、原始 origin 匹配、未过期的 **READY** 浏览器；不能为清除而自动打开、导航或重建浏览器。返回 `browser_reopen_required` 时先说明前提，由用户另行要求打开；重开本身可能按上节注入 Cookie。绑定站点有 queued/running 活动任务时拒绝，避免与任务 Cookie 导出并发；准备及批准应用时均复查。
- UI 展示已保存站点 ID、名称、完整公共地址、当前共享车道、已保存 Cookie 数量和清除风险。范围是**只删除该精确绑定站点的保存 Cookie 数据**，再清除**当前共享车道**中精确 `host` / `.host` 的所有路径 Cookie；不删除其他同主机站点的数据库 Cookie，不清父域、兄弟域、无关域或其他车道 Cookie。同主机、同车道的其他标签页可能退出登录，不能承诺只是助手页退出。
- 已保存账号、密码、凭据来源及 `localStorage` 保留，不刷新页面，也不关闭整个 profile。父域 Cookie 保留意味着不保证彻底退出登录；旧 DOM 也不因清除立即变为未登录。清除不是永久禁止保存 Cookie，后续新的成功任务仍可能重新保存 Cookie。
- 审核冻结目标/浏览器范围、站点身份修订及 Cookie 快照。批准事务重新校验并用 CAS **先清除数据库 Cookie**，与加密 `cookie_clear` action 回执一起提交；不是先调用 Worker 再删库。随后持久化认领一次私有 Worker 清除尝试，**认领提交在 I/O 之前**；Worker 也在实际清除前登记操作并旋转 generation。快照或范围变化不改清另一份 Cookie。
- 分别报告 `saved_cookies_cleared` 与 `browser_cookies_cleared` / `browser_outcome`。数据库已清但浏览器失败、超时、断线或取消时可能是部分完成/`unknown`，不能笼统宣称全部成功，也不回滚成“未清除”。**不自动重试，不换 UUID 绕过未知结果；同 ID 重放仅返回已存决定/结果，不再弹审批或调用 Worker**，拒绝/取消的 ID 也不能下一轮重新取得批准。
- 无人值守接管不暴露或调用此工具，`live_access` 也不授权清除。自动阶段结束后，用户可在同一个每日接管会话明确要求，按普通人工流程先满足浏览器前提并进行本次独立审核；保留的接管权限不替代清除批准。

此功能要求 **API、Worker、Web 配套升级**，尤其是私有种子/generation 接口和 `cookie_clear` 范围核对 UI；不能仅升级某一组件或把内部 Worker 接口暴露给模型/公网。

## 人工登录

人工登录不是 Cookie 模式的唯一入口：有有效显式绑定和已保存 Cookie 时可先按[绑定站点 Cookie](#绑定站点-cookie)私有注入。缺少或失效的登录态仍可按下述方式人工建立，助手不会自动将其导出或保存回站点。

自动登录采用[凭据与请求边界](#凭据与请求边界)的通用原始节点/同表单检查与运行时请求边界，不把 POST 绑定到某个冻结 action 端点。普通同源查询参数允许保留；需要跨源认证或不能满足这些检查时，使用独立人工标签页，不要求放宽规则。

单步结果为 `outcome_uncertain` 时，页面仍保留，禁止自动重复有副作用的步骤；可在当前权限内继续 `browser_observe`、子树查看、选择器检查及独立授权截图，输入值仍省略。结果中的 `diagnostics.reason` 是执行或策略原因，`diagnostics.evidence_errorcode` 说明 after 快照为何未能取得。读取当前安全页面时，历史被阻止的请求以 `warnings` 返回，不再仅因旧拒绝记录关闭页面；跨源候选仍展示完整非敏感目标信息以供确认。真正不安全的当前地址、失效授权或响应身份错误仍会终止会话。

`proxy=false` 固定使用 `interaction`，`proxy=true` 固定使用 `proxy_interaction`，不使用 `general` 或 `proxy_general`，也不自动换车道。`browser_open` 会通过车道租约按需自动启动所选交互车道，无需先手动启动；`get_system_status` 中通用车道停止与助手能否打开浏览器无关。需要人工登录时，打开「车道状态 / VNC」并进入助手返回的同一车道，不能在另一条车道登录后期待共享状态。

目标中的 `proxy` 字段只控制浏览观察及当前页面的单步验证，新目标默认 false；保存后的完整工作流另用 `run_lane_policy`，默认 `general`，旧/API 的 `auto` 同样解析为 `general`。用户明确要求后，通过 `update_site_config` 分别审核 `observation.proxy` 和已保存目的站点的 `patch.lane_policy`；失败不构成自动切换的理由。完整五种车道均可明确审核，但观察浏览器始终使用交互基础设施。

旧版 `purpose: "proxy"` 交互仅为持久化兼容保留，以下描述其既有行为，不是新调用推荐入口。该交互为 **`kind: "choice"` 单选**，宿主提供 `general`（直连）和 `proxy_general`（代理）两个选项，批准响应还须带 `selections: ["general"]` 或 `["proxy_general"]`。`scope` 为 `browser`、`workflow` 或 `both`，默认 **`both`**。模型传入的 `enabled` 只是建议，不授予权限，也不能覆盖用户选择。

| `scope` | 用户选择的作用 |
| --- | --- |
| `browser` | `general` 将目标 `proxy` 设为 false，`proxy_general` 设为 true；只改发现浏览器及当前页单步，不改保存运行车道 |
| `workflow` | 将目标 `run_lane_policy` 设为所选 `general` / `proxy_general`；只改后续导入/完整运行的车道策略，不改发现浏览器代理 |
| `both`（默认） | 按同一用户选择同时更新上述两个独立字段 |

选择名称不等于浏览器实际基础设施车道：发现浏览器仍必须使用 `interaction` / `proxy_interaction`，不能改用 `general` / `proxy_general` 打开助手页。改变浏览器模式后需安全重开，不自动重试旧操作；改变工作流策略也不等于已经导入、修改站点或触发运行，仍须按当前目标修订校验提案并走独立工作流权限。旧宿主接口仍可明确选择四种保存车道，但模型、页面或聊天偏好不能自行代选。无消费计划的完整运行正常 `general -> interaction` 或 `proxy_general -> proxy_interaction` 同代理模式回退不算配置漂移，不允许借此切换直连/代理模式；有消费计划的助手运行不自动回退/重试。

**人工登录时，在该车道中新建一个独立、由你控制的浏览器标签页，不要在助手观察标签页提交登录表单。** 助手页在单步活动窗口之外只允许 GET/HEAD，连人工提交的 POST 登录也会被阻止。独立人工标签页不受这套助手页限制，你应自行核对地址及登录行为；不要为方便人工操作而扩大单步授权。

同车道使用共享 profile/context，人工标签页登录后的 Cookie 可供助手标签页使用。完成后返回聊天，明确要求模型先调用 `browser_navigate`，例如 `path: "/"`、已知的同源账户页路径，或 `url` 指定的原始源/已确认可信源完整 URL，再调用 `browser_observe`。`path` 与 `url` 必须且只能提供一个，可保留非敏感查询与片段。即使地址与当前页相同，导航也会重新加载，使共享 Cookie 生效；仅观察旧 DOM 不保证页面已刷新。

认证页需要跨源 SSO 提交、敏感令牌或未获授权的 POST 时，应在独立人工标签页完成，不要要求模型绕过限制。普通非敏感查询与片段不需要因此改用人工标签页；跨源导航与观察仍须先由用户确认精确 origin。人工登录不扩大助手的目标授权。授权观察可能把已登录页面的个人资料发送给配置的模型；不愿披露时不要授权或继续观察。

## 完整 URL 与可信来源

`browser_open` 使用宿主确认的完整 `base_url`，模型不另传打开地址；显式 `browser_navigate` 也支持完整 URL。观察结果的 `url` 和元素 `href` 保留非敏感的查询与片段，包括参数顺序、重复参数、空值、`+`、百分号编码大小写及片段路由，不因展示而拆掉或重新编码这些部分。源的 scheme、hostname 和默认端口可规范化，但不会因此改写公开路径、查询或片段的原始编码。

- 识别到 `token`、`access_token`、`password`、`session`、`code`、`state`、`sig`、`signature` 等敏感参数键时，仅把值替换为 `[REDACTED]`；也处理片段参数、编码后的键及受支持的敏感键变体。页面 URL 标记 `url_redacted` 和 `redacted_parameters`，链接分别标记 `href_redacted` 和 `href_redacted_parameters`。
- 普通 `return_to` / `redirect` 不因名称或包含 URL 就被整体视为秘密。无秘密的嵌套 URL 保留原始编码；有敏感参数时只擦除嵌套敏感值，保留其余公开内容。嵌套 URL 含用户名/密码或超过脱敏深度边界时会更保守地隐藏对应值。
- **脱敏 URL 只能作证据，不能作工作配置、导航地址或可执行提案。** 不得把 `[REDACTED]`（包括编码形式）保存或执行，也不能猜测、补写秘密。确需敏感参数时在聊天之外处理；已知凭据匹配还可能使整个 URL 隐藏。按参数键脱敏不是通用 DLP，公开键的值、路径和文本仍须人工检查。

例如 `https://example.com/login?tab=foo&next=%2fhome#/login?tab=foo` 完整保留；`https://example.com/login?tab=foo&token=SECRET#details` 展示为 `https://example.com/login?tab=foo&token=[REDACTED]#details`，并标记已脱敏。嵌套的 `?return_to=https%3a%2f%2fother.example%2flogin%3ftab%3dfoo%26token%3dSECRET` 仅将 `SECRET` 换成 `%5BREDACTED%5D`，不是删掉整个 `return_to`。这里的 `SECRET` 仅为说明占位，不应实际发送秘密。

未批准的公共跨源导航或重定向被阻止时，工具返回 `code: "browser_trust_required"`，不是已成功访问。结果包含完整但按上述规则脱敏的 `source_url`、`target_url`，各自的 `source_url_redacted`、`target_url_redacted`，以及 `redacted_parameters`、`source_origin`、`target_origin`、`user_action: "confirm_trusted_origin"` 和 `trusted_url_pattern`。例如目标源为 `https://auth.example.com` 时，建议模式为 `^https://auth\.example\.com(?:[/?#].*)?$`；该模式由精确 origin 转义生成，不接受模型自行提供的宽泛正则。

前端工具卡片展示当前与目标完整 URL、待核对 origin 及脱敏警告，不再提供打开目标设置的添加按钮。用户明确要求变更观察来源后，助手通过 `update_site_config(observation={trusted_origins: [...]}, operation_id=UUID)` 单独请求核对完整来源列表；不自动信任，不因全局默认值而跳过。批准后原调用恢复、替换观察来源，改变目标修订并释放旧浏览器；这本身不导航、执行或重试，模型可在同一轮安全重开/导航，无需再发消息。旧 `purpose: "trusted_origins"` 仍保留原来的合并行为供持久化兼容，不再推荐新调用。脱敏地址仍不能因为来源已获批准就变成可运行地址。

`trusted_origins` 默认空，最多 20 个公共 HTTP(S) 精确 origin（scheme、hostname、可选非默认端口），不含路径、查询、片段、用户信息或正则。交互/API 接收规范 origin，例如 `https://auth.example.com` 或 `https://auth.example.com:8443`，不是完整路径 URL；旧目标编辑器曾按行输入、接受并移除末尾 `/`，不是当前聊天页的预填步骤。原始目标源始终保留，额外来源仅由用户在宿主 UI 确认，模型参数、链接和聊天不能扩权。Worker 对原始源和额外源检查公共 DNS，并在导航、重定向和观察时继续校验目的地。**这只是观察/导航授权，不是额外来源的执行或凭据授权，也不会修改已保存站点的 `trusted_urls`。**

## 浏览器边界

公共非敏感查询参数与片段可用于打开、显式导航和重定向，例如首页跳转到 `/login?return_to=...`。观察不会统一去除这些内容，而是按上一节擦除敏感值。未批准跨源先返回可信来源确认要求；非公共地址、URL 用户名/密码及携带已知凭据的 URL 继续拒绝。`general` 停止不会阻止助手使用 `interaction`。

- 目标仅接受公共 HTTP(S) URL，可包含非敏感查询与片段，不允许 URL 用户名/密码、本地/私网地址、受限主机名、控制字符、反斜线及其编码逃逸；Worker 还检查 DNS 是否解析到公共地址。
- `browser_navigate` 在公共 `title` 字段之外，必须且只能提供 `path`（最多 2048 字符）或 `url`（最多 4096 字符）一个地址字段。`path` 是相对于目标 `base_url` 解析的引用，可含查询与片段，不得携带 scheme、authority 或 `//` 等源逃逸；`url` 是完整 HTTP(S) URL，只能导航到原始目标源或用户明确确认的 `trusted_origins`。scheme、hostname 或有效端口变化就是新源，不能由模型自动信任。
- 助手页默认对受路由约束的请求只允许 GET/HEAD，授权非只读单步活动期间才临时允许原始同源 POST；打开、导航和等待步骤从不开放 POST。观察阶段主框架文档导航及重定向限于原始源和用户确认的额外源，单步期间及结束后则限于原始源。阻止 WebSocket，并尝试关闭弹窗。单步之前公共子资源可能来自其他源，因此这不是“所有流量始终只到目标域名”的保证；单步后保留同源子资源限制。
- 观察和选择器检查使用固定的隔离世界只读脚本，模型只能传入受限参数，不能提供 JavaScript、执行任意代码、发起网络请求或按 ARIA role 操作。`browser_check_selector` 只查询匹配，不点击、填写、提交或派发事件；经授权的内置点击/认证仅能走上述单步工具。
- DOM 快照采集通用 HTML、自定义元素及可读的 open shadow DOM，不按登录/挑战元素白名单筛选，也不为特定站点或挑战提供专用规则。**隐藏节点保留并标记 `visible: false`，隐藏不等于不存在；表单值被省略/脱敏，不是删除隐藏节点。** DOM 工具不提供完整 HTML、Cookie、存储、网络响应或图像；独立截图工具见下文。
- 人工助手浏览器租约从 Worker 准入/创建起固定 **15 分钟**，不因消息或观察续期，不按最后一条消息计时；Worker 每约 5 秒回收过期资源。过期后需重新 `browser_open` 打开新页面，已保存的目标和有效权限不会因此删除，不保证原 DOM 恢复。自动接管则在本轮结束、会话转为空闲前释放自己的页面和租约，不保留到 TTL 到期；车道空闲关闭是无 lease/viewer 后另计的默认 300 秒，见[排队与所有权](#排队与所有权)。
- 修改目标会释放旧浏览器；显式取消、删除会话和服务关闭也会尝试清理。网络或关闭失败由 Worker 回收器继续处理；清理未确认时保留车道占用，不冒险复用。清理助手页不代表清除同车道 profile、Cookie 或人工标签页。

以上额外来源规则描述普通人工发现；`live_access` 接管浏览器更严格，从首次导航起即限制原始 origin，不沿用保存站点的额外信任自动扩权，见 [失败接管](#失败接管)。

**这不是完整浏览器网络沙箱。** Chromium 独立解析 DNS，检查结果未固定到实际连接，存在 DNS rebinding 残余风险；既有共享 profile 的 service worker 不能靠 page routing 完全禁用；弹窗关闭前可能已经发出首个请求。代理车道仍需要 **Worker 本地 DNS** 能解析目标，解析失败会拒绝，并非完全由代理端解析。建议在浏览器及代理的网络层设置出站策略，阻断内网、环回、链路本地和云元数据等目标；不要把应用层检查当作完整 SSRF/出站隔离。即使 GET 也可能触发站点副作用，只访问你有权检查且确认可安全读取的路径。

## DOM 证据

`browser_observe` 返回扁平的 `elements` 数组，用 `parent_id` 重建层级，不是嵌套 HTML。每个节点含 `node_id`、`parent_id`、`frame_id`、`tag`、布尔 `visible` 和经过过滤的 `attributes`；可能另含 `text`、`has_shadow_root`，以及经采集时验证的 `selector`、`selector_source`（`id` / `name` / `dom_path`）、`selector_matches: 1`。节点 ID 只在对应 `snapshot_id` / `frame_id` 内有意义，父节点可能在前一页或所检查子树之外，不能因本页没看到父节点就认定其不存在。

`text` 仅是元素的直接子文本，规范空白后最多 300 字符，不聚合后代文本；按钮文案可能在其子 `span` 中。保留隐藏元素的普通文本，但不返回 script/style 等可执行或样式正文、template/noscript 正文、input/textarea/select/option 的文本和值，或可编辑区域正文。属性不是固定 id/name/type/role 白名单：在数量和长度限制内保留通用属性，过滤事件处理器、含 value 的属性名、敏感键及 style/srcdoc 等内容，URL 属性另行净化。每节点最多 24 个属性，普通属性值最多 512 字符，URL 属性最多 4096 字符，节点最多 8 KiB；已知凭据过滤还可能擦除文本/属性并移除受影响的选择器证明。这不是通用 DLP，隐藏普通文本、可见个人资料、属性及路径仍可能敏感。

| 工具 | 读取语义 |
| --- | --- |
| `browser_observe` | 可传 `frame_id`、`offset`、`limit`；默认主 frame、`offset: 0`、`limit: 100`。0 创建新快照，非零 offset 翻阅该 frame 最新的已捕获快照，不重新扫描 |
| `browser_inspect` | 必传 `snapshot_id`、`node_id`，可传 `offset` / `limit`；包含指定根节点，只分页读取该快照的不可变 **`captured_subtree`**，不是实时子树，也不接受选择器重新定位 |
| `browser_check_selector` | 必传 `selector`，可传 `frame_id`；读取该 frame 的实时 DOM，返回 `match_count`、`visible_count`、净化后的 `matches` 及 `truncated`。匹配包含隐藏节点；最多计数 10000，最多 10 个样本，样本还受响应字节限制 |

每次快照有界扫描最多 **5000 节点、深度 64、2 MiB 快照字节预算**，每浏览器会话最多缓存 **4 份**快照（各 frame 共用此数量）。普通 observe/inspect 每页最多 **100 节点且完整 JSON 最多 32 KiB**，所以第一页可能不足 100 个；`limit` 为 1-100，`offset` 为 0-5000。响应带 `snapshot_id`、`frame_id`、`offset`、`next_offset`、`total`、`truncated` 和 `limits`。`total` 是捕获集合的节点数，inspect 时是捕获子树的节点数，不是网站完整 DOM 总数；`next_offset` 非 null 表示还有已捕获节点可翻页，必须使用返回值而不是固定加 100。`truncated` 表示采集或 frame 元数据达到边界，不等于“还有下一页”；即使 `next_offset: null`，也可能仍有未捕获节点。

**inspect 无法恢复原始有界扫描之外的节点**，不能绕过节点数、深度或字节上限。新的 observe 可以刷新某 frame，但不是针对遗漏子树的深挖或无限扫描。observe 的非零 offset 跟随该 frame 的最新快照；若中间另有采集，先核对 `snapshot_id`。需要固定版本分页时，用原快照的文档根节点调用 inspect。缓存淘汰、导航或同 URL 重载均可能使引用失效；`browser_snapshot_stale` 时重新 observe，不能猜节点 ID。动态 DOM 更新不使缓存内容自动变成实时证据。

响应的 `frames` 列出有界的 frame 元数据（最多 64 个、12 KiB），含 `frame_id`、可选 `parent_frame_id`、净化 URL、`readable` 及不可读时的明确 `reason`，另有 `frames_truncated`。只允许读取原始同源或用户已批准观察来源且通过公共 URL/DNS 检查的 frame；不可读、未批准或不可用 frame 只提供元数据，**不能解释为其 DOM 或登录/挑战元素不存在**，元数据截断也不能证明未列出的 frame 不存在。读取 iframe 须使用实际返回的 `frame_id`，不会自动穿透，也不因此开放 iframe 单步执行或凭据使用；执行开始后的原始同源限制仍适用。

选择器检查仅支持 CSS 和显式 ` >>> ` 分段穿过 **open** shadow root，不支持闭合 shadow root、任意 Playwright 选择器引擎、JS 或自动穿透 iframe。`selector_matches: 1` 只证明采集时准确匹配该节点，不能从 id/name 重新拼接或猜测。写配置或做单步前，用 `browser_check_selector` 在正确 frame 复核数量、可见性及样本身份；隐藏匹配计入 `match_count`，`visible_count: 0` 不是零匹配。实时检查之后 DOM 仍可能变化，执行端仍会独立验证。`browser_selector_invalid` 应修正 CSS，`browser_frame_unavailable` 应刷新 frame 元数据；这两类错误和快照过期错误保留页面。

这里的 DOM 快照不是图像；不能仅凭 DOM 工具结果声称已看到截图。独立 JPEG 截图也不能因为密码被遮罩就视为完全安全，具体见下节。分页和无 ID 登录按钮的证据用法见 [发现指南](assistant-discovery.md#dom-分页与选择器核验)。

## 截图与恢复

### 截图证据

- 空闲时可点「截图预览」，需要当前目标的独立 `screenshot_consent: true` 及可用的助手浏览器；权限不足时应通过聊天让助手请求截图能力，不去预填目标设置。它不调用模型，只在当前 UI 内存显示；关闭预览即清除，不作为聊天图像持久化。统一执行授权、聊天中的“同意”或模型参数不能代替截图授权。
- 模型调用 `browser_screenshot` 时，宿主在缺少目标截图权限且未显式开启全局截图默认值时自动发起独立交互；用户批准后恢复同一调用，不需另发消息。还要求本轮配置 `supports_vision=true`。普通对话仍可使用文本模型；没有视觉能力返回 `model_vision_required`，不得假装已经看过像素。
- 两个入口均只截当前 viewport 的有界 **JPEG**，不是全页、PNG 或录像；最多 **1600 × 1200** 像素、**384 KiB（384 × 1024 bytes）**。主页面及可读同源 frame 内遮罩表单输入控件（非按钮/复选框/单选框 input、textarea、select、可编辑区域），其余 frame 保守地整体遮罩；已批准观察的跨源 frame 不因此免除整体遮罩。这不是遮住整个 form 的所有文本，也不保证所有 frame 内容可见。API 独立校验图像并重新编码像素，移除 EXIF、注释、ICC 等嵌入元数据。尺寸、MIME、`masked`、图像 ID 和来源 URL 等证据元数据仍可返回。
- 遮罩不是通用图像 DLP，不能保证所有秘密像素均已清除；输入控件之外仍可能有个人资料（PII）、账户文本或其他秘密。页面将图片验证码答案反映为可见文本时可以保留，不因此封锁截图或浏览器；真实凭据或 OTP 仍不得索取或回显。截图不能证明操作已失败、尚未提交或没有副作用；转圈也不是失败证明。可据此**询问用户是否确认刷新或重试**，不能据图自动刷新、重复提交或宣布成功。
- 模型截图的工具结果和 SSE 只携带文本/图像元数据与 owner 图片地址，不携带 base64 像素。完整一批工具结果之后，宿主才追加独立的 user 多模态证据消息，使用 `data:image/jpeg;base64,...` 给模型看图；图像及规范消息加密保存。图片不放进工具文本、摘要或历史摘录，不把 data URL 截断成不完整图像；大小预算仍有效。
- 撤销实时截图同意或目标修订变化后，历史**实时浏览器截图**像素在后续模型输入中被省略，即使关闭 `auto_compact` 也如此；重新同意不恢复旧修订像素。独立授权读取的历史 artifact 图像不受实时截图撤销影响。原始加密审计不删除，已发送的图像也无法撤回。owner 仍可通过受登录/归属保护的图片 GET 读取历史 JPEG；撤销控制的是后续实时截图重放，不是删除历史或撤销 owner 的读取权。UI 工具卡片只展示元数据，不自动加载历史图片地址。

### 刷新与重试

本节类别策略针对 `execute_step` 的单步，不解除配置保存/导入或完整 `run_site` 的不确定性门禁；完整运行未知状态没有对应批准/核销 UI，见 [导入与完整测试](#导入与完整测试)。

「刷新会话」只读聊天状态；「刷新网页」需确认后对当前归属的助手页发起**新的 GET**，模型对应工具为 `browser_refresh`。实现不是 `reload()`，不会重放 POST；为确保发出 GET，使用当前 URL 去掉片段后的地址，保留查询，并清除旧 DOM 缓存。它仍检查 URL、公共 DNS、origin 及已知秘密，不能刷新任意模型指定地址。GET 本身也可能有业务副作用，不能仅因截图有 spinner 就自动刷新。刷新保留结果不明状态、账本及原页面归属，不证明旧操作失败，也不解除重试门禁。

结果不明时保留页面并核验证据；验证码不要求重开，重开也不清除账本与未知状态。**唯一可信类别来自代码内置 `Feature.category`**，值为 `flow`、`auth`、`challenge`、`sign`、`action`、`post`，不能按功能键前缀、描述、模型参数或插件元数据推导权限。

| 类别 | 当前单步与重试策略 |
| --- | --- |
| `auth` | 单步及助手完整保存运行的登录与密码验证共用发起真实用户轮次的 `max_auth_uses_per_turn`，默认 3、严格整数 1-20；每次尝试及重试在解析凭据前预留，失败也计次。内部模型轮次、换目标/浏览器不重置；耗尽返回 `auth_budget_exhausted` |
| `flow` / `challenge` / `sign` / `action` | 原始同源、当前授权和受支持清单内可继续单步，历史未知不一概阻止；`flow.jump` 仍不支持孤立测试。`challenge.2fa` 属于 challenge，不占 auth 额度，但 OTP 始终私有且仍需凭据同意 |
| `post` | 四项购买/补签仅完整保存工作流执行，每次新派发前逐 post 步骤全新审核，所有面板批准后才开始；不按每个日期或内部点击再弹窗 |

助手完整运行在运行时签发每次 auth 凭据租约时计一次，兑换同一租约不重复计次，条件跳过不计；循环重入及执行器重启/回退尝试申请新租约仍占共享额度。后台任务绑定发起轮次及当时上限，即使聊天结束或用户发送新消息也不取得新额度。含 auth 的新 `run_site` 派发前检查剩余额度，但不预扣所有配置步骤；运行中耗尽则拒绝后续 auth 租约，不允许无限循环认证。结果查询及同一运行重放不计次，普通手动/调度任务不受此助手额度限制。

普通会话的 `retry_step` 除公共 `title` 外只传原 `operation_id`，宿主自动签发单次精确步骤能力，以新 UUID 执行**服务端存储的原步骤**，不弹人工重试审批；auth 重试另计一次共享额度。不允许修改步骤或从聊天/摘要提供授权。原 origin、目标、浏览器、凭据绑定、当前权限和幂等校验仍有效。自动接管目前仍拒绝 `retry_step`；允许的新类别单步不等于开放该工具，应如实报告当前门禁。

旧空闲「允许重试一次」及 retry-approval API 仍保留兼容，人工可按既有流程使用；旧授权为 5 分钟、浏览器绑定、单次使用，入口本身不执行。保留旧接口不代表当前非 post 重试始终需要人工审批。旧等待路径最多 180 秒，拒绝/超时/取消不执行，重启不自动续跑。

原 `unknown`、账本和受保护事实作为来源证据始终保留；重试成功不证明原操作失败，无关成功也不核销旧结果。当前宿主关联 resolution 与类别策略优先于历史 `no_retry` / `requires_host_approval` 文字；后者不再是非 post 单步的一概拒绝依据。类别许可是用户授权策略，**不是物理点击、导航或脚本不会改变网站的保证**；仍应提示真实提交、消费及其他副作用风险，不能宣称只有 post 能改变网站。

只读观察/截图遇到 DNS 解析或读取策略失败时，可能返回 `page_retained: true`，**没有返回证据**但保留页面；不代表已读到 DOM/像素或操作失败。历史阻止记录可作为 warnings，不能把旧警告当作当前页面必然不安全。含已知秘密的当前 URL 拒绝仍属隐私致命错误，会关闭会话，不因“保留页面”策略放行。

## 历史与状态

- 聊天按登录用户名归属，不绑定某次登录会话。退出、登录过期或关闭页面不会删除聊天；同用户名重新登录后可继续。更换用户名不会自动转移记录，重新使用旧用户名也应考虑其历史访问权。
- 标题、标题控制字段、目标、执行 UUID 账本、上下文摘要及其边界/修订信息、结果不明操作的安全记录、模型用量和消息载荷（含工具标题、参数、结果与提案，以及供模型重建历史的规范消息）加密保存；owner、ID、角色、状态、时间和请求 UUID 等索引元数据不全是密文。站点修订绑定和完整操作账本不进入公开目标/模型上下文；结果不明操作的必要安全事实会单独提供给模型，以保留禁止重试提示。浏览器能力令牌仅在 API 内存中，不返回 UI 或模型，不持久化。
- 会话列表按 `updated_at`、`id` 降序分页，每页默认/最多 **100** 条；左侧「加载更多会话」可继续读取旧会话，不再只限前 100 个。`GET /api/v1/assistant/sessions` 接受 `offset >= 0`（默认 0）、`limit` 1-100（默认 100），返回 `items`、`offset`、`limit`、`next_offset`（末尾 null）及 `truncated`，不承诺 total。它同样是实时 offset 而非历史快照，并发更新可能重叠/遗漏；UI 按会话 ID 去重合并，客户端仍应刷新核对。
- 详情/SSE 仍只返回最新 **200** 条消息；会话列表分页不等于旧消息分页。这是读取窗口，不是保留数量上限；当前无旧消息分页 UI、自动归档或聊天 TTL，删除会话才会删除其数据库消息，备份另行管理。
- 每轮按原始消息顺序重建模型历史，不再固定只取最近 100 条。`auto_compact=true` 时可使用「有效摘要 + 边界后历史」，达到整理条件时才压缩规范历史；关闭时忽略已有摘要及边界，从原始记录重建，不做有损工具投影。具体整理与读取边界见下文。
- 消息提交返回 `202` 后由 API 后台任务执行。切换会话、关闭标签页、SSE 断线乃至登录过期都不会自动取消；要停止助手轮次请在运行中的会话点「停止」。停止不能撤回已发送给模型或网站的请求，也不等于取消已经提交共享 executor 的完整任务；后者需通过独立确认的 `cancel_run` 或运行 UI 检查/取消，仍不能撤回已生效操作。
- 页面通过 SSE 接收整份会话快照，不是逐 token 输出；约每 0.5 秒检查一次，仅快照变化时发送更新，运行中或空闲未变化都发 heartbeat。模型请求明确使用 `stream: false`，所以要等每次完整响应，工具开始/完成仍可分别显示。线程隔离、阶段缓存及工具 JSON 惰性展示的范围见[性能与边界](#性能与边界)。
- SSE 会重新检查登录失效/撤销及归属，但不延长登录活跃期。原生 EventSource 可重连，页面不会自动重发消息或失败的修改请求。结果不明时先刷新核对，避免手动重复发送。
- 每条发送携带 `request_id` UUID；同一会话重复该 UUID 只返回现有状态，不追加消息、不重新运行，即使之前已取消或重启中断。UI 每次主动发送生成新 UUID，不能把新的手动发送当作旧请求重放。
- API 重启会把遗留助手轮次与工具日志标为中断/失败并恢复空闲，不自动续跑或重发；这不证明网站操作失败。已派发的单步保留 unknown 安全事实，未完成的工作流 action 保守记为 unknown，完整任务中断仍需人工核验。浏览器引用不跨 API 重启恢复，需重新打开；Worker 的 TTL 是残留资源清理后备。

工具卡片显示模型提供的短操作标题、工具名、状态和结果；它们是供用户阅读的操作/原因摘要，不是私有思维链。上游独立 reasoning 字段不会作为答案、历史或工具指令保存；普通答案和标题仍是模型生成的非可信内容，不能因此假定绝无敏感信息。

### 稳定请求历史

主对话的每次请求都是无状态的完整请求：代码维护的助手系统提示和当前宿主目标系统消息各出现一次，工具定义仍随请求发送。它们不会作为聊天消息反复追加或保存到历史中；不能因为前一次已发送就从下一次请求省略。用量账本也不会发送给模型。

新记录保存经过校验的规范模型消息，仅含允许的 `role`、`content`、`tool_calls` / `tool_call_id` 等对话字段；工具调用 ID、规范化参数字符串及序列化结果用于后续重建，而不是把 UI 工具卡片或整个加密载荷当成模型历史。不会保存或重发提供商原始响应、独立 `reasoning` / `reasoning_content` 等私有推理字段；下文的 `reasoning_tokens` 仅为数字计数。

设置、宿主目标/系统提示和工具定义保持不变、没有实际摘要或压缩且没有中断修复时，新规范记录的后续 `messages` 保持前次请求的精确前缀，只追加已完成的答案、用户消息和整批工具调用/结果。`auto_compact=true` 且低于整理阈值时同样保留这一前缀；实际摘要/压缩必须改变前缀，不能同时承诺压缩和逐字不变。

中断批次仅在模型输入投影中为缺失结果补静态失败记录，维持调用/结果配对，不重放已执行或尚未派发的旧调用，也不为修复改写审计记录。已持久化的旧版记录仍按安全的历史文本包装读取，不暴露私有参数或加密信封；旧记录若未保存原始调用 ID/规范消息，无法精确恢复当时的请求，也不会伪造迁移出原始 ID。已有摘要及边界可继续按整理规则读取，但迁移不能让旧历史获得新记录的精确前缀保证。

稳定前缀只是缓存的必要输入条件之一，不保证提供商缓存命中。实际结果还取决于模型/路由、缓存有效期、请求头，以及提供商对工具定义和提示的规范化等规则；以后台实际返回的缓存计数为准，不把本地 schema 缓存当作上游缓存或费用节省证明。

## 模型用量

详情/SSE 可选返回 `usage`，尚无已记录调用的旧会话可不含此字段；会话列表不携带逐调用账本。标题旁的上下文百分比及「上下文与累计用量」中的当前读数是**最近一次有效 `conversation` 报告的 `prompt_tokens + completion_tokens`**，不使用累计值或上游 `total_tokens` 作为分子。输入包含该次历史、系统提示及工具定义，输出是该次实际生成量；缓存命中另列为 `last_context_cached_tokens`。分母是该请求的 `context_max_tokens` 预算快照，不是后来修改的预算。`summary` / `title` 不覆盖当前读数，但仍进入累计消耗。

这不是实时测量：该次 completion 已包含在读数中，随后工具结果和未来输入仍需下一次真实对话报告。缺失/无效的 prompt、completion 或预算时跳过本次占用更新，不用本地估算或 0 补齐；保留整份最后有效读数及其原预算/修订，设置 `last_context_usage_missing: true`，前端明确标为最后已知、最近请求未上报，不能冒充最新值。从未有有效报告则显示 `--`；下一次有效对话报告更新读数并清除此标记。缺失报告仍进入调用明细和累计已知值，不从账本中丢弃。

整理或目标/上下文修订变化会使当前读数失效，显示 `--` 等待新报告，而不是保留旧百分比或宣称刚整理就测得占用下降；直到下一次匹配当前修订的真实对话报告才恢复读数。这与单纯缺失 usage 时保留最后有效值不同。旧版只有 prompt、没有分母的账本不得解释成新分子或当前百分比。`max_tokens` 仅限制输出，不代表实际输出、剩余上下文或模型容量。

展开「用量明细」可看会话累计已知值和最近 **100 次**调用，类型为 `conversation`（包括工具往返的每次模型请求）、`summary`、`title`。后端仅读取 Chat Completions 响应顶层 `usage`，不从工具结果中采集，也不估算：

| 公开计数 | 上游来源与含义 |
| --- | --- |
| `prompt_tokens` | 输入 Token，包含该请求发送的系统消息、历史、工具结果和工具定义 |
| `completion_tokens` | 输出 Token，包括提供商计入其中的推理 Token |
| `total_tokens` | 上游报告的总数，缺失时不以输入加输出推算 |
| `cached_tokens` | 优先取 `prompt_tokens_details.cached_tokens`；缺失/无效时回退 DeepSeek 的 `prompt_cache_hit_tokens`，两者不相加；0 是有效值 |
| `reasoning_tokens` | `completion_tokens_details.reasoning_tokens`，仅计数，不保存推理正文 |

缓存命中是输入的子集，推理是输出的子集，**不能再加到输入、输出或总计上重复计数**。`prompt_cache_miss_tokens` 不用于拼出缺失的输入计数；`input_tokens` / `output_tokens` 等其他协议别名不自动换算。计数须为有效非负整数；缺失或无效字段保留 null，明细 UI 显示 `--`（未返回），不是 0，不按文本长度或字节估算。当前占用只要求有效 prompt、completion 和预算；缺少 total 不妨碍两项相加的占用读数，但累计 total 仍不补算。

每次实际尝试发送模型 HTTP 请求只记一次；HTTP 错误、网络失败、超时、取消或无法安全解析响应仍计请求数，无法取得的计数为 null。安全解析出的用量可在后续答案/工具协议校验失败时仍被记录；非成功 HTTP 响应或秘密检查失败不保留其正文中的用量。请求序列化、请求头或本地构建失败，以及本地上下文/请求大小拦截，均未尝试发送，不计请求数。创建会话、固定欢迎语、刷新、SSE 重连和同 `request_id` 的幂等读取不会新增模型调用。

用量账本随会话加密持久化，逐次记录只保留 ID、类型、时间及上述白名单数字，不保存提供商原始元数据或推理。`calls` 最多保留最近 100 次；`totals` 和 `unreported_usage_count` 跨重启保留整个会话已记录生命周期的累计，不因逐次记录淘汰归零，也不回填升级前未记录的调用。累计只累加各字段的已知值，未知字段不算 0 用量；某字段从未有已知值时累计可显示 0，但不证明实际消耗为零。输入/输出/总计任一缺失时计入「部分调用未返回用量」提示，因此累计可能不完整。数字累计最多到安全整数 9007199254740991。**累计消耗不是上下文窗口占用**；这里只展示后端原始计数语义，不提供金额/成本换算。

## 上下文整理

**数据库保留原始记录，不等于模型每轮看到全部历史。** 摘要和工具投影都有损，可能抽样、省略或误述细节，不是完整事实依据、当前 DOM、宿主指令或授权。摘要不能授予凭据权限、扩大目标或允许重试；重要结论应核对原始工具结果，当前页面状态还需重新观察。

- **开启自动整理时，轮次开始先整理旧历史**：有可整理旧记录且记录超过 **40 条**，或待整理历史本地估算超过 `context_max_tokens × 0.6` 时尝试摘要；默认估算阈值为 **38400 Token**。摘要输入分块最多 `min(20000, context_max_tokens × 0.6)` 个本地估算 Token。最近 **2 条真实用户消息**及从较早一条起的近期记录不进入这次旧历史摘要；工具/系统记录即使在模型输入中包装为 user，也不计为真实用户消息。结果不明操作的 `operation_id`、`no_retry` 等安全事实另行保护，不依赖模型是否在摘要中写对。
- 每轮最多 **2 次**独立、无工具的摘要模型调用，每次最多 **12 秒**，均计入本轮配置的总预算（默认 **180 秒**），不追加时间。摘要复用已配置的连接、模型、秘密检查及本轮助手 `max_tokens` 策略（null 继承全局、0 省略、正整数原样发送），不另设隐藏输出 Token 上限。摘要文本最多 6000 字符，并受序列化大小限制，输入也可能抽样，不能据此保证保留所有细节。
- 摘要与 `boundary_id`、目标修订绑定和上下文修订号保存在会话加密载荷中，后续轮次/重启可复用；边界只标记已覆盖到哪条原始消息，不删除那之前的记录。保存目标会使旧摘要失效，但**不清空原始历史、执行 UUID 账本或结果不明操作的安全记录**；新目标确认也不代表旧操作已经核验或可重试。
- **开启自动整理时，工具轮次中再做投影**：每次主模型请求前以 `context_max_tokens × 0.6` 为本地估算软水位（默认 **38400 Token**），进一步缩减以完整预算为界。估算包含系统提示、工具定义和图像标记。已完成的 assistant 工具调用及该批全部结果作为整体处理，不拆出孤立的 tool 消息；保留最近两条真实用户消息、安全记录和最后一批调用/结果。最后一批尽量原样保留，即使超过软水位；仍过大时可确定性缩减结果正文、再缩减调用参数正文，但保留调用 ID、工具名及调用/结果配对，不重置去重集合或本轮工具计数，也不重新执行。原始记录仍保留。
- 摘要超时、格式不合规、不可用或未通过秘密检查时，通常回退到明确标注缺失的确定性摘录，继续主对话，不仅因摘要失败就阻塞；取消、总预算耗尽、无法容纳受保护内容或其他安全/请求边界仍会终止轮次。这不是“任何上下文都一定能继续”的保证。

`auto_compact=false` 跳过新的模型摘要、轮次开始和轮中的自动适配/缩减，**忽略已有摘要及其边界，从保留的原始历史重建输入**；也关闭旧版工具结果的有损正文投影。已有摘要、边界、上下文修订和原始记录仍保存在数据库中，不因关闭而删除或改写；重新开启后可按有效性规则复用。安全包装、禁止重试事实及中断调用的静态配对修复仍保留，不发送私有信封或提供商推理。旧记录无法找回从未保存的原始调用 ID，因此这不是恢复旧版精确线协议的保证。完整重建输入超过本地估算 Token 预算时以 `[context_limit]` 终止，超出线协议字节上限则受请求大小检查阻止，不暗中摘要、裁剪、改写历史或重放工具。

`get_tool_result` 可按当前用户、当前会话中的原始工具 `message_id` 读取已保存的结果正文，不要求该消息仍在最新 200 条详情窗口内。除公共 `title` 外，参数为 `message_id`、`offset`（默认 0）和 `limit`（默认/最多 **10000 字符**，最少 1）；offset/limit 计 Unicode 字符，不是节点数、字节或 Token。返回 `content`、`total`、`next_offset` 及工具名/标题/状态，按返回的下一偏移继续，单页可能只是 JSON 片段，拼接后才是完整 JSON。它不返回原始调用参数、私有绑定或加密信封，不访问浏览器、不调用网站、不重放执行，也不会另启一次专用模型调用；结果进入正常工具对话流程，仍消耗本轮工具/后续主模型请求预算。历史 DOM 结果只是旧快照，读取不能恢复浏览器缓存或使旧元素引用变成实时证据。

会话列表和详情在有已保存摘要时显示「较早上下文已整理，完整记录仍保留」，提示中包含上下文修订号。公开 `context` 含 `revision`、`summary_through_message_id`、`compressed`，不包含摘要正文；它不是 Token 使用率或费用仪表。标题修订和上下文修订相互独立；目标变更可清除摘要但不增加上下文修订号，不能只凭修订号相等就认定旧摘要仍有效。详情/SSE 仍只展示最新 200 条，数据库保留其余记录，当前没有通用旧聊天分页 UI。

`[context_limit]` 表示本地估算 Token/受保护内容预算仍无法满足，**不是提供商精确分词计数，也不是上游上下文窗口探测**。`context_max_tokens` 默认 **64000**、范围 **16000-1000000**；预检包含消息框架、系统文本、工具定义及图像标记。本地估算对 ASCII 按约 `ceil(chars / 3)`、非 ASCII 按 UTF-8 字节保守计数，图像使用低细节估算而非 base64 长度；它不写入用量账本，也不替代真实 usage。旧设置的 `ceil(bytes / 4)` 仅是迁移换算，不是当前估算算法。

线协议字节限制独立有效：含工具定义的整个主请求固定最多 **1536 KiB**，主响应 **256 KiB**；工具参数 **64 KiB**、结果 **128 KiB**，DOM、执行和截图另有各自边界。图像 data URL 不可截断，必要时以省略标记替代完整图像。JSON 转义、语言、工具 schema、图像和输出预算都会影响实际提供商 Token。低于本地估算预算不保证上游接受，也不保证历史完整保留。遇到提示先缩小本轮问题、聚焦选择器或局部子树、降低浏览分页 `limit`，必要时新建会话；不要通过重复登录/签到来恢复被压缩的细节。

用户可明确要求只读某个 frame、已捕获子树或选择器，并按需分页读取指定旧工具结果；系统不会为每次提问自动增加一次「全量重读历史」的模型调用。应在本轮复用已查询的功能 schema。缓存 schema 只能减少本地重复构造的 CPU 开销，不能据此免除仍随请求发送的工具定义/结果的输入 Token；实际用量及缺失值见 [模型用量](#模型用量)，不能把整理标记或缓存命中解释为已测得的成本节省。

### 导入与完整测试

`workflow_consent` 默认 false；用户要求导入/测试时，若没有已保存的目标权限或显式启用的全局 `auto_authorize_workflow`，宿主自动请求独立工作流授权，批准后恢复原调用。无需预填目标设置或批准后另发消息。旧会话、目标观察确认、执行授权或升级本身均不授予此权限；它覆盖导入和绑定站点完整测试，不只是保存草稿。确认目标/授予权限本身不导入、不创建任务。目标中的 `site_id` 只绑定凭据来源，`workflow_site_id` 才是配置导入/完整运行的目的站点，不能混用；目的站点必须与原始目标完全同源，空值表示导入时新建。

独立保存的接管 `live_access` 委托及其人工后续权限另见 [每日会话与知识](#每日会话与知识)，不来自全局默认值；自动阶段仍禁止完整运行，不能用保留的人工工作流权限绕过模式门禁。

manual 模式导入也要求有效的同源凭据站点绑定，不能仅靠聊天声明或空 `site_id` 创建自动登录配置；绑定不意味着复制其凭据到新站点，完整运行仍按目的站点实际存储检查。

- `import_workflow_draft` 除公共 `title` 外只接受 `{proposal_message_id}`，不接受 `draft`、站点 ID 或配置覆盖。ID 必须来自当前 owner、当前会话、当前目标修订下成功保存的 `submit_workflow_draft` 工具消息，且 `unresolved_questions` 为空。导入精确读取该加密原提案，并按当前 schema、功能策略、继承配置和 URL 边界重新校验，不导入模型另传的 JSON。
- 更新已有目的站点时，用冻结的 `history_key` / `config_revision` 做 CAS 防覆盖，只替换本地 `steps`、`groups`、`signals` 和宿主确认的运行车道；保留名称、基础地址、模板、启用状态、调度、可信网址、凭据及其他站点元数据。真实配置变更会通过共享保存服务生成递增版本和不可变历史，不改写旧版本。已有本地步骤含模型不能还原的隐藏/受保护配置时返回 `protected_config_changed`，必须用人工编辑器处理，不能以脱敏占位值覆盖或静默丢弃。
- 新建站点默认 **`enabled: false`**，不启用调度、不复制凭据或助手浏览器 Cookie。用户可在正常编辑器自行启用，或在当前配置完整成功测试后明确要求 `update_site_config` 单独审核启用，后者不受全局工作流默认授权绕过。明确授权的助手完整测试可通过私有 `_allow_disabled` 入口测试该禁用站点，测试不会把它改为启用；这不是公开运行 API 的 force/绕过禁用参数。**导入已有启用站点会保留 enabled 与调度，后续调度可能执行导入后的购买/补签配置。** 导入前应核对自动运行影响；新的逐次消费审核只约束助手调用，不是手动/调度运行的新门禁，这些入口仍按既有策略执行。调度/今日未成功筛选仍跳过存在未核清助手运行结果的站点，不能自动重放来补结果。
- `run_site` 的业务参数只能是 `{}`，没有任意 `site_id`、批量/全部站点或 `force`。它只运行当前宿主绑定且修订仍匹配的单个已保存目的站点，创建持久运行记录后提交给共享 executor，不把发现页单步拼成完整运行。运行使用目的站点实际保存的凭据来源与 Cookie，并核对目标认证策略；manual 必须绑定该目的站点且确有已存密码，Cookie 模式须目的站点确有已存 Cookie，不能拿发现页人工登录的 Cookie 代替。Cookie / none 不允许认证步骤，Bitwarden 使用已保存站点的提供商策略，不把任何凭据交给模型。
- 完整运行支持全部 **23 项**内置功能，包括受限公开 `action.fill` 和四项 `post.*`，消费步骤另须下节的逐次审核；插件功能/验证码方法/提供商仍拒绝，包括继承项。工作流 URL（含继承步骤）必须为原始目标同源的公共、无敏感值地址，保留公开的完整路径、查询及片段；不同 origin 即使已列入 `trusted_origins` 也不开放完整运行 URL。此检查是静态配置边界，不是完整运行的重定向/网络沙箱保证。
- 提交时创建 `assistant_run_guards` 守卫，使用新解析的本地配置、解析后配置、祖先模板依赖及功能设置/策略快照计算哈希；executor 执行前再次检查当前值。身份、修订或这些配置漂移会以静态 `assistant_configuration_changed` 拒绝执行，而不是运行已变化配置。无消费计划的普通完整运行仍允许正常同代理模式通用到交互回退；有消费计划的助手运行不允许自动 fallback/restart 或重试 attempt。
- 导入和运行都有持久 action 幂等记录。同一提案重复导入只重放原结果；同一绑定身份、修订及提案重复 `run_site` 返回原 `run_id`，不重新 submit。提交 executor 的确认丢失时返回 `ok: false`、`code: "run_submission_uncertain"`，保留 run ID 和 unknown action 状态；`submitted: false` 不是证明任务未到达 executor，后续调用只重放该结果，不自动补投或创建新任务。
- 新的助手导入通过共享保存服务新建或更新工作流时，保存 actor 的精确值为 `assistant`，所生成配置历史的 `created_by` 也为 `assistant`；新的助手完整运行保存 `Run.created_by: "assistant"` 和 `trigger: "assistant"`。真实人类身份仍由助手会话的 owner 及关联 `assistant_workflow_actions.owner` 保留并校验，不再存放在新运行的 `created_by` 中；会话/消息及 action 载荷加密保存，但 owner 等索引元数据本身并非全是密文。
- 运行列表创建人显示英文 `assistant`，tooltip 为「来源：智能助手」，不是显示实际人类发起人；通知的 `trigger_label` 同样是英文 `assistant`。助手工具卡仍提供站点/运行入口。这些规则仅用于新的助手操作，不迁移旧运行或配置历史。已有运行 329 保持 `trigger: "manual"`、`created_by: "admin"`，不能称为助手来源运行，也不能仅凭助手曾参与配置就改写来源。

**结果不明不是已知失败。** Worker 收到私有 `assistant_run` 标记后，可能已产生副作用的步骤发生异常/超时时记为 `unknown` / `outcome_uncertain`，不能降为普通 fail 再重复。传输失败也可能返回 `assistant_outcome_uncertain`。此时禁止新完整运行或用单步替代重放整次运行；当前授权内的非 post 单步仍按类别策略检查，不因历史未知一概拒绝，也不核销配置写入/完整运行门禁。当前没有完整运行的宿主审批/核销 UI，单步 `retry_step` 能力不能解除完整运行门禁；不能承诺点“批准”即可恢复。需人工在运行 UI、网站或 VNC 核清实际业务状态，持续未决时由管理员排查；普通手动运行不会自动核销旧未知状态，任何人工再运行也应先防止重复副作用，不能作为助手绕过门禁的建议。

已完成且证据明确的失败，可依据下节安全诊断修正草稿，重新 validate、submit、import，保存新修订后再测试；同一修订重复调用不会得到“再跑一次”。未知结果不能通过改提案、改修订、换会话或换工具恢复缺失证据。

### 购买与补签审核

插件功能可声明同样六个 category 值，但插件元数据未验证，不是助手授权来源；危险实际实现仍需独立审核，不因声明非 post 类别就开放助手访问。

`post.buy_card`、`post.resign`、`post.resign_click`、`post.resign_dialog` 均可用于助手完整运行，旧接口型 `post.resign` 也在支持范围内。每次**真正新派发**前，宿主都要展示并由 owner 审核本次精确消费计划；`auto_authorize_execution`、`auto_authorize_workflow`、工作流权限、导入批准或聊天同意均不能跳过，也没有全局自动消费授权。条件步骤中的启用 `post.*` 同样纳入审核，不能假定条件不会命中而省略。

审核单位是**每个 post 步骤**：同一完整工作流内依次展示各步骤的全新面板，全部批准后才启动一次完整运行；任何拒绝或超时都不启动。一个步骤的批准覆盖所列全部日期、数量和内部点击上限，不为每个日期或内部点击再次弹窗，也不授权其他步骤。

- 计划绑定当前站点历史身份/修订、有效工作流及功能策略指纹、本次调用、时区/当天和宿主计算的全部待补签过去日期。日期列表完整展示，窗口最多 **365 天**；不是只显示前几项，也不由模型传入 pending 日期或授权 token。
- 购卡数量必须有界，`purchase_quantity` 为 **0-365** 的整数；0 表示按待补签天数减库存自动补齐，审核仍给出最大数量。`max_price` 必须为**正整数**单价上限，展示最大数量及最大总花费；这不是网站实时报价。补签只消费已批准过去日期对应的卡，不自动加购。
- 批准仅供本次冻结计划单次使用。拒绝、超时、取消、计划/日期/配置变化均不能派发旧计划；新派发需新的审核。消费计划由 API 私下传给 Worker 的真实 SiteJob 检查点，不通过模型参数提供。
- 带消费计划的助手运行仅允许原始 attempt，不自动 fallback、restart、重试或重新提交。相同配置/提案运行的幂等重放只返回原 `run_id`，**不再弹审核，也不再次提交**；未知结果按完整运行门禁处理，不能换 UUID、工具或提案绕过。

这不是“所有网页消费都能识别并拦截”的保证。`action.click`、导航和站点脚本可能有无法从选择器确定的业务效果；提示明确禁止用点击、填充、导航或循环绕过消费审核，不能把通用动作当作购买/补签替代入口。新的消费计划检查只适用于助手发起的完整运行，不改变正常手动和调度运行的既有策略；特别注意导入到已经启用的站点。

### 完整运行反馈

普通会话的两个反馈工具只允许读取**当前 owner、当前会话关联创建的完整运行**，知道 `run_id` 或 `snapshot_id` 不能取得其他运行权限。接管会话另有宿主绑定的失败来源 run/job 特例；它不扩大到其他任务。普通历史查询及 artifact 专用工具的范围见[历史版本与 Artifact](#历史版本与-artifact)，不能把这两个反馈工具的范围套用于全部历史读取。

| 工具 | 参数与安全投影 |
| --- | --- |
| `get_run_results` | `{run_id, cursor: 0, limit: 50, wait_seconds: 0, snapshot_id?}`；cursor 为非负索引，limit 1-50，wait_seconds 为整数 0-20。返回运行/任务/步骤状态，以及代码维护白名单内的 `code`、`reason`、`errorcode`、`field`、`stage`、`cause`、布尔结果和有界计数，不返回任意结果正文 |
| `get_run_log` | `{run_id, offset: 0, limit: 16000, snapshot_id?}`；offset 为非负字节偏移，limit 1-16000。`content` 是安全结构化诊断事件的分页序列，不是原始 artifact 日志；按 `next_offset` 继续，整体最多 65536 字节，可能截断 |

步骤行运行中可能原地更新，不是只追加的事件流。`snapshot_id` 是当前安全投影的 SHA-256 哈希（64 位小写十六进制），cursor/offset 只相对于该投影有效，不是永久事件 ID，也不是保留不可变运行快照的句柄。首页从 0 读取并取得 ID；非零 cursor/offset 必须携带该 ID。投影变化或 ID 不匹配时返回 `ok: false`、`run_snapshot_changed`、新 ID 和从 0 重启提示，不能把不同快照的页拼接成完整结果。结果最多投影 1000 步，注意 `truncated`；状态尚未结束不等于失败。

建议用 `wait_seconds: 10` 或 20 有界等待，避免密集零等待轮询；等待仍占本轮预算。工具在本轮内可继续读取，但**普通聊天轮次结束后不会自动监看该任务、再次调用模型或主动回来汇报**。任务可能继续执行，用户可在运行 UI 查看，或下一条消息请助手读取结果；用 run ID 和当前状态说明未完成，不承诺任务结束后自动回答。独立持久授权的失败接管只处理其准入范围内的新手动/调度失败，不是聊天轮次自动续跑。

这两个安全反馈工具只取应用自身产生的诊断枚举与类型受控计数，不把页面文本、运行时标签、完整站点 URL、原始错误/异常 dump、任意 data 或日志 artifact 当成可信指令。`get_run_log` 是 **curated structured diagnostic**，不是“脱敏后直接返回全部日志”；`raw_log_available_in_ui` 仅描述私有运行 UI 的原始日志入口。需要模型分析实际历史文件时，用户可另行要求 `list_run_artifacts` / `read_artifact_log`，通过全文脱敏与有界分页读取；它与 `get_run_log` 的权限/投影不同。不要把密码、Cookie、未经处理的完整日志或原始异常粘贴到聊天。可信观察来源也不授予额外凭据权限。

### 草稿修复诊断

`validate_workflow_draft` 失败返回顶层 `ok: false` 和最多 **10 项** `diagnostics`；`submit_workflow_draft` 重新校验时使用同一安全诊断投影。每项有代码维护的 `code`、`message` 和 `path` 数组；能安全定位本地步骤时另有 `step_key`、受审核的 `feature_type`，配置字段另有 `field`，边界错误可带 `hint`，例如 `ge=0`、`min_length=1`。`hint` 只说明允许的数值/长度约束，不给出管理员默认值或实际输入。路径可含从 0 开始的数组下标，但不回显未知属性名；无法安全定位时路径可为空，附加字段也可省略。

例如，缺少条件引用的信号时可返回以下假设响应；键仅用于定位本地草稿，不包含条件原文、信号内容或秘密：

```json
{
  "ok": false,
  "diagnostics": [{
    "code": "signal_missing",
    "message": "Define the signal referenced by this condition or change the condition.",
    "path": ["draft", "steps", 0, "condition"],
    "step_key": "test_login",
    "feature_type": "auth.form_login"
  }]
}
```

若当前策略要求 `submit_selector`，而有效配置中仍缺失，可在另一轮校验得到：

```json
{
  "ok": false,
  "diagnostics": [{
    "code": "field_required",
    "message": "Supply this required field; omission or null cannot satisfy the current policy.",
    "path": ["draft", "steps", 0, "config", "submit_selector"],
    "step_key": "test_login",
    "feature_type": "auth.form_login",
    "field": "submit_selector"
  }]
}
```

这不是缺失选择器的实际值，也不会把私有默认值、凭据、原始异常、Pydantic `input`/错误正文或管理端 local/resolved 预览交给模型。已知语义规则有具体修复反馈，例如 `flow.jump` 的目标含冒号时为 `flow_jump_target_invalid`，定位到 `config.target_step_key`，提示移除冒号并使用工作流步骤 key；不能仅回报笼统“配置错误”，也不回显有问题的目标值。未知校验规则使用静态 `field_invalid`，未知工具故障使用 `tool_failed` 等静态兜底，不从异常文本猜路径或提取秘密。

**最多 10 项是首个失败校验阶段的有界反馈，不是一次扫描所有步骤、所有阶段的全部错误。** 模型应按路径查看受控 schema，修复草稿并反复校验，直到通过后再提交；修复一项后可能才出现下一阶段错误，仍受原轮次预算限制。工具失败文字和日志也不得附带实际输入、秘密或管理员默认值；管理端原有可读错误字符串不因此变成模型安全输出。完整共享协议见 [Validation Diagnostics](config-ai.md#validation-diagnostics)。

| 边界 | 当前值（可调项列默认值，其余为固定限制） |
| --- | --- |
| 输入 | 重命名标题/站点名 1-128 字符；目标 URL 1-512；导航 `path` 1-2048 / `url` 1-4096 且二选一，运行时与工具 schema 一致；`trusted_origins` 最多 20 个精确公共 origin；消息 1-12000；未知字段拒绝；宿主交互明确批准，消息 API 的发送同意仍必须是字面量 `true` |

| 自动标题 | `auto_title` 默认 true；仅前 3 条用户消息内的成功轮次且未锁定；独立、无工具调用固定最多 10 秒且计入配置的总预算；用户内容序列化预算约 8 KiB，响应最多 16 KiB，无重试 |
| 单步 | 活动最多 90 秒，受步骤超时/浏览器剩余 TTL 和本轮活动预算约束；非 post 精确重试按当前工具范围自动授权；auth 每用户轮次默认 3、范围 1-20；每浏览器 20 个操作、每聊天会话账本 256 个 UUID；旧人工重试 API 保留兼容 |
| DOM | 扫描 5000 节点 / 深度 64 / 2 MiB，每浏览器缓存 4 份；普通分页 100 节点 / 32 KiB，执行前后每份 24 KiB；普通 Worker 响应读取上限 64 KiB，不等于通用工具结果上限 |

| 宿主交互 | 每次最多等待 180 秒，实际等待不消耗本轮活动预算，等量顺延截止时间；活动预算已耗尽不弹出，停止/关闭服务立即取消；同轮同 subject 不重复请求；通用问题最多 20 选项/8 字段，每字段最多 2000 字符，仅非秘密输入 |

| 工具 | 单次参数最多 64 KiB；单次结果最多 128 KiB；提交提案必须是该响应中唯一的调用 |

异步超时不能硬中断同步校验或数据库阻塞，不是每个操作都能保证的硬墙钟截止时间。模型服务连接不走 SiteFlow 浏览器代理车道；目标 `proxy` 只控制发现浏览器车道，保存后的工作流另用 `run_lane_policy`。用户明确要求后，通过 `update_site_config` 分别审核 `observation.proxy` 与 `patch.lane_policy`，不从失败推断需要改设置；旧代理交互的 `scope` 仅描述兼容行为。

## API 与排查

下表路径以前缀 `/api/v1/assistant` 开始，要求登录；聊天接口按用户名校验归属，`/settings` 和 `/takeover/settings` 则是全局设置，接管审计仍按 owner 过滤。修改接口还要求登录会话绑定的 CSRF cookie 与 `X-CSRF-Token`。认证不更新登录活跃时间，响应使用 `Cache-Control: no-store`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /settings` | 读取全局 `{revision, source, values}`；无记录时 revision 为 0、source 为 `default`，不写数据库 |
| `PUT /settings` | `{expected_revision, values}`，CAS 保存全局设置，返回递增的 revision 及 source `db`；values 是替换而非 patch，省略的值字段按 schema 默认值补齐 |
| `POST /settings/reset` | `{expected_revision}`，CAS 写入全部默认值并递增修订，不清理聊天、标题锁或损坏记录 |
| `GET /takeover/settings` | 读取全局持久委托、revision、authorizing_owner、authorized_at、effective_from，不调用模型 |
| `PUT /takeover/settings` | `{expected_revision, confirm: true, values}`，独立持久授权并 CAS 保存，不调用模型或回填历史失败 |
| `GET /takeover/actions` | `limit` 默认 100、1-100；只读当前 owner 的接管审计，UI 显示最近 20 条 |
| `GET /sessions` | 当前 owner 会话实时分页；offset 非负、默认 0，limit 1-100、默认 100；返回 offset/limit/next_offset/truncated，无 total 保证，UI 可加载更多 |
| `POST /sessions` | 直接创建，UI 发送 `{}`；可选 `title`、`consent_to_send`（默认 false）；非空显式标题锁定自动命名，创建不调用模型 |
| `GET /sessions/{uuid}` | 详情及最新消息 |
| `PUT /sessions/{uuid}/title` | `{title: "新标题"}`，去除首尾空白后 1-128 字符；仅空闲可改，永久锁定自动命名，返回更新详情 |
| `PUT /sessions/{uuid}/target` | 保留的旧宿主接口，非当前聊天 UI 前置步骤：`{authorized: true, name, base_url, credential_mode, site_id, workflow_site_id, proxy, run_lane_policy, trusted_origins, workflow_consent, screenshot_consent}`；两个站点 ID 可省略或为 null，可信源默认 `[]`，两个独立同意均默认 false，运行车道默认 `auto` |
| `POST /sessions/{uuid}/interactions/{interaction_id}/response` | 运行中 owner/CSRF 保护的宿主决定；`{decision: "approve"}` / `{decision: "deny"}`；选择问题批准附 `selections`，输入问题附 `values`，拒绝不带答案；绑定有效才由原等待调用应用结果，相同响应幂等、冲突拒绝 |
| `POST /sessions/{uuid}/messages` | `{content, consent_to_send: true, request_id: UUID}`，返回 202 |
| `POST /sessions/{uuid}/browser/screenshot` | 空对象 `{}`；空闲、owner、CSRF、截图同意检查后返回有界 JPEG 的 base64 及安全元数据，供临时 UI 预览，不调用模型或持久化此预览 |
| `POST /sessions/{uuid}/browser/refresh` | 空对象 `{}`；空闲、owner、CSRF 检查后以新 GET 刷新当前助手页，返回会话详情；不重提 POST 或解除不确定性 |
| `POST /sessions/{uuid}/retry-approvals/{approval_id}/decision` | `{decision: "approve"}` 或 `{decision: "deny"}`；运行中、owner、CSRF 检查后决定 pending 审批；批准立即恢复原调用一次，拒绝不执行，同决定重放幂等、冲突决定拒绝 |
| `POST /sessions/{uuid}/retry-authorizations` | 可选旧版空闲预授权：`{operation_id: UUID, confirmed: true, request_id: UUID}`；owner、CSRF 校验后批准冻结步骤一次，返回含公开 `retry_authorizations` 的详情，此入口不执行或自动发消息 |
| `GET /sessions/{uuid}/images/{image_id}` | 登录 owner 读取加密历史图像解密后的 JPEG，`no-store`、`nosniff`；不公开给其他用户，不是无鉴权图片地址 |
| `GET /sessions/{uuid}/events` | `event: update` 的 JSON 全量快照及注释 heartbeat |
| `POST /sessions/{uuid}/cancel` | 停止助手轮次并释放助手浏览器，不是 `cancel_run`，不取消已提交完整任务 |
| `DELETE /sessions/{uuid}` | 删除空闲会话及消息，返回 204；运行中需先取消 |

列表/详情包含 `title`、`title_locked`、`title_revision`。目标请求中的 URL 和认证方式字段分别名为 `base_url`、`credential_mode`，`base_url` 可保留查询与片段；公开目标若含敏感参数会投影为脱敏地址，并标记 `base_url_redacted`、`redacted_parameters`，不能把该投影回填为可运行配置。`trusted_origins` 仅接受最多 20 个规范公共 origin，不接受完整路径 URL 或正则。`site_id` 默认 `null`，非空须为正整数的已保存站点 ID，必须与原始目标完全同源，额外可信源不能用于绑定；宿主冻结并复查身份与配置修订。模型可提出受类型约束的目标候选，但只有宿主明确确认才成为目标，不能直接提交权限补丁。

`workflow_site_id` 同样须为原始目标完全同源的正整数站点 ID，单独冻结目的站点身份/修订；它不从 `site_id` 自动推导。`workflow_consent` 不由旧 `authorized` 派生，旧目标缺字段按未同意处理；有效交互或用户明确启用的对应全局默认值才可授予。旧目标 API 的 `run_lane_policy` 允许 `auto`、`general`、`interaction`、`proxy_general`、`proxy_interaction`，默认 `auto` 实际为 `general`；新聊天目标默认 `general`。用户明确要求变更已保存目的站点车道后，用 `update_site_config` 的 `patch.lane_policy` 审核全部五种策略，与发现 `observation.proxy` 独立。四个工作流能力和设置工具都是模型工具，不是开放任意 JSON 保存或任意运行的公共 API 旁路；正常手动编辑/API 不受新增助手启用证据门禁影响。

详情/SSE 的 `pending_approval` 为 null 或仅包含 `id`、`operation_id`、`feature_type`、`status`、`created_at`、`expires_at`、`title` 的安全对象；不含冻结步骤、私有授权密钥、指纹或浏览器身份。通用 `pending_interaction` 另只公开 `id`、`kind`、`purpose`、`title`、`description`、`expires_at`、`options`、`multiple`、`fields`、`review`，不公开私有冻结参数/指纹。等待时会话仍运行，核对面板在输入框上方，可用「停止」取消；失效/拒绝/超时不执行，重启取消 pending 而不自动续跑。

新 UI 通过类型化宿主交互确认目标及执行/截图/工作流权限；站点设置由 `update_site_config` 生成内部 `site_config` 审核，购买/补签由宿主生成内部 `consumption` 审核；模板、全局调度和取消分别由专用工具生成 `template_import`、`scheduler_config`、`run_cancel` 审核，Cookie 清除由 `clear_bound_site_cookies` 生成 `cookie_clear` 范围审核。这**六个内部 purpose** 均不能通过公共 `request_user_interaction` 直接伪造。通用问题不授予权限。统一执行权限派生凭据、副作用和冻结的当前功能清单，不包含截图/工作流/消费或 Cookie 清除批准，拒绝按整个执行能力去重。`manual` 且有可用站点凭据绑定、或选择 `bitwarden` 时单步清单可包含上述 18 项；`manual` 未绑定及 `cookie` / `none` 排除两项认证和 `challenge.2fa`，仍可浏览和测试其余受支持功能。绑定不保证凭据实际存在，执行时仍会检查。Cookie 私有注入不改变此清单。工作流权限独立控制导入及完整运行，不以单步执行授权为前提，也不能跳过精确审核或逐次消费审核。

旧接口的 `confirmed` / `browser_consent` 及细分权限字段仍用于已有调用和已保存目标；旧显式权限保持有效，不因迁移自动扩权。缺少权限时由宿主交互请求，或使用用户明确启用的对应全局默认值，不能由模型或后台迁移代为同意。

旧 `PUT /target` 替换宿主授权并释放旧浏览器，不是合并保留旧权限，运行中不可调用；当前 UI 没有目标设置弹窗。运行中目标交互可在绑定校验后建立新目标。仅为兼容保留的旧可信来源交互合并来源，旧代理交互按用户单选和 `scope` 更新目标字段；新调用一律使用 `update_site_config`，其观察来源替换完整列表，非空 patch 则对绑定站点实际 CAS 保存。目标修订改变后旧摘要/提案引用失效，旧浏览器需安全重开；不能把更换浏览器当作解除不确定性。能力授权保存在当前目标内，不要求重新确认整个目标。目标/能力确认本身不导航、导入、执行、重试或保存站点配置；设置批准则只保存已审核差异，不触发运行。旧目标修订的提案不能直接导入，应重新校验并提交。运行中人工改标题或删除仍被拒绝。

Worker 的 `/assistant-browser/*` 是 API 持有能力令牌调用的内部接口，不是公开工具分发器，不应暴露公网。新增内部接口 **`POST /assistant-browser/{session_id}/execute`** 接收 `token`、`operation_id`、`site_origin`、一个 `step`、`execution: {feature_types, allow_sign}`，仅认证步骤可带 API 私下提供的 `credentials`。返回绑定会话/车道/操作 ID 的状态、静态日志、前后 DOM 快照和安全结果。

职责分界：前端发送消息并提交宿主交互决定，也可显式请求截图预览、刷新或单步重试批准；API 核对用户归属、当前授权、站点修订，规范化步骤、登记持久 UUID/单次重试授权，并私下解析凭据；Worker 校验令牌、源、受控功能、原始表单能力与操作指纹，在现有页面执行单步并保留页面。完整工作流则由 API 的导入/运行 action 账本及配置守卫约束，经共享 executor 派发给 Worker，不走发现页的单步执行接口。内部截图/刷新分别走 `POST /assistant-browser/{session_id}/screenshot`、`POST /assistant-browser/{session_id}/refresh`；这些内部 HTTP POST 不等于允许目标网站 POST。**前端不直接调用 Worker `/execute`，模型也不获得 Worker URL、能力令牌、重试密钥或凭据参数。**

请求错误返回静态 `detail.code`，例如 `generation_disabled` / `model_unavailable` / `assistant_settings_invalid`（503）、`assistant_busy`（429）、`session_running` / `assistant_settings_conflict`（409）、`session_not_found`（404）、`invalid_request` / `secret_input`（422）、`request_limit`（413）、`request_timeout`（408）；登录和 CSRF 保留 401/403。已接受的后台轮次失败通常写入系统消息，例如 `[provider_timeout]`、`[provider_network]`、`[invalid_response:truncated]`、`[context_limit]`，不是把 202 改成错误响应。

遇到中断先「刷新会话」核对状态和工具结果，再决定是否发送新消息；这不是刷新网站或重试步骤。`browser_reopen_required` 需请模型重新打开，`target_confirmation_required` 需让助手发起目标交互并由用户在 UI 确认；`browser_trust_required` 需核对完整 URL 与 `target_origin`，只有用户明确要求变更来源后才用 `update_site_config` 审核完整观察来源列表，不主动扩权或换通道绕过。`redacted_url_not_usable` 表示脱敏证据不能当作工作配置。持续 `browser_unavailable` 应检查配套 Worker 版本、交互车道占用、代理及 Worker 本地 DNS。`credential_binding_changed` 需重新核对绑定；`operation_already_used` 不可复用 ID，精确重试用原 ID 的 `retry_step`。`outcome_uncertain` 保留未知来源事实，当前非 post 单步按类别策略；`retry_authorization_required` 应核对当前宿主工具范围与绑定，不因旧文字声称必需人工审批。`auth_budget_exhausted` 等待真实新用户轮次，不换目标/浏览器重置。`screenshot_consent_required` 需独立图像同意，`model_vision_required` 需支持视觉的本轮配置，不能据此推断登录失败。不要粘贴凭据排障；已知 Key 检测不是通用 DLP，请自行审核请求、DOM、链接和输出。

浏览器打开失败的工具结果返回安全的 `code`、`lane_key` 和 `reason`，例如 `code: "browser_unavailable"`、`lane_key: "proxy_interaction"`、`reason: "browser_dns_denied"`。按实际返回值排查，不把 Worker 原始异常、响应正文、凭据或未净化 URL 发送给模型：

| `reason` | 排查含义 |
| --- | --- |
| `browser_dns_denied` | Worker 本地 DNS 解析失败或解析结果不符合公共地址限制；代理车道也受此限制，不证明需要代理。读取失败若 `page_retained: true` 则无证据但保留页面，不是登录失败结论 |
| `browser_credential_endpoint_not_approved`（旧结果） | 旧端点策略诊断，不是缺少站点 ID、Bitwarden 故障或需网站专用适配；当前实现不要求逐表单批准 POST action |
| `browser_url_denied` / `browser_redirect_denied` | URL 或导航/重定向违反公共地址、原始源执行等边界；不要绕过限制。可供用户确认的公共跨源候选另以 `browser_trust_required` 返回 |
| `browser_lane_busy` | 所选交互车道占用或获取容量超时；核对该车道，不是通用车道 |
| `browser_lane_unavailable` | 所选车道租约、启动或浏览器上下文不可用；检查该车道及 Worker 配套版本 |
| `browser_access_denied` | Worker 返回 403，但未提供可识别的更具体安全原因；不能据此断言 DNS、代理或车道停止 |

此前生产环境观察到两次 `browser_open` 返回 403；没有证据表明由 `general` 停止导致，具体根因尚未确认。明确交互车道及增加安全诊断不等于已经完整修复该生产问题，也不能把离线测试通过当作生产复测成功。缺少具体原因时应明确原因未知，保留安全诊断供排查。

Cookie 清除是上述重开建议的例外：`clear_bound_site_cookies` 返回 `browser_reopen_required` 时只说明缺少 READY 原始绑定浏览器，不自动 `browser_open`。`cookie_binding_changed` 需重新核对显式绑定，不能改用同主机其他站点；`cookie_restore_unavailable` 不能通过把原始 Cookie 交给模型解决。清除后的部分/未知结果及同 ID 重放按[绑定站点 Cookie](#绑定站点-cookie)处理，不套用 `retry_step`。
