# 使用指南

本指南介绍页面操作和日常使用。首次安装、登录与安全配置见 [README](../README.md)；服务部署及数据备份见 [部署与运维](deployment.md)。

## 建议顺序

1. 登录并修改管理员密码。
2. 在「系统设置」配置需要的代理、凭据和验证码服务，使用测试按钮确认连接。
3. 在「模板管理」建立通用流程，或导入可信来源的模板配置。
4. 在「站点管理」添加站点、选择模板、保存登录来源并调整站点步骤。
5. 先手动运行一个站点，检查步骤结果、日志和页面，再启用自动调度。
6. 在「通知设置」配置结果推送，通过「运行分析」持续查看执行情况。

## 系统设置

代理、2FAuth、CFbox、Bitwarden 和视觉模型可在此保存、测试或清除。字段会显示来源：环境变量提供的配置只读；页面保存的配置可以继续编辑。

- 配置代理后，站点才能使用代理车道。代理失败时不会自动改为直连。
- 使用 Bitwarden 时，填写服务地址和访问令牌，或使用部署自带的服务；同时配置该服务需要的保险库凭据。
- 使用 Turnstile 功能前配置 CFbox 地址。仅当 CFbox 自身启用鉴权时填写 API Key。
- 使用视觉验证码或图片答题时，在「大模型支持」配置支持图片输入的模型；修改后先「保存模型配置」，再「测试已保存配置」，未保存的输入不会用于测试。
- 调度支持关闭、定时、间隔和随机时间范围，可设置时区；环境变量指定的字段不能在页面修改。
- 可查看任务日志和截图的保留设置、数量及空间占用，按需要执行清理。清理前确认不再需要这些排查资料。

「大模型支持」中的「输出 Token 上限（max_tokens）」用于后端图片/文本自测、Worker 字符验证码/图片答题/九宫格/结果判断、AI 配置生成，并由持久化智能助手默认继承；助手可在「助手设置」单独覆盖，不影响其他入口。全局字段正整数原样发送；留空或 0 保存后清除数据库上限，不发送该参数，使用上游默认值，不保证无限输出。全局配置 API 省略该字段保留原值，显式 null、空白或 0 清除上限。可选环境变量 `SITEFLOW_VISION_MAX_TOKENS` 即使设为 0 也会覆盖全局数据库值并锁定全局字段；助手设置的 null 才表示继承，显式 0 或正整数则覆盖本轮助手调用。支持思考模型，但推理可能消耗预算，应为最终答案或工具调用预留足够 Token；系统不会把推理当成答案或自动切换模型。固定响应大小等安全限制不变。

完整字段与环境变量见 [集成配置](configuration.md)。

## 模板与功能

「功能管理」可查看各类功能的配置字段、必填项及所需服务。通用默认值可在支持的功能设置中调整；具体站点的差异优先在站点中覆盖。

在「模板管理」新建模板并添加分组和步骤。选择功能后填写对应字段，保存前补齐必填项。已有类似流程时，可选择父模板，再调整需要覆盖的步骤。

已有站点流程可在模板新建/编辑器中点「从站点导入配置」，选择来源并确认。仅将站点**本地**步骤、分组、信号替换到当前表单，并将站点 `template_id` 映射为模板 `parent_id`；不把解析后的继承结果拍平。当前名称、描述和启用状态保持不变，不复制站点凭据、Cookie、调度或其他元数据，源站点不变。**导入只填表，不自动保存或运行**，仍需检查继承链、校验并手动保存；活动/结果不明的来源、无效工作流或循环继承会被拒绝。助手审核后直接保存模板是另一入口，见下文。

- 步骤可保持继承、强制启用，或保留配置但禁用。
- 使用上下移动调整步骤顺序；在模板中定义的顺序会沿用到站点。
- 修改继承步骤时点击「修改步骤」；需要回到父级配置时使用恢复继承。
- 「代码配置」可粘贴 JSON 批量编辑当前步骤，应用前检查字段和错误提示。
- 模板和站点步骤的 key 由系统生成。使用条件跳转时选择目标步骤，不手工改写 key。
- 页面信号可配置包含/排除文本或选择器，步骤条件引用这些信号。保存前确保被引用的信号存在；无法判断的条件会要求人工检查。
- 条件跳转可跳到指定步骤或重新开始，需设置合理的跳转次数限制，避免反复提交操作。

### 选择器与元素拾取

选择器可填写多个候选，通常按顺序使用第一个匹配项；`auth.form_login` 的成功元素检查则跨主页面及可见同源 iframe 检查各候选的多个匹配，所有祖先 iframe 也须可见且同源，任一匹配可见即可，不限于第一个匹配。优先使用能唯一定位目标的操作选择器，避免泛用的 `button`、`input` 等误点其他操作。

信号的包含/排除选择器默认检查元素是否存在，隐藏元素也可能命中；需要可见证据可在工作流的 Playwright 选择器中显式使用 `:visible`。表单登录成功元素要求可见。系统不会自动追加 `:visible` 或改写已保存的信号，不新增数据库列，也不改变默认语义。文本规则 `include_texts` / `exclude_texts` 匹配页面标题和各 frame 的 body `innerText`，通常不包含 body 内隐藏后代文本；不能把选择器存在性语义套用到文本规则。

点击选择器字段旁的「拾取」，在交互车道打开页面。必要时先正常登录，再按住 **Alt/Option** 点击目标元素，确认生成的选择器。拾取会话默认 15 分钟过期，完成后关闭会话。

## 站点与登录

在「站点管理」添加名称和基础地址，选择模板，然后检查展开的步骤。步骤地址可使用 `{base_url}`，运行时替换为当前站点地址。

继承字段可以单独覆盖；点击「修改步骤」调整模板步骤，不需要复制整套流程。保存后查看解析预览，核对最终步骤、条件和参数。

「登录凭据」中选择适合的来源：

- **账户**：首次填写用户名和密码；以后可以单独更新，密码不回显。
- **Cookie**：粘贴浏览器 Cookie 请求头或支持的 JSON。保存后不回显明文，过期时重新导入。
- **Bitwarden**：启用集成后选择域名匹配方式；有多个相似域名时检查完整域名、主域名或自定义匹配是否符合预期。
- **插件提供商**：先在插件管理中完成接入和审批，再在对应标签启用，并设置匹配方式。

外部凭据来源互斥，不要同时启用多个提供商。远程凭据不会自动写入手动账户字段。更换来源后先做单站点验证。

### 表单登录就绪

`auth.form_login` 的 `success_wait_seconds` 默认 **10 秒**，只接受 **1-120 的严格整数**，不接受布尔值、小数、字符串或 null。此字段只控制提交后的成功证据等待；步骤总超时 `timeout_seconds` 须另行覆盖凭据/秘密查询、定位、填写、点击提交及成功等待，不会自动延长，助手单步还受 90 秒及剩余会话/轮次预算限制。不要只靠延长等待掩盖首个匹配隐藏、选择器错误或存在性与可见性要求的差异。

提交一次后，只读轮询主页面及可见同源 iframe 中各 `success_selector` 的匹配，所有祖先 iframe 须可见且同源，`about:blank` / `srcdoc` 沿父链继承来源，凭据 `trusted_urls` 不扩大成功证据范围。任一匹配可见即可，不只检查首个匹配；每轮最多检查 100 个 frame、每个选择器在各 frame 中最多 100 个匹配，共用等待期限。隐藏节点存在不算成功，成功选择器留空只表示已提交、不证明登录成功。等待不会自动刷新、导航或重提表单；超时也不证明原提交未生效。

工作流信号的选择器检测默认只判断**存在性**，隐藏节点也可能命中，与登录成功元素的**可见性**检查不同；稍后的 `is_logged_in` 命中不能倒推较早检查已通过。任务 329 在 `06:57:42.875` 提交，已经等待约 10 秒，旧实现仅检查各选择器首个匹配的可见性，于 `06:57:52.940` 失败，`06:57:53.130` 截图已显示已登录；`settle_home` 因相同 URL 跳过 GET、耗时约 `0.008` 秒，未实际刷新，再等待 3 秒后信号按存在性命中，不是刷新后才成功。现有证据无当时匹配/可见数量，不能确定是隐藏首匹配、延迟渲染还是其他情况，也不能从截图证明具体 DOM 属性。不能把更长等待当作根因修复，也不代表已完成生产复测；详见 [登录时序与误判](assistant-discovery.md#登录时序与误判)。本次是实现修复的文档更新，不是在线配置变更，站点 98 保持修订 3，步骤总超时已为 120 秒，无需因此加长。其他功能同名等待字段的默认值不变。

超时后的诊断原因及匹配/可见计数是**超时后的有界只读采样**，不是等待期间的历史证据或原子快照。选择器索引对应原步骤 `config.success_selector` 的配置索引（从 0 开始），不是 DOM 匹配序号；请按原配置核对，诊断不回显选择器值、表单值或凭据。后来的可见或不存在都不能倒推等待期间的状态。助手的 `browser_check_selector` 仅支持 CSS，不直接支持 Playwright `:visible`，应核对返回的 `visible_count`。

### 智能助手

菜单「智能助手」（`/assistant`）可新建或继续旧会话，聊天载荷加密保存并按用户名归属，不随退出登录或关闭页面删除。管理员需设置 `SITEFLOW_CONFIG_AI_ENABLED=true`，配置支持工具调用的大模型，并配套升级 Web、API、Worker。

新模型输出的语言优先级为「真实用户明确要求 > 真实用户消息语言 > 安装级 `Settings.scheduler_timezone`（`SITEFLOW_SCHEDULER_TIMEZONE`）白名单默认语言」，不是用户确认的国籍/所在地，也不由站点时区切换；站点时区只用于接管任务本地日分组。上海默认简体中文，台北/香港/澳门为繁体中文，东京日语、首尔韩语、指定英美时区英语、巴黎法语、柏林德语；无效或未映射时区（含新加坡）保留简体中文。自动英文接管指令、网页、工具/日志及助手输出不构成人类偏好。策略涵盖最终回复、可见工具标题、提案说明和接管结论模型正文；固定欢迎语/宿主 UI、中文通知前缀/标题及独立会话标题生成器不变，历史结论和冻结通知不翻译/回填、不加翻译或模型调用。这是提示指令，不是语言校验或送达保证；精确映射见[回复语言](ai-assistant.md#回复语言)。

当前共 **23 项内置功能**可编写提案并用于授权完整运行，包括公开非秘密 `action.fill` 和四项购买/补签 `post.*`；孤立单步为 **18 项**，排除 `flow.jump` 和四项 `post.*`，插件仍不开放。普通交互工具为 **38**，包括 Cookie 清除、站点转模板、全局调度、任务取消、历史版本和 artifact 读取；另有 1 个接管专用结论工具，注册表合计 39 个，自动接管只开放受限子集。目录与 schema 按当前代码及服务端策略提供，不保证生产站点适用或业务成功。

页面顶部依次为「助手接管」「助手设置」「新建会话」，无需创建会话即可打开前两项。「助手设置」是所有用户、所有会话共用的全局设置，保存于 `AppSetting` 的 `assistant.settings`，不是单会话偏好；打开、刷新、保存和恢复默认均不调用模型。接管是独立持久委托，不沿用下表的自动授权默认值。

| 设置字段 | 默认值 | 可用范围或语义 |
| --- | --- | --- |
| `max_tool_calls` 工具调用次数 | 20 | 每轮 1-200 次 |
| `max_model_rounds` 模型轮数 | 12 | 主对话每轮 1-100 次模型请求，不含独立标题/摘要调用 |
| `max_parallel_tool_calls` 每轮并行工具调用数 | 4 | 模型一次响应最多发回 1-8 个工具调用；**实际始终顺序派发，不并行执行** |
| `max_auth_uses_per_turn` 每用户轮次认证次数 | 3 | 严格整数 1-20，助手单步及完整保存运行共享发起真实用户轮次的登录/密码验证及重试额度；解析凭据前预留，失败计次；完整运行按实际新租约计次，条件跳过不计；challenge.2fa 不占额度，OTP 仍私有 |
| `turn_timeout_seconds` 单轮超时 | 180 秒 | 30-1800 秒，主对话、摘要和标题共用活动预算，不含等待用户确认 |
| `context_max_tokens` 上下文预算 | 64000 Token | 16000-1000000，本地预检估算预算，不是提供商精确分词或容量声明 |
| `max_tokens` 模型输出上限 | null | 继承全局；取消继承后留空或 0 保存为 0、向提供商省略参数；正整数最多 9007199254740991 |
| `auto_compact` 自动整理上下文 | true | 关闭忽略已有摘要/边界，从原始历史重建，超限报错；不删除已保存摘要或记录，见下文 |
| `auto_title` 自动生成会话标题 | true | 关闭保留最后标题，不解除人工标题锁；恢复默认或重新开启也不解锁 |
| `auto_authorize_execution` 默认执行授权 | false | 仅用户明确勾选后开启，目标内统一执行能力，不是逐功能授权 |
| `auto_authorize_screenshot` 默认截图授权 | false | 仅用户明确勾选后开启，独立于执行及工作流能力 |
| `auto_authorize_workflow` 默认工作流授权 | false | 仅用户明确勾选后开启，涵盖提案导入及绑定站点完整测试 |

数字输入只接受范围内的十进制整数，不接受小数或科学计数法。每条新消息接收时取设置快照，同一旧会话的后续消息也会应用保存后的设置，**正在运行的轮次不变**；主对话、标题和摘要都沿用本轮 Token 覆盖。三个全局授权默认值彼此独立、默认关闭，不跳过目标身份、可信来源或代理的显式宿主确认，也不扩大凭据/来源范围。执行开关只控制浏览器单步；第三个工作流开关保留原有组合权限，**同时授权提案导入和绑定站点完整运行，不是仅保存，也不依赖单步执行开关**，不拆分权限。即使第三项文案仍写「保存工作流」，也须按这一完整范围审核。已保存目标/会话权限仍可复用，关闭默认值不撤销已授予权限。提供商 URL、API Key、模型连接不变；这些设置仅用于持久化助手，不改变单次「AI 生成配置」接口。整个模型请求 1536 KiB、主模型响应 256 KiB、单步 90 秒和人工助手浏览器准入/创建起固定 15 分钟 TTL 等安全边界不能在此调整；消息不续租，自动接管结束则提前释放本轮浏览器。

完整匹配旧版结构的持久化 `context_max_bytes` 按 `ceil(bytes / 4)` 近似换算并钳制到 16000-1000000，新授权默认值补 false；读取不写库、不改修订，下一次成功 CAS 保存/恢复默认才写新结构。旧 bytes 字段原范围 64000-1000000，其他损坏/缺字段结构仍报错，不静默修复；该迁移公式不是当前发送前估算算法。

设置通过 `GET /api/v1/assistant/settings` 读取 `{revision, source, values}`；`PUT /api/v1/assistant/settings` 提交 `{expected_revision, values}`，`POST /api/v1/assistant/settings/reset` 提交 `{expected_revision}`。无记录时显示默认值、修订 0；保存及恢复默认均按修订 CAS 防覆盖，成功递增修订，恢复默认仍写数据库、不归零。409 `assistant_settings_conflict` 时保留草稿、不自动重试，核对后「刷新设置」并重新编辑；刷新会丢弃草稿，响应丢失也应先刷新确认是否已保存。持久化设置损坏返回 503 `assistant_settings_invalid`，不会静默采用默认值，新消息也无法继续；恢复默认同样拒绝覆盖损坏记录，需管理员排查。完整字段及权限见 [助手设置](ai-assistant.md#助手设置)。

1. 点「新建会话」直接创建，没有弹窗，也无需预填目标设置。初始「新会话」标题和固定 assistant 欢迎语不调用模型。先在聊天中提供非秘密的公共 URL、站点名称和流程需求，请助手用 `check_site` 检查是否已配置，再澄清认证来源及代理偏好。发送即同意将消息、有限历史和已授权观察结果交给模型，不再要求发送前勾选。
2. 可请助手读取脱敏的站点/模板本地与解析配置、近期运行摘要、集成配置来源及车道状态。这些元数据工具不返回凭据、密钥、原始日志或截图；历史日志/图像另用下文的 artifact 专用工具，不能把元数据工具的限制当作全部工具的限制。过滤不是通用 DLP；没有任意 SQL、Shell、JavaScript、任意路径文件或密钥读取工具。
3. 助手用 `request_user_interaction` 的 `purpose: "target"` 发起宿主确认。输入框上方面板只以可读字段展示网站名称和完整公共地址，不展示原始 JSON；认证方式、同源凭据 `site_id` 和独立配置目的 `workflow_site_id`（空为新建，同样须完全同源）留在私有载荷中。核对后「确认并继续」，原调用恢复。**目标确认只授权浏览观察，不授权真实业务执行**；即使开启全局能力默认值也必须确认目标。新目标代理默认关闭、保存运行车道默认 `general`。用户明确要求对应设置变更后才走 `update_site_config` 精确审核，不从 DOM、浏览失败或模型建议推断需要变更。额外可信来源最多 20 个规范公共 HTTP(S) origin，不含路径、查询、片段、用户信息或正则，只允许导航/观察，不扩大执行或凭据权限。聊天、认证方式和 schema 均不能代替宿主决定。
4. 请模型打开并观察目标。`browser_open` 使用宿主确认的完整 `base_url`；`browser_navigate` 除 `title` 外必须且只能传 `path` 或完整 `url` 一个地址字段，`url` 限原始源或用户确认的可信源，可保留非敏感查询与片段。`proxy=false` 固定使用 `interaction`，`proxy=true` 固定使用 `proxy_interaction`，`browser_open` 通过车道租约按需自动启动所选车道，不使用 `general` / `proxy_general`；通用车道停止与此无关。人工登录需进入返回的同一交互车道 VNC，**另开由你控制的标签页**；助手页在授权单步活动之外只允许 GET/HEAD，人工 POST 也会被阻止。完成后要求 `browser_navigate` 重新导航（可用当前地址重新加载），再观察共享 Cookie 生效后的页面。
5. `manual` 未绑定已有站点仍可确认授权、浏览和进行非认证测试，但不能自动登录。自动表单认证需先保存站点及凭据并绑定完全同源的站点，或选择 Bitwarden 后重新确认目标；API 冻结绑定身份与修订，变化后需重确认。Bitwarden 可为未保存的新域名私下按完整域名匹配。Cookie / 无需登录模式不提供账号密码或 OTP 测试凭据，但有效显式绑定下仍可私有注入已保存 Cookie，或人工登录后观察，见下文。凭据由 API 私下交给 Worker，不进入聊天或模型，不要在聊天中提供密码。
6. 单步支持上述 18 项，含 2FA、Turnstile、字符/九宫格验证码、iframe 图片验证码签到、图片答题、公开填充和布尔结果，完整清单见 [单步验证](ai-assistant.md#单步验证)。缺少执行权限且未明确开启全局执行默认值时，宿主暂停调用并请求统一执行授权，批准后原调用继续，不需另发消息。面板冻结并展示当前支持且来源允许的清单及凭据/副作用权限，批准只授予该清单，不逐功能反复确认。拒绝、超时、取消或失效按整个执行能力去重，同轮不能换功能重问。未绑定 manual 及 Cookie / 无需登录模式排除两项认证和 2FA。**真实登录、签到、点击和挑战可能产生费用或其他副作用，不是模拟**。四项购买/补签孤立测试尚未实现，因为依赖真实 SiteJob 消费检查点，不是用户拒绝权限，应改用完整运行审核；插件、任意代码仍不支持。
7. 单步必须启用且无条件，在当前页面执行最多 90 秒，单次派发不隐式重派，结束保留页面。返回安全结果及可用的前后结构化 DOM 快照，**不是图像**；每份最多 24 KiB，两份及外层须落在 API 64 KiB Worker 响应读取上限内。验证码处理后可继续观察、选择器检查、独立授权截图及同页授权单步，不需重开，输入值仍省略。比较证据，不把“已提交”当作成功。普通会话精确重试以原操作 ID 调用 `retry_step`，宿主自动签发一次原步骤能力、以新 UUID 执行，不弹 UI 审批；auth 重试另占共享额度。新授权非 post 步骤不因历史未知一概拒绝，旧 `unknown` 来源事实和账本仍保留。每浏览器最多 20 个操作，每聊天会话持久账本最多 256 个 ID。
8. 展开并人工审核提案 JSON、说明、待确认问题及 `required_site_settings` 的认证来源、提供商和保存运行车道。`trusted_origins` 仅作观察来源说明，跨源提示的 `trusted_url_pattern` 只是候选；站点 `trusted_urls` 涉及凭据授权，需在正常编辑器另行审核保存，或用户明确要求后通过 `update_site_config` 精确审核已保存目的站点的规则，不能自动沿用观察授权。提案本身不保存、不运行。用户要求导入/测试时，模型可在同轮继续；缺少工作流权限且未明确开启对应全局默认值时，宿主请求独立授权，批准后恢复同一调用，无需预先设置或另发消息，只能引用已成功保存的提案 ID。也可人工复制三个工作流集合到正常编辑器，不使用含 `[REDACTED]` 或其编码形式的 URL。

**绑定站点 Cookie**
新助手浏览器首次导航前，可私有注入有效显式绑定站点的已保存 Cookie：优先 `workflow_site_id`，没有时才用凭据 `site_id`；优先绑定失效不回退，不按 hostname 查找站点。所有凭据模式均适用，但不授予 auth、OTP 或完整运行能力；Cookie 原文不进模型/工具参数/助手会话，助手登录后也不自动导出回写。无可用登录态时仍可使用独立人工标签页。Cookie 由当前车道共享 context 持有，非标签页隔离，浏览器 TTL 不变。

用户明确要求清除时，`clear_bound_site_cookies({operation_id})` 使用新 UUID4（另需公共 title），必须已有原始绑定 READY 浏览器并逐次核对内部 `cookie_clear` 面板，不能自动打开浏览器。面板展示站点、地址、共享车道、保存数量及风险；只清绑定站点保存 Cookie 与当前车道精确 host/.host 所有路径 Cookie，同主机同车道其他标签页可能退出，父域/兄弟域/其他车道、账号密码/localStorage 保留且不刷新。有活动任务时拒绝；保存与浏览器结果分别报告，部分/未知不自动重试，同 ID 只返回原结果。无人值守接管不可清除，人工每日会话后续可另行申请。完整事务顺序、generation 失效机制、300 条/256 KiB 私有种子与隐私限制见[绑定站点 Cookie](ai-assistant.md#绑定站点-cookie)；API、Worker、Web 须配套升级。

**私有验证与填充**
- 类别只信任代码内置 `Feature.category` 的 `flow`、`auth`、`challenge`、`sign`、`action`、`post`，不按键前缀、描述、模型参数或插件声明授权。助手单步及完整保存运行的 auth 登录/密码验证及重试共享发起真实用户轮次的额度，解析凭据前预留、失败计次；内部模型轮次、换目标/浏览器不重置。完整运行在运行时签发新 auth 凭据租约时计一次，兑换不重复计次，条件跳过不计；循环重入及执行器重启/回退的新租约仍计次，后台任务跨聊天轮次也不重置原额度。含 auth 的新 `run_site` 派发前检查剩余额度，运行中耗尽拒绝后续 auth 租约；普通手动/调度任务不受此助手额度限制。challenge.2fa 属于 challenge，不计 auth。当前同源授权内的受支持 flow/challenge/sign/action 单步可在历史未知后继续；这只是用户策略许可，不是点击、导航或脚本不会写网站的保证，仍须提示副作用。插件可声明六类，但元数据未验证、危险实际实现需另行审核，不因此开放助手。
- 全部 `challenge.*`、`sign.iframe.image_captcha`、`sign.image_quiz` 由宿主配置的运行时处理。2FA 仅用 `builtin.twofauth`，需凭据同意及已绑定、凭据可用的同源 manual 站点或 Bitwarden 来源。真实 OTP/TOTP 动态码、种子、密码、Cookie、隐藏 token、私有提示词及 API/提供商密钥仍是秘密，绝不索取或回显。图片 CAPTCHA 的 OCR 文本/解题答案不一概视为秘密；用户“它不是秘密”可指图片验证码答案，不能解除实际 OTP 或凭据的保护。配置的识别/视觉服务可能处理图像，不等于“任何模型都不处理图像”。
- 验证码后不锁浏览器，observe/inspect、选择器检查及独立授权截图（含 UI 预览）仍可用，也可在同页连续测试已授权的导航、等待、填充、登录、点击和结果步骤，**不要求重开或强制完整运行**。所有 DOM/选择器证据仍省略输入值，不能通过截图恢复；截图遮罩主页面及可读同源 frame 的输入控件，其余 frame 保守地整体遮罩。页面反映的图片验证码答案可以保留，不保证所有秘密像素均已清除。权限、同源限制、账本与不确定性门禁保持有效。
- 私有 Turnstile 单步需明确批准 `https://challenges.cloudflare.com` 观察来源，并在当前助手页唯一定位可见的受支持 Cloudflare challenge iframe。Worker 绑定原始目标、来源、文档及边界，仅对落在并命中该固定目标的 CFbox 坐标行动，非挑战坐标不执行；不开放任意全页坐标、全页挑战替代绑定、桌面/X11 或其他标签页操作。私有提供商回包回显已知密钥时拒绝，不将密钥填入网页；私有输入在 focus 后复查目标并原子校验/插入，防止焦点事件替换输入目标。
- `action.fill` 仅填显式公开非秘密字面量，不能填密码、账号凭据、Cookie、Token 或 OTP/TOTP 认证动态码；具体字段与内容仍由宿主校验，图片 CAPTCHA 不等于 OTP。`flow.result` 单步仅返回配置布尔值，不调用模型判断；false 是该步骤失败，不证明网站操作失败，也不能改为 true 掩盖失败。完整工作流结果判断遵循宿主策略，其运行配置、提示词及提供商密钥由宿主私下传给 Worker；助手仅获安全布尔结果/状态，不获原始模型答案、判断理由或密钥。

宿主授权、单选/多选和非秘密文本问题均内联显示在输入框上方，不是聊天文本伪造的弹窗；通用 `purpose: "question"` 的确认/偏好答案不授予目标权限。每次交互最多等待 **180 秒**，不按本轮剩余活动时间缩短；活动预算已耗尽则不弹出。仅实际用户等待暂停本轮活动计时，等量顺延共享截止时间及外层超时，不重置预算；审批处理、网络请求和批准后的执行仍消耗剩余活动时间，提供商单请求超时、单步上限和浏览器 TTL 不变。停止及关闭服务仍立即取消。拒绝、超时、取消、失效后同轮同 subject 不重复请求，不能换措辞或拆分绕过；缺少必需授权或必填信息时停止相关操作。输入仅限非秘密文本，最多 8 字段、每字段 2000 字符；选项最多 20 个，没有秘密输入入口，不能索取或回显密码、Cookie、Token、提供商密钥或 OTP/TOTP 认证动态码；图片验证码答案不一概视为秘密，实际输入仍受宿主校验。有效目标/会话权限保留并可复用。

标题/状态操作区和输入区固定保留，消息时间线独立滚动，移动端也可发送/停止。底部安全提示可关闭，关闭状态仅存本浏览器 `localStorage`（`siteflow.assistant.safety.v1`），不改变服务端授权或安全检查，也不替代任何宿主确认。

**站点设置变更**
- 助手不得主动提出或修改任何站点设置。仅在用户明确要求对应变更后调用 `update_site_config`；每次写入均须真实用户审核并批准本次精确差异，包括观察设置、禁用或启用，即使已有工作流权限或开启 `auto_authorize_workflow` 也不能跳过。通用问题、聊天同意及模型的 `user_requested` 参数都不能授权。
- 参数为稳定 `operation_id` UUID、可选 `patch` / `observation`（至少一项非空）及仅启用时可选的 `successful_run_id`，另有公共 `title`。patch 只允许 **10 项**：`name`、`trusted_urls`、`enabled`、`lane_policy`、`support_resign`、`resign_max_days`、`checkin_after`（null 清除）、`timezone`、`tags`、`notes`。不开放 `base_url`、模板、提供商/凭据来源、凭据/Cookie 或 `steps` / `groups` / `signals` 数组。仅修改已确认的 `workflow_site_id`，不能指定任意站点或把凭据源 `site_id` 当作目的地；尚未导入时只可用空 patch 修改观察设置，不创建站点。
- observation 仅允许 `proxy` 与 `trusted_origins`，后者替换完整列表，不是追加。观察代理只控制 `interaction` / `proxy_interaction` 及当前页单步；保存运行独立使用 `patch.lane_policy`，支持 `auto`、`general`、`interaction`、`proxy_general`、`proxy_interaction` 全部五项，`auto` 当前解析为 `general`。旧 `purpose: "proxy"` / `purpose: "trusted_origins"` 仅保留兼容，不再推荐。
- 宿主设置面板以可读字段展示名称、地址、逐项变更前/后及风险提示，不展示原始 JSON。`trusted_urls` 是本站点的凭据/TOTP 信任正则，须核对完整原始正则；宽泛规则可能泄露凭据，不是观察来源授权。`observation.trusted_origins` 仅用于观察/导航，不授权凭据发送或完整运行跨源访问。旧备注隐藏，旧正则/标签只显示数量；秘密、敏感 URL 或脱敏占位值拒绝。
- 同一调用最多等待 **180 秒**，实际用户等待暂停活动预算，批准处理仍计入。批准后原调用复查冻结目标/历史身份/配置修订及设置，再 CAS 保存；历史 actor 为 `assistant`，新绑定与加密 action 回执同事务提交。拒绝、超时、取消、重启或绑定漂移不写入；相同 UUID/相同请求只重放结果，不重复保存。成功后旧浏览器释放，目标修订改变、旧提案/摘要失效，但不清除不确定性。字段边界见 [站点设置变更](ai-assistant.md#站点设置变更)。

**保存与完整测试**
- 更换目标或批准设置变更后，应核对当前目标修订；修订变化使旧提案失效，须重新校验提交，浏览器需安全重开。观察代理不改保存运行车道，运行车道不改观察代理，也不自动导航、运行或重试；无消费计划的正常完整运行仍可同代理模式从通用回退到交互车道，有消费计划则不允许自动回退/重试。单独授予工作流能力不要求更换整个目标。manual 模式导入也需有效的同源凭据站点绑定，不会把该凭据复制到新目的站点。
- `import_workflow_draft` 除公共 `title` 外只接受 `{proposal_message_id}`，必须是当前 owner/会话/目标修订下成功保存的原提案，且无待确认问题；不接受另传草稿或任意站点 ID。导入会重新校验，已有目的站点按冻结身份/修订 CAS 保存，只更新本地步骤、分组、信号及宿主选择的运行车道，保留模板、启用状态、调度、凭据、Cookie、可信网址及其他元数据。配置变化生成新修订和不可变历史；受保护/隐藏本地配置不能安全重建时拒绝并要求人工编辑，不用占位值覆盖。
- 新导入站点默认 **`enabled: false`**，不会自动进入调度，也不复制秘密或浏览器 Cookie。明确授权的助手完整测试可经私有入口运行禁用站点，但不启用它；公开 API 没有对应 force 标志。**导入已有启用站点会保留调度状态，后续调度可能执行新购买/补签配置。** 导入前先核对影响；消费审核仅针对助手调用，不是普通手动/调度的新门禁，后者按既有策略执行。自动调度/今日未成功筛选仍跳过未核清助手运行结果的站点。
- 用户可在正常编辑器自行启用，或在当前配置完整成功测试后明确要求助手单独审核启用。`enabled: true` 必须是唯一 patch 字段且无 observation；准备与应用两次均须同 owner、同会话创建的当前历史身份/配置修订的完整助手 Run 及其唯一 SiteJob 均已结束、均为 `success`，Run 未请求取消、关联 run action 已完成、严格配置守卫仍有效。可选 `successful_run_id` 指定证据，省略由服务端查找。排队/运行中、跳过、单步成功、手动/其他会话运行和旧配置证据均不算；设置变更后须重新完整测试。该启用门禁仅约束助手，不改变正常编辑器或手动 API，也不使完整测试自动启用调度。
- `run_site` 的业务参数仅 `{}`，只运行当前绑定的单个已保存目的站点，经共享 executor 执行，没有任意站点、全部运行或 force。使用目的站点实际保存的凭据/Cookie，manual 凭据绑定必须就是目的站点；Cookie 模式须已有保存的 Cookie，发现浏览器人工登录不能代替它。完整解析支持全部 23 项内置功能，包括公开非秘密 `action.fill` 和逐次消费审核的四项 `post.*`，插件/插件方法/提供商仍拒绝，包括继承项。工作流完整 URL 必须为原始目标公共同源、无敏感值地址；可信观察来源不扩大完整运行导航或凭据权限。
- `post.buy_card`、`post.resign`、`post.resign_click`、`post.resign_dialog` 每次实际新派发前须 owner **逐 post 步骤**审核精确消费计划，条件启用步骤也纳入；每个步骤单独全新面板、全部批准后才启动一次保存的完整工作流，不为每个日期或内部点击再弹窗。全局自动授权、工作流权限或导入批准不能跳过。完整展示全部过去待补签日期，窗口最多 365 天，绑定时区/当天及有效工作流/策略指纹。购卡 `purchase_quantity` 为 0-365 整数，0 自动按缺口减库存补齐，仍给出最大数量；`max_price` 为正整数，显示最大总花费而非实时报价。日期/授权/检查点计划由宿主私下生成，单次批准后复查再派发。带消费计划的助手运行不自动 fallback/restart/重试 attempt；相同配置/提案重放只返回原 run ID，不再弹审核或 submit。通用点击/导航效果不总能识别，禁止用点击、填充、导航或循环绕过审核，不保证所有网页消费都被拦截。详见 [购买与补签审核](ai-assistant.md#购买与补签审核)。
- 运行守卫哈希覆盖新解析的本地/解析配置、祖先模板依赖及功能设置/策略，executor 再核对当前值；漂移以静态 `assistant_configuration_changed` 拒绝，而非执行变化后的配置。新的助手导入在新建/更新工作流时使用精确 actor `assistant`，生成的配置历史 `created_by` 为 `assistant`；新的完整运行保存 `Run.created_by: "assistant"` 及 `trigger: "assistant"`。真实人类身份仍在助手会话 owner 及关联 action owner 中保留，不在新运行的 `created_by`；会话/消息及 action 载荷加密，owner 等索引元数据并非全是密文。列表创建人显示英文 `assistant`，tooltip 为「来源：智能助手」，通知 `trigger_label` 也为英文 `assistant`，不是展示实际人类发起人。旧运行/历史不迁移；已有运行 329 仍为 `trigger: "manual"`、`created_by: "admin"`，不能称为助手来源运行。
- 同一提案导入、同一绑定修订加提案运行均幂等，重复调用返回原身份/run ID，不再 submit。提交确认丢失返回 `ok: false`、`run_submission_uncertain`，持久保留 run ID 和未知状态，不自动补投；`submitted: false` 不证明没有执行。Worker 对助手完整运行可能已产生副作用的异常/超时保留 unknown，而不是普通 fail；未知结果阻止新完整运行及配置写入/导入，不能换提案、修订、UUID 或工具重放整次运行。非 post 单步仍按当前类别授权检查，不核销完整运行门禁。当前没有完整运行审批/核销 UI，单步重试能力不适用，普通手动运行也不会自动解除未知状态。
- `get_run_results` 参数为 `{run_id, cursor: 0, limit: 50, wait_seconds: 0, snapshot_id?}`，limit 1-50、等待 0-20 秒；建议 10 或 20 秒有界等待。仅返回本 owner/会话关联运行的状态、白名单 reason/field/stage/cause、布尔结果和计数。步骤可原地更新，cursor 是安全投影相对索引；非首页须带返回的 SHA-256 `snapshot_id`，遇 `run_snapshot_changed` 从 0 重读，不混合不同投影。
- `get_run_log` 参数为 `{run_id, offset: 0, limit: 16000, snapshot_id?}`，按字节返回 `content` 页，limit 1-16000、跟随 `next_offset`，非首页也需 snapshot。它是 **curated structured diagnostic**，不是原始 artifact 日志，不回传完整站点 URL、页面正文或原始错误 dump；实际历史日志可另行要求专用 `read_artifact_log` 全文脱敏后分页读取，不要把未经处理的文件或秘密粘贴给模型。完成且已知失败时，可据安全反馈修正草稿、校验、提交、导入新修订再测，不能重跑未知结果补证据。
- 工具等待占本轮预算；本轮结束后不会自动监看任务、另起模型调用或主动回来汇报。任务仍运行时只报告 run ID 与当前状态，可去运行 UI 或下一条消息要求读取结果，不承诺完成后助手自动回复。完整规则见 [导入与完整测试](ai-assistant.md#导入与完整测试) 和 [完整运行反馈](ai-assistant.md#完整运行反馈)。

草稿校验失败时，`validate_workflow_draft` 返回顶层 `ok: false` 及最多 10 项 `diagnostics`，包含静态 `code`、`message`、安全 `path`，可带 `step_key`、`feature_type`、配置 `field` 和仅数值/长度约束的 `hint`。例如 `signal_missing` 指向 `["draft", "steps", 0, "condition"]`，策略要求但仍缺失的 `submit_selector` 以 `field_required` 指向 `["draft", "steps", 0, "config", "submit_selector"]`，不回显实际值或秘密。已知 `flow.jump` 目标含冒号会具体提示 `flow_jump_target_invalid` 及 `target_step_key`，未知错误仍静态兜底。每次只返回首个失败校验阶段的有界反馈，不保证一次列完全部错误；助手应按路径/schema 修复并迭代校验，再提交。管理端原始错误字符串、默认值及 local/resolved 预览不是模型安全输出，工具失败文字/日志也不应输出秘密或默认值。响应示例见 [草稿修复诊断](ai-assistant.md#草稿修复诊断)。

助手普通交互有 **38 个工具**，含 `clear_bound_site_cookies`、`create_template_from_site`、`get_scheduler_settings`、`update_scheduler_settings`、`cancel_run`、`list_workflow_versions`、`get_workflow_version`、`list_run_artifacts`、`read_artifact_log`、`read_artifact_image`；注册表另有接管专用 `submit_takeover_conclusion`。提示与响应校验使用 `assistant_prompt.tool_definitions()` 动态取得名称，完整清单见 [工具与限制](ai-assistant.md#工具与限制)。浏览器观察是通用 DOM 证据，不是可见登录/挑战元素白名单：扁平 `elements` 含 `node_id`、`parent_id`、`frame_id`、`tag`、`visible`、过滤后的 `attributes`，可附直接子 `text` 和选择器证明。隐藏节点保留为 `visible: false`，不代表不存在；输入值、可编辑正文、script/style 等正文及敏感属性被省略/脱敏，而不是删除所有隐藏节点。文本不聚合后代，没有特定站点/挑战的专用规则；普通隐藏文本与可见个人资料仍可能敏感。

**模板、调度与取消**
- 用户明确要求后，`create_template_from_site` 可把当前宿主绑定的已保存 `workflow_site_id` 转为模板，不接受任意来源 ID、也不是凭据 `site_id`。复制本地三集合并映射父模板，不复制站点设置/秘密或改变来源。有效且无活动/未知任务的已配置站点**不要求先有成功助手完整运行**。每次新 `operation_id` 配 name/可选 description；替换已有模板还需 `destination_template_id`、当前 `expected_revision` / `expected_history_key`，只替换父模板和完整本地三集合，保留目的名称、描述、enabled，不合并。
- 模板保存逐次显示宿主精确审核，自动授权不能跳过。冻结来源/目的快照与依赖，批准后复查、条件更新并 CAS，漂移、受保护配置、循环继承、拒绝或超时不写入。保存历史与加密 action 回执同事务提交；相同 UUID/请求只重放，不重复保存或运行。这与人工导入只填表不同，详见[从站点保存模板](ai-assistant.md#从站点保存模板)。
- 助手替换在准备及应用时比较原目的与候选的解析结构，含继承项：原分组不得删除、改名或重排，原步骤不得删除、换组或重排。已有步骤配置可更新，新分组/步骤可插入任意位置；`position` / `step_anchor` 可变，只须原项相对顺序不变。不兼容来源直接拒绝，不隐式合并。审核的完整候选是精确来源**本地**三集合及父模板，`before` 是目的原本地三集合及父模板（新建 null）；可展开候选及按 key 的前后差异，不是继承展开结果。受保护配置无法安全展示则拒绝，不用隐藏标记代替；旧审批无 `before` 明示基线不可用。人工编辑器导入行为不变。
- `get_scheduler_settings` 读全局配置、修订、来源/环境锁、时区及 next_run_at，不需站点目标。仅用户明确要求后 `update_scheduler_settings({operation_id, patch})` 精确审核 enabled/mode/cron/interval_seconds/ranges 的非空稀疏补丁，省略保留，null/未知字段拒绝；不是站点调度。任何调度环境覆盖锁定全局编辑，timezone 仅环境管理、不接受修改，单独时区环境值不锁其他字段。审核冻结配置与环境并做修订 CAS，动态 next_run_at 不计冲突绑定，成功后重算；相同 UUID/请求幂等，拒绝/超时/漂移不写入。
- `cancel_run({run_id})` 需用户明确要求及精确任务宿主确认，不限本会话创建任务。批准先提交取消，再对活动任务调用真实 executor；运行中 cancel_requested / worker_cancel_delivered 不是已停止证明，应核对 status/finished。终态只读现状，不能撤回已生效操作，也不清除未知门禁。聊天「停止」只停轮次，不取消完整任务。字段与风险见[调度与取消](ai-assistant.md#调度与取消)。

**历史资料**
- 先从 `list_sites` / `get_site_config` 的 `history_key`，或模板列表/详情的同名 UUID 定位历史身份。站点/模板列表支持名称 query 和分页；近期运行、运行摘要 jobs 也可分页，整体运行计数不变。跟随 next_offset（末尾 null），不假定有 total；实时偏移可能重叠/遗漏，应按 ID 去重并刷新。精确分页范围、导航 path 2048 / url 4096 及状态工具的 CFbox/环境模型元数据边界见[数据查询](ai-assistant.md#数据查询)。
- `list_workflow_versions({history_key, offset, limit})` / `get_workflow_version({history_key, revision})` 按历史 UUID 读当前或归档的脱敏本地/解析配置、依赖和功能快照，不恢复配置。`list_run_artifacts({run_id, job_id?, offset, limit})` 列实际历史 artifact ID/元数据，limit 1-50。普通会话可读当前管理 UI 已授权范围内的历史运行，不限会话创建；本会话限制只适用于 get_run_results/get_run_log，接管另限来源任务。
- `read_artifact_log({artifact_id, offset, limit})` 读实际历史 log 文件，原文件最多 **2 MiB**；先对全文替换已知模型/集成密钥与凭据模式，再按脱敏字符分页，limit 1-16000、默认 16000，跟随 next_offset 并核对 snapshot_sha256。不是 get_run_log 的 curated 诊断，也不是原字节分页；过滤不是通用 DLP，其他个人资料可能保留。路径只从合法数据库 artifact 关联解析，拒绝逃逸、符号链接和特殊文件，不接受任意路径。
- `read_artifact_image({artifact_id})` 需本轮 **supports_vision=true**，读 screenshot/captcha 的真实历史像素，**不遮罩**。原 PNG/JPEG 最多 2 MiB、2000 万像素，移除嵌入元数据、按比例缩至最多 **1600 × 1200** 并编码为最多 **384 KiB JPEG**，不保证清除像素秘密。用户明确要求历史资料发送后，宿主向模型追加像素并加密保存，工具/SSE 仅有元数据；不要求实时 screenshot_consent，实时撤销不撤回独立历史授权。不要把它当作当前页面、已遮罩截图或成功证明，见[历史版本与 Artifact](ai-assistant.md#历史版本与-artifact)。

**失败接管**

接管面板的「结论复用有效期」对应 `TakeoverValues.conclusion_ttl_days`，严格整数 1-30、默认 7 天。完全匹配旧结构时缺 TTL 只读补 7，缺 live_access 仍补 false，不写库、不改修订或扩权。新决定使用当前保存 TTL，按原正式结论 created_at 算 UTC 滚动年龄，复用不续期。过期后下一个合格新来源正常调查，不自动回填、重排队已有 reused 或删除记录，已有历史/冻结通知仍可读。精确边界及不变的策略 CAS/生效时间语义见[失败接管](ai-assistant.md#失败接管)及[相同失败去重](ai-assistant.md#相同失败去重)。

重启/重新部署不会因新规则扩大准入而回填旧任务。周期扫描只发现本次 API 进程创建接管管理器时或之后结束的 Run（UTC `Run.finished_at >= _scan_started_at`），仍须满足策略生效后创建等条件；启动前已开始、启动后结束的运行可以入队。已有 queued action 仍恢复处理；dispatched 若有精确已接受用户消息及有效同 owner 会话，则保留供持久证据完成恢复，否则启动回退仍按导入回执记 updated、无回执记 unknown。完成恢复不重排队或重放模型/网站动作，不改变通知网络派发不明时 unknown、不重发的规则，详见[结论与通知](ai-assistant.md#结论与通知)。历史结论去重范围和显式终态通知规划入口不变。
- 顶部「助手接管」新策略默认 enabled=false、live_access=true、mode=analysis、site_ids=[]（不选任何站点）、max_attempts=1（严格整数 1-3），整体仍默认关闭。「授权无人值守浏览与单步验证（权限保留供后续对话）」是唯一实时复选框，没有独立浏览器功能开关；勾选只改草稿，核对并保存后才生效。旧版缺 live_access 的只读兼容规则见上文；启用策略的 API values 必须显式提供这个布尔值。独立委托核对失败报告、日志、未遮罩历史图像以及实时页面/遮罩截图可能交模型和真实操作风险，不沿用助手设置默认授权；打开/刷新/保存不调模型、不启动浏览器或任务。
- ID 列表只覆盖所选且启用的站点；live 策略保存时在同一事务冻结所选站点 `history_key` 和规范 origin，按策略修订写入独立 `AppSetting` 键 `assistant.takeover.site_grants`，准入复查修订、完整 ID 集合和当前绑定。旧 live 策略缺绑定或绑定无效时 fail closed，不启动所选站点接管，须核对并重新保存；不把数字 ID 当作永久身份。null 明确覆盖**所有当前及未来启用站点**，无需预存未来站点绑定，但每个实际 action 仍冻结具体历史身份、origin、策略修订和来源任务，导航不能扩权；身份、origin 或绑定变化须重确认。
- 策略保存于 `assistant.takeover.settings`，`PUT /api/v1/assistant/takeover/settings` 需 `{expected_revision, confirm: true, values}`，CAS 防覆盖；authorizing_owner 由当前登录设置，含 authorized_at/effective_from。冲突保留草稿、不自动重试，响应不明先刷新。接管失败、错误和需要人工的任务；已推迟不接管。每次保存更新生效时间，**不回填历史任务**，只接管生效后创建、已结束且为 fail/error/waiting_human 的手动/调度任务，站点须仍启用且在授权范围；取消、unknown、中断、deferred、未完成任务和助手运行均跳过。
- 历史失败或与当前来源无关的 unknown 记录本身不阻止合格新故障入队和分析；有效 live_access 下可浏览及按类别执行支持的同源单步，auth 共用额度。当前来源自身的 unknown、中断、取消、deferred 仍不触发接管。配置保存/导入与完整运行的不确定性门禁仍有效，不自动重放历史部分消费。waiting_human 挑战可在实时授权及宿主检查通过后尝试，不保证没有副作用或所有功能可自动处理；暂不复用旧挑战分析。以 Piggo 为通用示例，只有旧失败/unknown 时仍需调查，不能当作已有结论；这不是生产站点验证或修复成功声明。
- analysis 可分析/提出校验后建议，**只是不保存配置，不代表网站只读或没有副作用**。两种模式在 live_access=true 时都允许无人值守浏览、支持视觉时的实时截图及冻结清单内最多 18 项真实同源单步，包括私有凭据登录、表单提交、签到和点击；凭据来源仍须可用，插件功能/方法/提供商拒绝。已保存车道 proxy_general/proxy_interaction 映射到 proxy_interaction，其余映射到 interaction，无自动 fallback；从首次导航起严格原始 origin，不自动信任其他来源。秘密及能力令牌不交模型或日志，DOM 输入值省略、实时输入遮罩及未知门禁不变。live_access=false 则只用来源历史证据，不浏览或单步。
- autofix 仅在失败实际派发快照仍匹配当前身份/修订/attempt/车道/配置/依赖/策略、且无活动或未知任务时，一次导入现有绑定来源站点工作流；不新建、不取消、不改凭据、站点元数据、模板或全局设置，**不自动运行修复后的完整配置**。缺失/过期快照不能用于保存，max_attempts 不是业务重试次数。自动阶段不开放 flow.jump / 四项 post.* 孤立动作、完整运行或重试审批；当前 `retry_step` 门禁仍拒绝，不应宣称该工具可用，新 `execute_step` 则按类别授权和额度检查。设置、模板、全局变更及取消仍须人工明确要求和独立宿主确认，消费完整运行每次新派发仍须逐步骤精确审核。
- 每次自动工具与导入均复查 owner、策略修订、范围和来源；关闭/修改策略撤销旧修订自动委托，不追溯撤销已授予的人工会话权限，也不撤回已发送证据、已提交修改或网站副作用。对话框显示当前 owner 最近 20 条审计并可「查看接管会话」，API `GET /assistant/takeover/actions` 仅返回当前 owner 记录。updated 只表示保存，completed_analysis 只表示有分析，不代表业务成功。完整准入/撤销见[失败接管](ai-assistant.md#失败接管)。
- 同版本同故障仅在当前准入和实际派发快照仍有效时去重：匹配 owner、站点历史 UUID/origin、完整配置指纹/修订及 v2 失败签名。签名纳入车道、失败步骤 key/功能/状态、reason/code/field/stage 等事实和空白规范化 message，去重元数据只存哈希、不存原消息/字段路径；缺稳定事实的通用错误不去重。来源须有有效 completed_analysis/updated 正式结论和类型明确的成功轮次结果，updated 另需导入回执；失败、unknown、排队、缺失/损坏结论或签名本身都不是成功标记。无关历史 unknown 不阻止有效结论复用，因为复用不派发新动作，也不解除变更安全门禁。
- 复用安全要求是：即使有失败步骤，也应同时区分完整 Run/Job 终态原因和明确 false 的结果；分析实际运行时配置若与失败派发版本不同，该分析不得因后来恢复旧配置而成为原版本的去重依据。完成状态或当前指纹相同不能单独证明历史分析来源。明确未接受的 busy/session-running/model-unavailable 发送应保留为可继续处理的排队工作，不得作为成功或抑制后续合格分析的依据；不能与发送确认不明混同。这些要求不声明新增公开字段。
- 保存站点产生新修订即不沿用旧分析；完整快照中任意字段实际改变（不仅是步骤，也含名称/备注/调度等）、祖先模板或功能 schema/默认值/策略变化同样失效。此前 updated 对应修复前失败版本，不能抑制修复后新版本分析；重新保存接管策略/切换模式本身则不是配置失效开关。命中仍新建本次审计 action：reused、same_config_same_failure、attempts=0，只关联原始有效 action 和仍存在的旧会话，不新调模型、开浏览器或修复，不复活已删聊天。UI 标「相同失败，复用已有分析」和「历史结论（复用，非本次重新分析）」；发送原任务通知前本地复查来源结论，将历史结论及「当前未重新分析/未修复」直接写入该站点消息，原失败状态保留，不显示新复查文案或另发新复查通知。与每日聊天路由不同，详见[相同失败去重](ai-assistant.md#相同失败去重)。
- 同一 owner、同一站点历史 UUID、同一本地日复用一个每日聊天；日期取来源 SiteJob.finished_at 按站点时区换算，不取分析时间或星期几。跨日最多带入 3 条以往正式结论及有界字段级修复差异，排除当前日，不能据此授权或重做操作。自动轮次结束清除 action 委托，但有效 live_access 浏览、执行、可用凭据、截图权限保留在该会话供 owner 继续人工聊天，不借用全局默认授权。人工后续 workflow_consent 无论自动 analysis/autofix 都保留为 true；不放开自动 analysis 保存或自动完整运行，人工明确要求后才走普通导入/运行流程，消费仍需新的审核。无实时授权则通过正常交互取得能力；仅询问能力不会新授权，身份/origin/绑定变化须重确认。
- 自动接管在轮次结束清理自己的页面和租约后才置为 idle，成功、错误或取消均如此，不保留到 15 分钟到期；聊天历史和有效人工权限保留。用户后续可复用仍有效的权限要求 `browser_open` 重开新页面，无需重复授权，不保证恢复原页面/DOM/临时状态，也无需先手动完整运行才能观察、截图或单步验证。人工助手浏览器仍从准入/创建起固定 15 分钟，消息不续租，不是最后消息后的闲置计时；身份/origin/绑定变化须重确认。人工非 post 重试按当前类别策略，未知完整运行无核销 UI、不能重跑补证据。
- 自动接管的 `browser_open` 使用 `wait_for_lane: true`，非阻塞返回并轮询 `queued/opening/ready`，每车道 FIFO、最长 **1200 秒（20 分钟）**；实际排队不占活动预算，同一工具调用内 await 一次，等待期间不额外调 LLM。超时/取消/策略撤销只清理自己的排队项、页面及租约，不抢占人工浏览器或 viewer；来源活动任务与拾取器共享执行信号量。两车道队列独立不代表并行接管，当前主自动消费者仍串行，不同时运行两个自动浏览接管。另有可配置 `idle_stop_seconds` 默认 **300 秒**，无 lease/viewer 后才开始车道空闲关闭，不等同助手 TTL，也不参与结果通知判断，见[排队与所有权](ai-assistant.md#排队与所有权)。
- 接管专用 `submit_takeover_conclusion` 提交最多 240 字符纯文本加密候选；宿主核对精确 action/request 和确定结果后提升，完整解释仍可保留在聊天。任务结束立即发送原任务通知，不等待接管或额外调用模型；注册时仅本地规划符合 fail/error/waiting_human 准入的 action（deferred 排除）并做去重。需要新模型复查的站点在原始脱敏消息前添加「助手复查中，结果稍后发出。原任务结果：」，复用则直接包含有效历史结论，不发第二条调查通知。事件、渲染正文和通道目标冻结加密保存为 ready；原通知自定义布局、数据库原消息、任务状态、统计和筛选不变，waiting_human 仍为 waiting_human，不改为 success。实际接管完成且有有效简短 completed_analysis/updated 结论时另发独立纯文本调查简报，不使用用户任务布局，HTTP 事件为 `assistant.investigation`；仅发送给已启用且该通道 `notify_assistant=true`（默认 true）的邮件/HTTP 通道，不依赖原任务通知的成功/手动筛选。failed、unknown、revoked 或没有有效结论时不发；updated 只表示配置已保存、未重新运行验证。完成/正式结论与独立 `assistant_takeover_notices` 账本在同一事务提交；先完成原任务通知发送尝试，再派发调查通知，不保证送达成功或收件顺序。独立账本按 action ID 唯一登记，在网络前认领、最多一次尝试，重启不明派发记 unknown、不重发，不保证恰好一次送达。旧版等待意图保留冻结事件/消息并转为 ready 释放一次，不追补新复查标记，不回填历史任务，见[运行通知](run-notifications.md)。
- 数据在 `DATABASE_URL` 配置数据库，Compose 默认 SQLite `/app/data/siteflow.db`（`siteflow_data` 卷）。接管审计、加密派发快照、每日路由、加密候选/正式结论分别在 `assistant_takeover_actions`、`assistant_job_config_snapshots`、`assistant_takeover_daily_conversations`、`assistant_takeover_conclusion_candidates`、`assistant_takeover_conclusions`，不是模型自带记忆。正式结论/审计不随聊天删除；数据库备份还需单独安全保存 `SITEFLOW_MASTER_KEY`，见[记录存储](ai-assistant.md#记录存储)。
- `assistant_takeover_analysis_provenance` 保存分析实际观察配置与来源派发配置的一致性证据；缺失时不能作为有效历史分析复用，须与结论、审计和去重记录一起备份。
- 备份须同时包含 `AppSetting` 的 `assistant.takeover.settings`（规范 owner、修订、授权/生效时间）和 `assistant.takeover.site_grants`（同修订所选站点身份/origin）；owner、规范每日会话路由及绑定元数据不全是密文。新记录表由 `create_all()` 创建，live_access 和绑定使用现有 JSON/设置记录，不新增旧表列，`create_all()` 不迁移历史开发版列。首次 Worker open 已携带严格同源约束，在首次导航前生效，不是先打开再限制。

去重签名及直接来源链接另存 `assistant_takeover_failure_signatures` / `assistant_takeover_dedup_links`，与结论/审计及 `assistant_takeover_notices` 一起备份，不依赖聊天或模型记忆。性能修正将接管启动恢复、reconcile 和 process_one 的选择、运行时预检、会话创建、认领、发送失败处理、完成等阶段通过 `_phase` 放入线程；各数据库 helper 自行管理 session，阶段间不传 ORM 对象，模型发送/等待/唤醒仍在事件循环。executor 运行准备/终态、接管策略保存、助手 SSE 认证/详情/编码也移出事件循环；未变化的 running 快照只发 heartbeat。工具 JSON 解析缓存限当前选择，完整格式化/渲染等展开才做，原文、提案、审批/停止和安全检查不删减。通知规划、reconcile、选择和认领分别创建阶段事实缓存，限同一事务/session/策略视图，不跨 await、提交或授权/配置变化，认领重新复查来源和策略。不保证任何负载下绝不卡顿，详见[性能与边界](ai-assistant.md#性能与边界)。

`browser_observe` 默认从 offset 0 新采集，最多扫描 5000 节点、深度 64、2 MiB，每浏览器缓存最多 4 份。普通每页最多 100 节点、完整 JSON 32 KiB，可能不足 100；按实际返回的 `next_offset` 和同一 `frame_id` 翻页，核对 `snapshot_id`，不要固定加 100。`total` 是捕获数量，`truncated` 表示采集/元数据不完整，与有无下一页不同。`browser_inspect` 用实际 `snapshot_id` / `node_id` 分页包含根的不可变 `captured_subtree`，**不能恢复有界扫描外的节点**，不是实时深挖；过期/淘汰/导航后应重新 observe，不猜引用。具体分页示例见 [DOM 分页与选择器核验](assistant-discovery.md#dom-分页与选择器核验)。

先看 `frames` 的 `readable` 和明确的不可读 `reason`，只读取同源或已批准观察来源且通过公共 URL/DNS 检查的 frame，使用实际返回的 `frame_id`。frame 元数据也有界并以 `frames_truncated` 标记；不可读或未列出的 frame 不能当作表单/挑战不存在。`browser_check_selector` 接收 `selector` 和可选 `frame_id`，以固定只读 CSS 查询实时返回含隐藏节点的 `match_count`、单列的 `visible_count` 及有限样本（计数最多 10000、样本最多 10）；不点击、填写或提交，不授权 iframe 执行。只支持 CSS 和显式 open-shadow ` >>> `，不支持 closed shadow root、任意 Playwright 引擎或自动穿透 iframe。

登录按钮没有 ID 也不必猜选择器：实际观察若给出 `selector_source: "dom_path"`、`selector_matches: 1`，说明该 selector 在采集时唯一定位了该节点。使用前必须在对应 frame 做 `browser_check_selector`，核对匹配数、可见数均为 1 且样本身份正确，再用于人工审核的配置或授权单步；不能从 id/name 重建、猜 fallback，实时核验也可能随后过时。DOM 不是截图，不能只凭 DOM 结果宣称已看到像素。

**截图与恢复**
- 以下类别重试只适用于单步，不解除配置写入或 `run_site` 的未知完整运行门禁；后者当前没有批准/核销 UI，须人工核验。验证码不封锁后续 DOM/选择器/独立授权截图或已授权单步；历史未知不一概阻止当前非 post 单步，导航、刷新或重开不清除未知来源事实。
- 模型 `browser_screenshot` 缺少独立目标截图权限且未明确开启全局截图默认值时，宿主自动请求图像授权，批准即恢复原调用，无需预先打开设置。它独立于统一执行/工作流权限、默认 false，还要求本轮 `supports_vision=true`。已有权限与可用浏览器时，空闲可点「截图预览」；UI 预览不要求视觉模型、不调用模型，仅当前页面内存显示，关闭即清除，不持久化预览。
- 图像为当前 viewport 的 JPEG，最多 **1600 × 1200、384 KiB**，不是全页/PNG/录像。主页面与可读同源 frame 内遮罩表单输入控件（非按钮/复选框/单选框 input、textarea、select、可编辑区域），其余 frame 保守地整体遮罩，包括已获观察信任的跨源 frame；不是遮住整个 form。API 校验并重编码像素、移除 EXIF 等嵌入元数据。可见个人资料、账户文字或其他秘密仍可能保留，页面反映的图片验证码答案可以保留；遮罩不是通用 DLP，也不保证全部秘密像素脱敏。
- 模型实时截图的图像及规范多模态消息加密保存；工具结果/SSE 只有图像 ID、owner 图片 URL、尺寸等元数据，没有 base64 像素。宿主在整批工具结果后追加独立 user 图像证据，不把图片塞入工具文本、摘要或摘录。撤销实时同意或目标修订变化后，旧实时截图像素从后续模型输入省略，关闭整理也不绕过；独立历史 artifact 图像授权不因此撤销。不删除审计，owner 的历史图片 GET 仍可用，已发给模型的图片无法撤回。UI 工具卡不自动加载历史图像。
- 「刷新会话」只读聊天状态；「刷新网页」确认后，或模型 `browser_refresh`，对当前归属页面去掉片段、保留查询的地址发起**新的 GET**，不是 `reload()`，绝不重提 POST。它清除旧 DOM 缓存但保留不确定性与账本。GET 也可能有副作用，截图转圈不能触发自动刷新；截图不能证明原操作成功、失败或没有效果，可以据此询问用户是否确认刷新/重试，不能据图自动行动。
- 普通会话 `retry_step` 只传原 `operation_id`（及公共 title），宿主自动签发单次精确存储步骤能力，以新 UUID 执行，不弹 UI 审批；auth 重试另计一次共享额度。不改写原步骤、不从聊天或模型参数提供授权；初始授权、原 origin、站点修订、浏览器及凭据绑定和幂等校验仍有效。自动接管仍拒绝 `retry_step`，新 `execute_step` 的类别许可不意味着开放该工具。
- 旧运行中审批 API 仍保留兼容，最多等待 **180 秒**，实际用户等待暂停活动预算，执行仍计入；拒绝、超时、取消或失效不执行，重启不自动续跑。可选旧空闲「允许重试一次」仍提供 **5 分钟、浏览器绑定、单次使用**预授权，入口本身不执行。人工仍可使用这些旧入口，但它们不是当前非 post 重试的必需前提。
- 原始 unknown 历史、账本和受保护事实不抹除；重试成功不证明原操作失败，无关成功不核销旧结果。当前类别策略与宿主关联 resolution 优先于旧 `no_retry` / `requires_host_approval` 文字，不能据旧文字要求所有重试审批。类别许可不保证无网站副作用，真实点击仍可能写网站；配置保存/导入与完整运行门禁不变。完整语义见 [截图与恢复](ai-assistant.md#截图与恢复)。

上述 UI 操作走 owner/CSRF 保护的 `POST /api/v1/assistant/sessions/{uuid}/browser/screenshot`、`POST .../browser/refresh`（空对象），运行中重试审批走 `POST .../retry-approvals/{approval_id}/decision`（`{decision: "approve"}` 或 `{decision: "deny"}`）；可选旧版空闲预授权走 `POST .../retry-authorizations`（`{operation_id, confirmed: true, request_id}`）。通用交互走 `POST .../interactions/{interaction_id}/response`，批准/拒绝带 `decision`，选择批准另带 `selections`，输入批准另带 `values`；相同响应幂等，冲突拒绝，只有原等待调用复查绑定后才应用授权。历史图像通过登录 owner 专用 `GET /api/v1/assistant/sessions/{uuid}/images/{image_id}` 从加密记录解密返回 JPEG，响应不缓存。UI 不直接请求 Worker，也不把内部令牌或重试密钥交给模型。

观察结果的 `url` / `href` 保留公开查询与片段的原始编码、参数顺序、重复项与空值，不统一截断或重编码。`token`、`password`、`session`、`code`、`state`、`sig` 等敏感键仅擦除值为 `[REDACTED]`，用 `url_redacted`、`redacted_parameters` 或 `href_redacted`、`href_redacted_parameters` 标记；普通 `return_to` 和无秘密的嵌套 URL 保留，嵌套敏感值单独擦除。脱敏 URL 只作证据，不能当作工作配置或执行地址，也不要在聊天中补写秘密。

未批准的公共跨源导航或重定向返回 `browser_trust_required`，包含脱敏后的完整 `source_url`、`target_url`、对应的 `source_url_redacted` / `target_url_redacted`、`redacted_parameters`、`target_origin` 和建议的 `trusted_url_pattern`。工具卡片展示完整地址、待核对来源及脱敏警告。用户明确要求变更观察来源后，助手才可用 `update_site_config` 的 `observation.trusted_origins` 请求审核完整来源列表，不再推荐旧 purpose 或打开目标设置。用户批准后恢复原调用、替换列表、更新目标修订并释放旧浏览器；确认本身不执行、导航或重试，模型可同轮安全重开/导航，无需另发消息。Worker 仍校验公共 DNS。添加来源不允许向额外源发送凭据或执行单步，也不修改站点已保存的可信网址。

开启 `auto_title` 后，未锁定会话只在前 3 条用户消息对应的成功主轮次后，发起独立、无工具的轻量标题调用，复用同一模型及本轮 Token 策略；最多 10 秒且计入配置的总预算（默认 180 秒）。失败/取消或关闭自动命名期间的用户消息仍消耗前三条窗口，标题失败保留原名、不重试。空闲时「重命名」会永久停止自动更新；关闭/重开自动标题或恢复默认不会解除人工标题锁。旧会话缺少标题控制字段时按锁定处理，字段保存在现有加密载荷中，无新增列迁移。

切换页面或断线不停止后台轮次，要停止助手请明确点「停止」；已提交的完整任务需通过独立审核的 `cancel_run` 或运行 UI 检查/取消，停止聊天不撤回任务或已生效操作。页面只通过 SSE 接收完整状态快照，不是模型逐 token 输出，断线重连不自动重发消息。左侧会话列表每页默认/最多 100 个，可点「加载更多会话」继续；`GET /api/v1/assistant/sessions` 支持 offset>=0（默认 0）、limit 1-100（默认 100），返回 offset/limit/next_offset（末尾 null）和 truncated，无 total 保证。按 updated_at/id 降序的实时偏移可能重叠/遗漏，UI 按 ID 去重，仍应刷新核对。详情/SSE 仍只显示最新 200 条消息，**这是读取窗口，不会据此删除其余数据库记录**；会话分页不等于旧消息分页，当前无通用旧消息分页 UI。开启自动整理时模型可使用「摘要 + 边界后历史」，关闭时从原始历史重建，仍受请求大小限制。列表/详情的「较早上下文已整理，完整记录仍保留」标记表示有已保存摘要，可查看上下文修订号，不是 Token 使用率，也不证明关闭整理时仍在使用摘要。

详情/SSE 可选携带加密持久化的 `usage`，未记录过调用时可不显示用量区。标题旁的百分比及「上下文与累计用量」当前读数是最近有效 `conversation` 报告的 **`prompt_tokens + completion_tokens`**，除以该请求的 `context_max_tokens` 预算快照；不是累计值或上游 `total_tokens`，摘要/标题不覆盖当前读数。prompt 包含当次历史、系统提示及工具定义，completion 已计入当次答案；后续工具结果及未来输入仍需下一次真实报告，不是实时上下文测量。

缺少有效 prompt/completion 或预算时跳过本次占用更新，保留整份最后有效读数及原预算/修订，设置 `last_context_usage_missing: true`；前端明确标为最后已知、最近请求未上报，不当作最新值，从未有有效读数则显示 `--`。下一次有效对话报告更新读数并清除此标记；缺失报告仍进入明细和累计已知值。整理或目标/上下文修订变化则使当前读数失效，显示 `--` 等待新报告，直到下一次匹配当前修订的真实对话报告才恢复，不能用整理估算声称已测得占用下降。旧版只有 prompt、没有预算分母的记录不能重解释为新百分比。完整口径见 [模型用量](ai-assistant.md#模型用量)。

展开用量可看最近 **100 次**对话、摘要、标题模型调用及会话生命周期累计已知值；淘汰明细不清零累计，也不回填旧版未记录的调用。后端读取顶层 `usage` 中的 `prompt_tokens`（输入）、`completion_tokens`（实际生成输出）、`total_tokens`（上游总计）、`prompt_tokens_details.cached_tokens`（缓存命中）和 `completion_tokens_details.reasoning_tokens`（推理计数）。缓存字段缺失/无效才回退 DeepSeek `prompt_cache_hit_tokens`，两者不相加；缓存是输入子集、推理是输出子集，不能再加入总计重复计算。缺失/无效计数为 null，明细显示 `--`（未返回），不估算，也不以输入加输出补上游 total；当前占用可使用有效 prompt + completion，但累计 total 仍不补算。累计只加已知值，部分调用缺输入/输出/总计时会提示，不能把累计当作当前上下文大小或完整账单。

每次实际尝试发送 HTTP 请求计一次，包含 HTTP 错误、网络失败、超时和取消；无法取得安全用量时计数未知，本地序列化/请求头/构建或大小检查失败不计请求数。读取、刷新和幂等重复 `request_id` 不新增调用。账本仅保存允许的数字、调用 ID、类型和时间，不保存提供商原始响应或推理正文，不发给模型，不提供费用计算。输入上下文按每次请求计，输出上限仍由共享模型设置及助手 `max_tokens` 覆盖控制，上限不是实际输出量。完整口径见 [模型用量](ai-assistant.md#模型用量)。

默认开启 `auto_compact`：有旧记录可整理且记录超过 **40 条**，或旧历史本地估算超过 `context_max_tokens × 0.6` 时尝试摘要，默认阈值为 **38400 估算 Token**；摘要输入分块最多 `min(20000, context_max_tokens × 0.6)` 估算 Token。保护最后 **2 条真实用户消息**及近期记录，另行保留结果不明操作的禁止重试安全事实。每轮最多 **2 次**无工具摘要模型调用，每次最多 **12 秒**，均占用配置的总预算（默认 **180 秒**），沿用全局模型连接、秘密检查和本轮助手 `max_tokens` 策略，不另设隐藏输出 Token 上限。摘要、消息边界及目标/上下文修订信息加密持久化并可复用；改目标使旧摘要失效，但不清空原始聊天、执行 UUID 账本或结果不明安全记录。摘要有损且不构成授权，无法保证所有细节都保留，重要结果仍需核对。

开启整理时，工具轮次以 `context_max_tokens × 0.6`（默认 **38400 估算 Token**）为软水位整理整批调用/结果，保留调用 ID、配对、工具计数、最近用户请求和安全记录；最后一批尽量原样保留，必要时也可确定性缩减正文，不重放执行。摘要失败通常回退确定性摘录而继续，不代表所有情况都能完成：受保护内容过大、取消、安全边界及总超时仍可能终止。发送前估算包含系统提示、消息框架、工具定义及图像标记，ASCII 约按 `ceil(chars / 3)`、非 ASCII 按 UTF-8 字节保守计数，图像按低细节标记估算而非 base64 长度；**不是提供商精确分词，也不作为真实用量写入账本**。

`[context_limit]` 是本地估算/保护预算提示；`context_max_tokens` 默认 **64000**、范围 **16000-1000000**，与输出上限 `max_tokens` 不同，也不保证上游容量。线协议上限独立有效：整个序列化请求仍固定 **1536 KiB**、主响应 **256 KiB**、工具参数/结果 **64/128 KiB**，DOM/执行/截图各自限制不变；base64 图像仍占传输字节，不能截断 data URL。调高 Token 预算不能绕过字节边界，即使本地检查通过，上游仍可能因分词、图像、输出预算或自身上下文窗口拒绝。

关闭 `auto_compact` 后忽略已有摘要和边界，从保留的原始历史重建输入；不再生成新摘要，跳过轮次开始及工具轮次中的自动适配/缩减，也禁用旧工具结果的有损正文投影。**已有摘要、边界、修订和原始记录不会因此被删除或改写**，重新开启后可按有效性规则复用。安全包装、禁止重试事实和中断调用的静态失败配对修复仍保留；超过本地估算 Token 预算就返回 `[context_limit]`，线协议字节上限另行检查，不会暗中摘要、裁剪、改写历史或重放工具。

每次无状态请求都发送一份代码维护的助手系统提示和一份宿主目标系统消息，不把它们重复追加保存到聊天历史。新记录保存允许字段的规范模型消息，包含原始调用 ID、规范参数及结果，不保存/重发提供商独立推理字段。设置、目标/提示和工具定义不变、未实际压缩且无需中断修复时，后续请求的 `messages` 保持前次精确前缀，只追加新消息；开启整理但低于阈值也保持稳定。实际压缩必然改变相关前缀。旧版记录按安全包装兼容读取，未保存过的原始调用 ID 无法靠摘要迁移还原，不承诺旧历史精确重建。稳定前缀不保证提供商缓存命中，仍取决于模型路由、缓存有效期、请求头和提示/工具规范化；离线/mock 测试不是完整真实网关流量验证。详见 [稳定请求历史](ai-assistant.md#稳定请求历史)。

可明确要求聚焦某个 frame、selector 或已捕获子树，并降低 observe/inspect 的 `limit`，避免反复读取整页。细节被压缩时，可请助手用 `get_tool_result` 按本会话的工具 `message_id` 读取原始结果：`offset` 默认 0，`limit` 为 1-10000、默认 10000，按字符分页，跟随 `next_offset`；单页可能只是 JSON 片段。它只读保存的正文，不执行、不重放、不读取当前页面，也不另启专用模型调用；正常后续工具对话仍计入本轮预算。历史 DOM 是旧快照，不是实时状态，仍须重新观察确认，不能为补细节重复登录或签到。系统不会为每次提问自动另加一次全量历史重读的模型调用。schema 缓存减少本地 CPU 开销，不等于免除仍发送给模型的输入 Token；实际统计取自后端上报值，不做费用估算。完整边界见 [上下文整理](ai-assistant.md#上下文整理)，聚焦读取示例见 [证据发现指南](assistant-discovery.md#聚焦读取与历史结果)。

人工助手浏览器从准入/创建起固定最多 15 分钟，消息不续租，过期需重开新页面；自动接管结束即释放自己的页面和租约，不等 TTL，也不保证后续恢复原 DOM。跨源观察须用户确认精确可信来源，不能由模型自动扩权。目标和导航支持完整公共 URL，但拒绝 URL 用户名/密码、非公共目的地、控制字符及反斜线等危险输入。只有授权的非只读单步活动期间 `writes_authorized` 才开放原始同源 POST，可到该 origin 任意合规路径，不限某个 form action；`flow.open`、`action.navigate`、`action.wait` 从不开放 POST，PUT/DELETE 也不开放。结束后关闭 POST 并保留原始同源限制，跨源 POST 即使指向可信观察源也拒绝。前端不直接调用 Worker `/execute`。

自动认证仍要求唯一可见的原始节点、同一个原始 form、可编辑的 `input[type=password]`（用户名为 text/email）及当前窗口的同源 action/formaction；反复核对身份，拒绝节点替换或跨表单。不要求 form 声明 POST，也没有逐表单 POST action 端点审批：隐式/显式 GET 表单可由页面原有 JS 阻止默认提交，再 fetch POST 到原始同源其他路径。普通查询如 `/api/auth/login?redirect=%2F` 保持编码；任何请求 URL 含已知秘密（包括编码/嵌套编码）仍阻止，原生 GET 不能把凭据送入 URL。这是通用策略，不是网站专用补丁或开放任意 JS。

运行时 `diagnostics.blocked_requests` 最多 5 项，只含安全 `code`、HTTP `method`、投影 `url` 及脱敏标记，不含 POST body、请求头、凭据、浏览器令牌或重试授权密钥；普通查询可保留，秘密值擦除或整个地址为 `[redacted]`。旧 `browser_credential_endpoint_not_approved` 是端点诊断，不代表缺 site ID 或 Bitwarden 未配置。真实 JS/Chromium 本地 fixtures 验证同源 JS/native POST、查询保留、拒绝边界及截图/刷新，但**不等于已验证实际 Fengchao 登录**或端到端业务成功。

浏览器失败时按工具返回的安全 `code`、`lane_key`、`reason` 排查：`browser_dns_denied` 为 DNS/公共地址检查，**不证明需要代理**；`browser_url_denied` / `browser_redirect_denied` 为 URL/重定向边界，`browser_lane_busy` / `browser_lane_unavailable` 为所选交互车道占用或不可用，不应猜测为通用车道停止。读取 DNS/策略失败若返回 `page_retained: true`，表示没有证据但页面保留，可排查后再读，不代表登录失败；含已知秘密的当前 URL 拒绝仍会关闭会话。此前生产环境两次打开返回 403，根因未确认，没有证据归因于 `general`，也不能声称已完整修复；缺少具体原因时应说明未知，不粘贴原始异常或凭据。

打开/轮询成功 `ready` 不保证页面在后续异步拦截中仍存活。`browser_response_interception_failed` 保留安全阶段 `response_event`、`continue_response` 或 `fail_request`，仍 fail closed 清理，不自动重试或放宽请求策略。关闭后的有界 tombstone 先验令牌：正确令牌可取得已知原因或 410 `browser_closed`，错误令牌仍只获通用 404；API 将 Worker 404 映射为 `browser_session_unavailable`，不再笼统归为 `browser_worker_error`。Cookie generation 握手/私有导入失败也保留静态原因。来源任务认证选择器失败与后续实时浏览器失败应分开说明；精确生产异常未记录时，不能断言 CDP 不支持、需要代理或 URL 有错，观察不可用也不能排除验证码/站点问题。完整隐私与生命周期边界见[生命周期诊断](ai-assistant.md#生命周期诊断)，结论/通知边界见[运行通知](run-notifications.md#output-language)。

不要发送密码、Cookie、令牌或 TOTP 秘密；可见个人资料仍可能进入模型。浏览器限制不是完整网络沙箱，仍有 DNS rebinding、service worker、弹窗首请求等残余风险，建议配置浏览器/代理出站策略；代理车道也要求 Worker 本地 DNS 可解析。**GET 导航也可能签到或触发其他副作用**，观察授权不是任意路径的执行许可。操作、API、权限和限制见 [智能助手](ai-assistant.md)。

可参考 [NexusPHP 独立示例](examples/nexusphp-assistant-workflow.json) 和 [证据发现指南](assistant-discovery.md)：示例来自 `NexusPHP站点登录签到` 及父模板 `NexusPHP站点登录` 的只读脱敏改编，未修改在线模板，不是实时验证结果；默认禁用，购买与补签步骤完全排除。

### AI 辅助配置

站点配置页已移除独立「AI 生成配置」按钮及生成/应用对话框。AI 辅助配置请使用菜单「智能助手」，按[助手说明](ai-assistant.md)确认目标与相应权限后生成、审核提案；导入和完整测试仍需独立授权。站点的手动新建、编辑、复制配置及模板继承不变。

此次仅移除独立前端 UI；`/api/v1/config-ai/generate`、只读发现接口、共享生成协议与助手使用的模型设置仍保留。后端接口和限制见 [AI 配置协议](config-ai.md)。

### 密码验证

已登录后仍要求再次输入账户密码的页面，可添加认证分类下的“密码验证”（`auth.password_verify`）步骤。它从站点当前的账户凭据来源（手动账户、Bitwarden 或凭据插件）获取密码，只填写密码框并点击验证按钮，不填写用户名，也不需要在步骤配置中保存明文密码。同一工作流可添加多个密码验证步骤。

配置“密码选择器”“提交按钮选择器”，并建议填写验证通过后才出现的“成功元素选择器”；选择器均支持有序候选。成功元素留空时只报告已提交，不证明页面已经验证通过。此步骤沿用表单登录的同源和可信网址检查，不会自动扩大跨域凭据授权。

### 跨域登录与可信网址

站点编辑器的「备注」上方可添加可信 URL 正则数组。默认空数组，仍仅允许在站点同源页面读取和填写登录凭据/TOTP。跨域 SSO 必须显式授权，不能仅凭导航步骤自动信任。

例如基础地址为 `https://www.natfrp.com`，需要授权 `https://openid.13a.com/login` 及其查询参数时，添加：

```text
^https://openid\.13a\.com/login(?:[/?#].*)?$
```

每条 Python `regex` 正则对浏览器完整 URL（含路径、查询和片段）进行全匹配，任意一条匹配即可；最多 20 条，每条 1024 字符，匹配限时 25ms。请根据实际登录路径收窄规则，域名的 `.` 应转义为 `\.`，不要使用 `.*` 信任所有网址。只允许合法 HTTP(S) URL，URL 中的用户名/密码无论匹配与否均拒绝。

这是敏感凭据授权，不是普通导航白名单。配置仅对本站点的内置登录与 2FA 生效，不扩大插件浏览器代理权限，不自动同步跨域 Cookie，也不改变 Bitwarden 的凭据匹配方式。复制或导入站点时会带上规则，使用前应逐条审核。清空数组可撤销额外授权，未匹配时仍提示 `Secret origin denied`。

这里的站点 `trusted_urls` 与智能助手目标中的 `trusted_origins` 是两种独立授权。助手额外 origin 须经独立宿主交互确认，仅用于观察与导航，单步执行及凭据仍限原始目标源；跨源提示的 `trusted_url_pattern` 仅供审核，不会自动写入站点。助手完整运行的配置 URL 也不因观察信任而开放额外 origin。若正常人工配置的工作流确需跨源凭据授权，应另行核对实际登录 URL、尽量收窄规则并在站点编辑器显式保存。

需要 2FA 时，在对应步骤选择提供商，填写 **2FA 服务名**；同服务有多个账户时再填写 **2FA 用户名**。无论使用内置 2FAuth 还是插件，服务名都不能为空。

### 验证与签到

根据站点实际页面添加功能，不必把所有验证方式都开启：

- 图形验证码可选择 ddddocr、视觉模型、NexusPHP GD 5 或已批准插件方法；按验证码填写字符集与长度。置信度阈值仅适用于 ddddocr。
- 识别失败时可配置刷新或重新开始，并限制重试次数。视觉模型与 GD 5 不会自动退回 ddddocr。
- Turnstile 需要 CFbox；ALTCHA 使用独立验证功能。成功组件仍可能显示在页面，不必等待它消失。
- 通过按钮、导航、iframe 签到或 UNIT3D Claim 等步骤完成操作，再配置明确的成功信号和结果输出。
- 验证步骤成功不代表站点服务端一定接受提交。出现 `Captcha verification failed` 等提示时，检查提交后的截图和日志，不要无限重试。

### 补签与购买

站点启用「支持补签」并设置最大天数后，使用「断签」信号判断是否需要执行补签步骤。购卡的「购买数量」为 0 时，按待补签天数减去现有卡数自动补齐；大于 0 时固定购买该数量，即使没有待补签日期也会购买。固定购买仍受步骤执行条件约束，若条件要求「断签」为真，无断签时仍会跳过。

购卡使用页面点击，不再构造购买 API 请求。选择表格、网格卡片或自定义布局，通过商品标题和容器定位商品；表格可按价格列索引读取，网格及自定义布局必须配置商品内的价格选择器，自定义布局还需要商品选择器。

「购买点击项」仅支持添加和删除，按显示顺序执行，没有上下移动或拖拽。每项可选在「商品内」或「当前页面」查找，并配置多个候选选择器；每项只点击首个可见、启用且可用的目标，发起点击后不再尝试其他候选。HTML 确认弹窗可用后续页面点击项处理；原生浏览器弹窗会被拒绝并停止，需人工检查。

可选配置「购买数量输入框候选」（`quantity_selectors`），选择器在当前唯一商品内查找。留空时逐张购买；配置后，一次填写本轮可购买数量，再执行点击列表。每批数量取目标剩余数量、余额可负担数量及输入框 `max` 的最小值，按整数 `min/step` 向下取合法值，不向上凑数。输入框限制非法、不可编辑、实际值被页面改写或报价失效时停止；价格选择器必须读取单张价格，不是填写数量后显示的总价。若单次上限小于目标，分批完成并逐批核验。

每轮点击后，必须确认补签卡数量恰好增加本轮填写的 N 张才记录成功，未配置数量框时 N 为 1。例如购买前 3 张、本轮输入 5，则期望库存为 8 张。可配置卡数选择器、正则、独立库存地址和验证等待时间；库存地址必须与商店同源，配置前确认访问该地址不会额外签到或消费。在验证等待时间内，旧卡数、暂时读不到、数量不一致或同源页面加载异常会继续复核，不立即报错；页面加载稳定且卡数一致时提前成功，直到等待期限仍未确认才停止，不重复付款。跨源、原生弹窗、取消或外层步骤超时仍可提前停止。日志记录本轮数量、检查次数、实际耗时和最后卡数。已发起购卡的任务不自动重启、转车道重跑或回跳重复执行该购卡步骤。

新字段保存在现有步骤配置 JSON 中，无新表或旧数据搬迁。旧 `option_selector`、`exchange_action`、`submit_value` 字段保留但隐藏并忽略。旧卡片布局配置升级后应选择正确布局并补齐价格选择器，不能依赖旧 API 参数购买。

首次读取库存时，优先进入配置的「补签卡库存地址」；为空才使用商店页。页面到达 `domcontentloaded` 后，按「购买验证等待秒数」在原页持续等待数量元素出现，再用数量正则的第一捕获组提取整数；不是刚进页就只匹配一次。轮次间同样会等待库存读数恢复一致。日志记录访问路径（省略查询参数）、读取来源和结果。正则匹配的是可见文本而非 HTML，例如文本为「你目前拥有补签卡 3 张」时，可使用 `补签卡\s*(\d+)\s*张`；默认正则要求卡名后带冒号，不一定适合所有站点。

动态页面显示的初始 `0` 可能只是占位值。库存读取前后会检查页面是否仍有可见的 `[aria-busy="true"]`、`.loading` 或 `.spinner`，加载未完成时不接受该数值；商店也在同一等待期限内轮询商品、价格和余额，避免 SPA 尚未渲染商品就失败。导航保留完整 URL，日志仅隐藏查询参数，不会删除 `?tab=shop` 等导航参数。

购买步骤可能实际消耗积分或余额。先核对价格、购买限制与条件，不要在不了解页面行为时对正式账户反复测试。

### 页面点击补签

自定义日历可使用独立的「页面点击补签」（`post.resign_click`），原有「补签」仍保留 NexusPHP FullCalendar/AJAX 方式，不自动切换。启用站点「支持补签」并设置历史范围后，新步骤复用待补签日期；首次没有历史执行记录时不会自行猜测漏签日期。

默认选择器针对已检查的 `/calendar` 自定义日历：

| 配置 | 默认值 |
| --- | --- |
| 日历地址 | `{base_url}/calendar` |
| 月份标题 | `.cal-board > .cal-water` |
| 上一月 / 下一月 | `.cal-arr[aria-label="上一月"]` / `.cal-arr[aria-label="下一月"]` |
| 目标日期 | `.cal-grid > button.cal-cell:not(.mute):has(.cal-num:text-is("{day}"))` |
| 目标日期选中 | `.cal-grid > button.cal-cell.on:not(.mute):has(.cal-num:text-is("{day}"))` |
| 目标日期完成 | `.cal-grid > button.cal-cell:not(.mute):has(.cal-num:text-is("{day}")) .cal-badge.att` |
| 补签按钮 | `.cal-att button.cal-att-pill.act` |
| 卡数文本 | `.cal-help` |
| 卡数正则 | `补签卡（当前\s*(\d+)\s*张` |

这些字段使用候选数组。日期模板支持 `{date}`（ISO 完整日期）、`{day}`、`{month}`、`{year}`；拾取后要保留日期占位符，不要把具体某一天写死。月份标题必须能读出数字年月；不要选包含所有年份下拉选项的整个工具栏。`.mute` 用于排除相邻月日期，其他站点需要按实际结构配置。

执行会依次确认月份、目标日期、选中状态和补签按钮，按钮文字必须明确为补签含义，不能替代今日签到。操作后等待目标日期完成标记及卡数减少 1，单纯出现提示或点击完成不算成功；卡数为 0 时保留剩余日期。页面加载或未知结果停止后应先人工核验，不重复运行尝试扣卡。

点击前服务端会预留该日期，收到持久化确认后才点击；结果未知的日期后续只读复核，不盲目再次补签。已发起补签后，任务不自动整项重启、换车道重跑或回跳重复执行。无需新建数据库表或迁移；更新时需同步 API 和 Worker，前端从功能目录自动显示新步骤。本功能仅适用于“选日期后再点击独立补签按钮”的页面，不适用于点击日期格立即消费的日历。

### 弹窗按钮补签

对于“点击补签卡入口打开弹窗，点击弹窗中的日期按钮立即补签”的页面，使用独立的「弹窗按钮补签」（`post.resign_dialog`），不要套用 `post.resign_click` 的“选日期再提交”流程。入口点击仅打开弹窗，**日期按钮点击直接消费一张补签卡**，不是预览操作。步骤使用当前页面，不包含导航地址；先用正常工作流进入已确认的签到页。站点需启用「支持补签」，仅处理 pending 中的过去日期，不自动购卡。

配置示例（步骤 `config`，选择器均为候选数组，需根据实际页面结构拾取并调整，不能直接假定示例选择器适用）：

```json
{
  "entry_selector": [".attendance-card header button[title*=\"补签卡\"]"],
  "dialog_selector": ["[role=\"dialog\"][aria-label^=\"补签\"]"],
  "dialog_ready_selector": [],
  "button_selector": ["button"],
  "date_regex": "(?<!\\d)(?P<month>\\d{2})-(?P<day>\\d{2})(?!\\d)",
  "missing_button_as_signed": false,
  "dialog_wait_seconds": 10,
  "success_wait_seconds": 10,
  "success_selector": ["[role=\"dialog\"][aria-label^=\"补签\"] p"],
  "success_regex": "补签成功",
  "done_selector": [".attendance-calendar__day.is-done[title^=\"{date}\"]"],
  "card_count_selector": [".attendance-card header button[title*=\"补签卡\"]"],
  "card_count_regex": "补签\\s*[×x]\\s*(\\d+)"
}
```

`button_selector` 相对唯一可见且明确就绪的弹窗枚举按钮，仅点击可见、启用的目标，不在整个页面寻找同名日期。`date_regex` 必须有 `month/day` 命名组，或 `date` 命名组捕获 ISO 日期（例如 `(?P<date>\d{4}-\d{2}-\d{2})`）；若含 `year` 命名组，`month/day` 都必需。文本没有明确年份时才从待补签日期的对应月日推导；同一月日对应多个年份时停止，不猜年份。文本含明确 ISO 完整日期时，不得忽略年份而仅截取月日；命名 `date` 或完整 `year/month/day` 与 DOM 中的完整日期矛盾时拒绝。配置阶段校验正则编译和命名组，真实日期、ISO 格式和 DOM 日期一致性由 runner 校验。

仅 `done_selector` 是日期模板，支持 `{date}/{year}/{month}/{day}`，每项必须包含 `{date}` 或 `{day}`，需明确绑定目标日期。其他选择器不做模板解析，因此 Playwright 文本正则中的 `\d{2}` 等花括号不会被误判。拾取 done 标记后须将具体日期改回占位符，不能使用其他日期的完成标记。

模型要求 `done_selector` 或 `success_selector` 至少配置一项。schema 的 `success_selector` 默认为 `[]`，默认 done 为示例中的日历选择器以保证默认配置合法；只有真实页面匹配才能作为证据。若成功提示位于补签弹窗的段落元素中，可按实际结构配置 `success_selector`，例如 `[role="dialog"][aria-label^="补签"] p`。`success_regex` 默认 `补签成功`，`card_count_regex` 必须有捕获组，第一组为库存数量；两者均做编译校验。

成功必须同时具备“目标日期 done，或本次新出现的成功提示”以及“补签卡数恰好减少 1”。成功提示 baseline 在 prepare ACK + authorize 之后、实际点击之前采集，不能使用准备或授权之前的旧快照判断提示是否为本次新出现。旧提示、仅点击完成、仅卡数变化均不足。提示可能瞬时出现，随后网站刷新；runner 捕获本次提示后仍等待刷新后的稳定库存，不要求提示与新卡数同时存在。弹窗等待和成功等待默认各 10 秒，范围各为 1-60 秒，步骤总超时需覆盖整个处理过程。

「找不到日期按钮视为已签到」（`missing_button_as_signed`）默认关闭。开启后目标日期按钮缺失时，必须至少观察过一个可解析日期按钮，或 `dialog_ready_selector` 在唯一弹窗内唯一可见命中；两种证据皆无时返回 `waiting_human`，不视为已签到。单纯看见弹窗或没有按钮，无法区分合法空列表与日期加载错误，不能把加载失败当成已签到。此开关**不用于历史 unknown 自动消除**。历史未知结果必须先只读核验，不得为了消除未知记录重复消费。独立 AI 生成和助手均可编写该功能；助手执行仅限已保存完整运行的逐次消费审核，不支持孤立单步，此开关不扩大授权。

「弹窗内容就绪选择器」（`dialog_ready_selector`）可选，默认 `[]`，最多 20 个候选，相对唯一弹窗查找明确加载完成或合法空列表证据，不做日期模板解析。弹窗有其他可解析日期按钮时无需此字段；整个列表为空且要启用缺失按钮判已签到时，需配置经实际 DOM 确认的明确就绪/空态证据，不要使用弹窗外元素或仅证明弹窗已打开的容器。该字段不替代成功核验所需的 `done_selector` / `success_selector`。

部署需同步更新 API 和 Worker。配置前应确认入口只打开弹窗、日期按钮直接提交，以及成功标记和卡数的更新方式；不要为验证选择器反复运行真实补签。

### 车道选择

通过「使用代理」和「优先交互」选择车道。普通通用、代理通用可并行执行；交互车道一次只执行一个任务，适合需要人工查看或桌面坐标操作的流程。

导航页面偶发出现 `net::ERR_CONNECTION_CLOSED` 或连接重置时，可在确认目标页面可重复访问后，将该“页面导航”步骤的“失败重试次数”设为 2，最多尝试 3 次。默认 0 不重试；带签到、购买等副作用的 URL 不应开启。重试只缓解瞬时断连，不能修复持续的站点/CDN、网络或代理故障，规则见 [任务执行](execution.md)。

## 配置历史

站点和模板列表的“历史”入口可分页查看旧版本、本地配置、模板依赖和当时的解析结果。选择“恢复为新版本”会生成递增的新版本，不改写历史，不恢复登录凭据或 Cookie，也不递归回滚模板或撤销业务操作。

依赖版本或功能设置已变化时默认拒绝恢复；明确勾选接受当前依赖后，仍须通过当前校验。普通编辑保存遇到版本冲突时保留草稿，不自动覆盖其他修改。首次升级只能为现有配置建立基线，不能找回过去未保存的版本。完整规则和 API 见 [配置历史](workflow-history.md)。

## 导入与导出

模板和站点列表均支持勾选部分或全部项目后导入导出。导入前查看预览，处理同名项、父模板缺失或字段错误；同名项会跳过，不会直接覆盖。

站点导出包含流程配置，不包含保存的登录密码和 Cookie。导入后按需要重新设置凭据，并先手动验证再启用调度。自定义步骤字段仍可能包含敏感值，分享前应自行检查。

可使用 [插件 Demo](../plugins/examples/demo/README.md) 的单站点导入配置熟悉流程。它使用固定公开测试凭据，不用于真实账户。

## 执行与排查

页面可能先后展示多套使用同一 class 的引导弹窗。例如 `data-tour-root="shell"` 关闭后，首页的 `data-tour-root="home"` 会再显示 `.shell-tour-card`，并非原按钮未响应。应按 root 分别配置点击条件，定位 `.shell-tour-acts > button.ghost:text-is("跳过")`，避免宽泛的 `button.ghost` 命中“上一步”；两次引导之间使用对应 root 的出现/消失作为依据，不自动重复可能有副作用的点击。

可以从站点列表直接执行，也可以在「任务调度」选择站点运行。批量执行支持全部启用且有效的站点，或今天尚未成功且当前未在排队/运行的站点。

站点的最早签到时间与系统调度共同决定自动执行时机，日期按所设调度时区判断。

在运行详情中：

- 按站点切换子标签，查看每步状态、消息和输出。
- 切换「详细日志 / 状态日志」，定位等待、失败或超时原因。
- 打开失败截图，确认页面是否仍有挑战、已跳转，或出现站点错误提示。
- 任务运行中可以取消；系统会取消在途操作并清理任务页面，但已提交的请求不能撤回。
- 点击车道名进入任务对照视图，使用「定位任务标签页」查看该任务实际页面。

需要人工操作时，进入对应车道 VNC。任务结束通常会关闭其标签页，因此保留的失败截图和日志是排查历史运行的主要依据。重新运行前确认是否已签到或已发生购买，避免重复操作。

## 浏览器与人工操作

「车道状态」中可手动启动、进入 VNC 或关闭浏览器，也可等待任务按需启动。

- 退出 VNC 只关闭查看连接，不停止浏览器。
- 有任务执行时禁止关闭浏览器。
- 没有任务或 VNC 查看者时，超过空闲时间会自动关闭；默认 300 秒，设置 `0` 则禁用空闲关闭。
- 关闭浏览器保留 profile 数据，下次启动继续使用。不要在外部 Manager 中同时修改或关闭 SiteFlow 正在使用的 profile。
- 可在车道设置调整空闲时间及通用车道并发数；普通默认 5、代理普通默认 3，交互固定 1。

浏览器相关更新前请先结束任务并退出人工会话，避免中断执行。

## 插件管理

先按插件文档部署其容器并配置独立令牌，再在 SiteFlow「插件管理」查看注册结果和检查项。插件容器的安装、更新和删除由部署工具处理，不在 SiteFlow 页面执行。

1. 检查插件来源、声明能力和配置要求，确认可信后审批。
2. 审批完成后，在工作流、验证码方法或凭据/2FA 提供商中选择插件。
3. 插件不可用时检查容器状态、心跳和检查结果，不要通过反复审批掩盖连接故障。
4. 更新后先查看引用及影响提示，修复不兼容配置，再按要求重新审批。

停用会阻止接入但保留配置；撤销审批后需重新授权。移除接入不删除外部容器，恢复后也需重新审批。可通过审计列表查询相关管理操作。

## 通知与运行分析

在「通知设置」启用邮件或 HTTP 渠道，填写地址和必要凭据，发送测试确认可达。按需选择仅失败通知、自动调度通知，调整公共标题和正文；支持 `{{run_id}}`、`{{status_label}}`、`{{sites}}` 等变量。环境变量指定的字段在页面只读。

邮件和 HTTP 各自提供「接收助手调查通知」开关（`notify_assistant`，默认开启）。页面说明原任务通知仍按成功/手动筛选发送，只有实际接管产生有效结论后才另发简洁调查结果，未发生接管时不声称已调查。该开关只控制本通道的独立调查通知，不改变原任务自定义布局、成功/手动筛选或接管授权；通道未启用时仍不发送。调查通知是独立纯文本简报，HTTP 事件为 `assistant.investigation`；配置已保存不表示已验证成功。读取、刷新或保存通知设置不调用模型，详见[运行通知](run-notifications.md)。

通知失败不会改变任务结果。详细模板与渠道配置见 [通知设置](notifications.md)。

「运行分析」提供站点与日期状态矩阵、趋势和失败筛选。点击记录进入运行详情，通过日志和截图判断是否需要修改流程、凭据或服务配置。

## 账户

右上角账户菜单可修改密码或退出登录。管理员密码由环境变量管理时，需修改部署配置后更新服务，不能在页面改密。不要将自己的登录会话分享给其他人。
