# 使用指南

本指南介绍页面操作和日常使用。首次安装见 [README](../README.md)；服务部署见[部署与运维](deployment.md)，遇到异常请按现象查阅[故障排除](troubleshooting.md)。

## 建议顺序

1. 登录并修改管理员密码。
2. 在「系统设置」配置需要的代理、凭据和验证码服务，使用测试按钮确认连接。
3. 在「模板管理」建立通用流程，或导入可信来源的模板配置。
4. 在「站点管理」添加站点、选择模板、保存登录来源并调整站点步骤。
5. 先手动运行一个站点，检查步骤结果、日志和页面，再启用自动调度。
6. 在「通知设置」配置结果推送，通过「运行分析」持续查看执行情况。

## 系统设置

代理、2FAuth、CFbox、Bitwarden 和大模型可在此管理。连接字段会显示来源：环境变量提供的对应字段只读；页面保存的配置可以继续编辑。大模型支持多条有序配置，无主次之分；可选环境变量条目带「环境变量」来源标签，整条连接只读，不只是锁定个别字段。

- 配置代理后，站点才能使用代理车道。代理失败时不会自动改为直连。
- 使用 Bitwarden 时，填写服务地址和访问令牌，或使用部署自带的服务；同时配置该服务需要的保险库凭据。
- 使用 Turnstile 功能前配置 CFbox 地址。仅当 CFbox 自身启用鉴权时填写 API Key。
- 使用视觉验证码或图片答题时，在「大模型」添加支持图片输入、启用且勾选「功能卡片」用途的模型；助手模型需勾选「智能助手」并支持工具调用。模型用途不等于执行或截图授权。
- 调度支持关闭、定时、间隔和随机时间范围，可设置时区；环境变量指定的字段不能在页面修改。
- 可查看任务日志和截图的保留设置、数量及空间占用，按需要执行清理。清理前确认不再需要这些排查资料。

### CookieCloud

在「系统设置 → CookieCloud」添加只读服务器，选择要共享的站点，再将完整端点、UUID 和加密密码填入客户端。勾选「所有站点」会自动纳入以后新增的站点；手动模式的「全选」只选择当前列表。配置步骤、PyCookieCloud 示例和域名匹配问题见 [CookieCloud 接入指南](cookiecloud.md)。

### 管理模型

在「系统设置 → 大模型」按以下步骤操作：

1. 点击「添加模型」或现有条目的「配置」，填写显示名称、OpenAI 兼容的 `/v1` 地址、上游模型名称和 API Key。编辑已有条目时，API Key 留空可保留已有密钥。
2. 按用途勾选「功能卡片」或「智能助手」，图片功能还需勾选「支持视觉」。可按需设置输出 Token 上限；留空或填 `0` 使用上游默认值。
3. 用「测试当前配置」验证弹窗中的草稿；列表行内「测试」只检查已保存的连接。复用已保存的密钥测试新地址时，先核对目的地址再确认。测试成功后仍需手动保存。
4. 用「上移 / 下移」调整模型优先级，按需停用或删除，再点击「保存排序与启用状态」。运行时使用第一个符合用途、能力及启用条件的模型；请求失败不会自动切换。遇到保存冲突时，核对草稿后刷新并重新编辑。

连接数量、测试请求的用途和去向、模型选择规则见[模型与功能设置](vision-feature-settings.md#model-registry)。测试或运行失败见[模型故障排查](troubleshooting.md#模型调用失败)。

### 环境变量配置

日常连接配置可通过页面保存。需要由部署统一管理模型时，在 `.env` 配置 `SITEFLOW_MODEL_BASE_URL`、`SITEFLOW_MODEL_API_KEY` 和 `SITEFLOW_MODEL_ID`；在列表中找到标记「环境变量」的条目。该条目的连接在页面只读，仍可调整排序和启用状态。按需配置视觉能力、输出上限及全局请求超时，完整字段、默认值及必填条件见[配置与安全：环境变量](configuration-security.md#环境变量)。

## 模板与功能

「功能管理」可查看各类功能的配置字段、必填项及所需服务。通用默认值可在支持的功能设置中调整；具体站点的差异优先在站点中覆盖。

在「模板管理」新建模板并添加分组和步骤。选择功能后填写对应字段，保存前补齐必填项。已有类似流程时，可选择父模板，再调整需要覆盖的步骤。

在模板编辑器点击「从站点导入配置」，选择来源并确认。它仅把站点的本地步骤、分组、信号及父模板关系填入表单，保留当前模板的名称、描述和启用状态，不复制凭据，也不自动保存或运行。检查继承关系后手动保存。助手审核后保存模板是另一入口，见[从站点保存模板](ai-assistant.md#从站点保存模板)。

- 步骤可保持继承、强制启用，或保留配置但禁用。
- 使用上下移动调整步骤顺序；在模板中定义的顺序会沿用到站点。
- 修改继承步骤时点击「修改步骤」；需要回到父级配置时使用恢复继承。
- 「代码配置」可粘贴 JSON 批量编辑当前步骤，应用前检查字段和错误提示。
- 模板和站点步骤的 key 由系统生成。使用条件跳转时选择目标步骤，不手工改写 key。
- 页面信号可配置包含/排除文本或选择器，步骤条件引用这些信号。保存前确保被引用的信号存在；无法判断的条件会要求人工检查。
- 条件跳转可跳到指定步骤或重新开始，需设置合理的跳转次数限制，避免反复提交操作。

`flow.jump` 的「跳转匹配方式」（`match_mode`）默认为 `page`，必须配置至少一项 `texts` 或 `selectors`，在步骤 `condition` 允许执行且页面匹配时跳转。设为 `always` 时，无需页面文字或选择器匹配，仅由步骤 `condition` 控制；应明确配置条件，避免无条件循环。两种模式均保留目标步骤校验，`max_jumps` 默认 10，范围 0-100，不会因选择 `always` 而取消上限。

### 选择器与元素拾取

配置多个候选选择器时，按优先顺序填写，优先使用能唯一定位目标的选择器，避免泛用的 `button` 或 `input`。

工作流信号默认检查元素是否存在，隐藏元素也可能命中；需要可见证据时，可在工作流的 Playwright 选择器中写 `:visible`。表单登录的成功元素则必须可见。

点击选择器字段旁的「拾取」，在交互车道打开页面。必要时先正常登录，再按住 **Alt/Option** 点击目标元素，确认生成的选择器。拾取会话默认 15 分钟过期，完成后关闭会话。

## 站点与登录

在「站点管理」添加名称和基础地址，选择模板，然后检查展开的步骤。步骤地址可使用 `{base_url}`，运行时替换为当前站点地址。

继承字段可以单独覆盖；点击「修改步骤」调整模板步骤，不需要复制整套流程。保存后查看解析预览，核对最终步骤、条件和参数。

「登录凭据」中选择适合的来源：

- **账户**：首次填写用户名和密码；以后可以单独更新，密码不回显。
- **Cookie**：粘贴浏览器 Cookie 请求头或支持的 JSON。保存后不回显明文，过期时重新导入。
- **Bitwarden**：启用集成后选择域名匹配方式；有多个相似域名时检查完整域名、主域名或自定义匹配是否符合预期。
- **插件提供商**：先在插件管理中完成接入和审批，再在对应标签启用，并设置匹配方式。

外部凭据来源互斥，不要同时启用多个提供商。远程凭据不会自动写入手动账户字段。更换来源后先做单站点验证。

### 表单登录就绪

在「表单登录」步骤配置只在登录成功后出现的可见元素。成功元素留空时，只能确认表单已提交，不能确认已经登录。

如果成功标记出现较慢，可设置「成功等待秒数」（默认 10，范围 1–120）。同时确认步骤总超时足以覆盖查询凭据、定位、填写、提交和等待。若失败截图已显示登录成功，先按[登录时序与误判](troubleshooting.md#登录时序与误判)核对日志和选择器。

### 智能助手

管理员先设置 `SITEFLOW_CONFIG_AI_ENABLED=true`，并在「大模型」启用支持工具调用、用途为「智能助手」的模型。

1. 在「智能助手」点击「新建会话」，提供非秘密的站点地址、名称和需求。不要在聊天中填写密码、Cookie 或动态码；需要凭据时选择已保存的同源站点或启用 Bitwarden。
2. 在输入框上方核对并确认目标。目标确认允许观察；单步执行、截图和工作流是三类独立权限，工作流授权涵盖导入和完整测试。人工登录时，在助手所用的同一交互车道中另开一个 VNC 标签页，登录后请助手重新观察。
3. 先观察页面，再按需授权单步验证。真实点击、登录和签到可能产生副作用；「刷新会话」只更新聊天状态，「刷新网页」会发起新 GET。结果不明时先核对网站状态，不要直接重跑。
4. 核对提案中的工作流、认证来源、车道及待确认问题。提案不会自动保存或运行；经授权可导入并测试，新增站点默认不参与调度，已有站点保留原调度状态。购买和补签仅在完整运行中按步骤审核消费计划。点聊天「停止」不会取消已提交的完整任务；请到「任务调度」检查或取消。

页面顶部可打开「助手设置」或「助手接管」。接管默认关闭；启用前核对覆盖站点、处理模式和是否允许无人值守浏览或单步验证。「仅分析」不保存工作流，但若允许实时操作，仍可能影响网站。接管不会自动重跑完整工作流，可在接管面板查看审计记录。

更多操作见[智能助手](ai-assistant.md)，包括[截图与恢复](ai-assistant.md#截图与恢复)、[从站点保存模板](ai-assistant.md#从站点保存模板)以及[调度与取消](ai-assistant.md#调度与取消)。会话中断或浏览器不可用见[智能助手故障排除](troubleshooting.md#智能助手中断权限或浏览器失败)。

### 密码验证

已登录后仍要求再次输入账户密码的页面，可添加认证分类下的“密码验证”（`auth.password_verify`）步骤。它从站点当前的账户凭据来源（手动账户、Bitwarden 或凭据插件）获取密码，只填写密码框并点击验证按钮，不填写用户名，也不需要在步骤配置中保存明文密码。同一工作流可添加多个密码验证步骤。

配置“密码选择器”“提交按钮选择器”，并建议填写验证通过后才出现的“成功元素选择器”；选择器均支持有序候选。成功元素留空时只报告已提交，不证明页面已经验证通过。此步骤沿用表单登录的同源和可信网址检查，不会自动扩大跨域凭据授权。

### 跨域登录与可信网址

站点编辑器的「备注」上方可添加可信 URL 正则数组。默认空数组，仍仅允许在站点同源页面读取和填写登录凭据/TOTP。跨域 SSO 必须显式授权，不能仅凭导航步骤自动信任。

例如基础地址为 `https://www.natfrp.com`，需要授权 `https://openid.13a.com/login` 及其查询参数时，添加：

```text
^https://openid\.13a\.com/login(?:[/?#].*)?$
```

规则匹配完整 URL，域名中的 `.` 应转义为 `\.`；尽量限定实际登录路径，不要使用 `.*` 信任所有网址。复制或导入站点后，重新审核可信规则；清空列表可撤销额外授权。助手的观察来源与站点的凭据授权独立，不能互相替代。

需要 2FA 时，在对应步骤选择提供商，填写 **2FA 服务名**；同服务有多个账户时再填写 **2FA 用户名**。无论使用内置 2FAuth 还是插件，服务名都不能为空。

### 验证与签到

根据站点实际页面添加功能，不必把所有验证方式都开启：

- 图形验证码可选择 ddddocr、视觉模型、NexusPHP GD 5 或已批准插件方法；按验证码填写字符集与长度。置信度阈值仅适用于 ddddocr。
- 识别失败时可配置刷新或重新开始，并限制重试次数。视觉模型与 GD 5 不会自动退回 ddddocr。
- Turnstile 需要 CFbox；ALTCHA 使用独立验证功能。成功组件仍可能显示在页面，不必等待它消失。
- 通过按钮、导航、iframe 签到或 UNIT3D Claim 等步骤完成操作，再配置明确的成功信号和结果输出。
- 站点未接受验证码或签到提交时，见[页面导航、选择器与站点提交](troubleshooting.md#页面导航选择器与站点提交)。

### 补签与购买

站点启用「支持补签」并设置最大天数后，使用「断签」信号判断是否需要执行补签步骤。购卡的「购买数量」为 0 时，按待补签天数减去现有卡数自动补齐；大于 0 时固定购买该数量，即使没有待补签日期也会购买。固定购买仍受步骤执行条件约束，若条件要求「断签」为真，无断签时仍会跳过。

1. 选择表格、网格卡片或自定义商品布局，填写商品标题、价格和所需商品选择器。价格须定位单张价格，不能读取批量总价。
2. 按操作顺序添加「购买点击项」，为每项选择「商品内」或「当前页面」，并填写候选选择器。可选填商品内的「购买数量输入框候选」以分批购买，留空时逐张购买。
3. 配置卡数选择器和正则；第一捕获组应提取张数。例如页面显示「你目前拥有补签卡 3 张」，可用 `补签卡\s*(\d+)\s*张`。必要时另设同源的库存地址，先确认打开该页本身不会签到或消费。
4. 核对价格、购买数量和执行条件。购买后验证库存是否增加本轮张数；结果不明时先人工核对，不要对正式账户反复提交。

字段、分批和库存核验规则见[任务执行](execution.md#4-已支持功能块)。

### 页面循环补签

对于“选日期后再点击独立补签按钮”的日历，选择「页面循环补签」。先在站点启用「支持补签」并设置历史范围；没有历史运行记录时，系统不会自行猜测漏签日期。使用 NexusPHP FullCalendar 的站点可选择普通「补签」。

默认选择器针对已检查的 `/calendar` 自定义日历：

| 配置 | 默认值 |
| --- | --- |
| 日历地址 | `{base_url}/calendar` |
| 月份标题 | `.cal-board > .cal-water` |
| 上一月 / 下一月 | `.cal-arr[aria-label="上一月"]` / `.cal-arr[aria-label="下一月"]` |
| 目标日期 | `.cal-grid > button.cal-cell:not(.mute):has(.cal-num:text-is("{day}"))` |
| 目标日期选中 | `.cal-grid > button.cal-cell.on:not(.mute):has(.cal-num:text-is("{day}"))` |
| 目标日期完成 | `.cal-grid > button.cal-cell:not(.mute):has(.cal-num:text-is("{day}")) .cal-badge.att` |
| 补签按钮 | `.cal-att button.cal-att-pill.act` |
| 等待秒数 `wait_seconds` | `10`，整数 1-60 |
| 最大翻月次数 `max_month_jumps` | `12`，整数 0-120；0 表示不翻月 |
| 最大重试次数 `max_retries` | `3`，整数 0-10 |

共 11 个配置字段，其中 7 个选择器字段使用候选数组。日期模板支持 `{date}`（ISO 完整日期）、`{day}`、`{month}`、`{year}`；拾取后要保留日期占位符，不要把具体某一天写死。月份标题必须能读出数字年月；不要选包含所有年份下拉选项的整个工具栏。`.mute` 用于排除相邻月日期，其他站点需要按实际结构配置。

按实际页面填写日期、选中状态和完成标记选择器。点击后如需处理验证码，请在后续步骤处理，再回到补签步骤核验同一日期。配置重试前，确认站点不会对同一日期重复扣卡；只有所有日期均确认完成，才会清除断签信号。详细规则见[任务执行](execution.md#4-已支持功能块)。

按下表配置循环，并在编辑器选择 A 作为回跳目标：

| 步骤 | 功能与配置 | 步骤 `condition` |
| --- | --- | --- |
| A 补签 | `post.resign_loop`，`max_retries=3` | `signal:sys_resign_pending:true` |
| B 可选验证码 | 按页面实际验证码类型配置处理步骤；`captcha` 为已配置的页面信号 key | `all(signal:sys_resign_pending:true,signal:captcha:true)` |
| C 回跳 | `flow.jump`，`match_mode="always"`，`action="jump"`，`target_step_key` 指向 A；无需填写 `texts` / `selectors` | `signal:sys_resign_pending:true` |

C 的 `max_jumps` 按预计日期数、额外重试及回到 A 确认结果所需次数配置，必须不超过 100；不能只按首次点击次数估算，也不能用放宽上限掩盖未决结果。**购卡放在循环外、A 之前**，不要把 `post.buy_card` 放进 A/B/C 的回跳范围，避免重复购买。

循环应在一次任务内完成。若结果不明，先人工确认对应日期是否已补签，不要通过新任务延续未知结果。

### 弹窗按钮补签

对于“点击补签卡入口打开弹窗，点击弹窗中的日期按钮立即补签”的页面，使用独立的「弹窗按钮补签」（`post.resign_dialog`），不要套用 `post.resign_loop` 的“选日期再提交”流程。入口点击仅打开弹窗，**日期按钮点击直接消费一张补签卡**，不是预览操作。步骤使用当前页面，不包含导航地址；先用正常工作流进入已确认的签到页。站点需启用「支持补签」，仅处理 pending 中的过去日期，不自动购卡。

配置示例（步骤 `config`，选择器均为候选数组，需根据实际页面结构拾取并调整，不能直接假定示例选择器适用）：

```json
{
  "entry_selector": [".attendance-card header button[title*=\"补签卡\"]"],
  "dialog_selector": ["[role=\"dialog\"][aria-label^=\"补签\"]"],
  "dialog_ready_selector": [],
  "button_selector": ["button"],
  "date_regex": "(?<!\\d)(?P<month>\\d{2})-(?P<day>\\d{2})(?!\\d)",
  "missing_button_as_signed": false,
  "dialog_wait_seconds": 10,
  "success_wait_seconds": 10,
  "success_selector": ["[role=\"dialog\"][aria-label^=\"补签\"] p"],
  "success_regex": "补签成功",
  "done_selector": [".attendance-calendar__day.is-done[title^=\"{date}\"]"],
  "card_count_selector": [".attendance-card header button[title*=\"补签卡\"]"],
  "card_count_regex": "补签\\s*[×x]\\s*(\\d+)"
}
```

- `button_selector` 相对弹窗查找日期按钮；`date_regex` 使用 `month/day` 命名组，或用 `date` 捕获 `YYYY-MM-DD` 完整日期。
- `done_selector` 支持日期占位符，须含 `{date}` 或 `{day}`。至少配置日期完成标记或本次成功提示，并配合卡数验证；`card_count_regex` 第一组提取库存数量。
- 「找不到日期按钮视为已签到」默认关闭。确需开启且可能出现合法空列表时，用 `dialog_ready_selector` 定位该弹窗明确的就绪或空态证据；不要用仅表示弹窗已打开的容器。
- 日期按钮会真实消耗补签卡。不确定是否扣卡时先查看页面状态和库存，不要重复提交。详细核验规则见[任务执行](execution.md#4-已支持功能块)。

### 车道选择

通过「使用代理」和「优先交互」选择车道。普通通用、代理通用可并行执行；交互车道一次只执行一个任务，适合需要人工查看或桌面坐标操作的流程。

通用车道可并行运行任务，但前台输入仍需轮流进行。车道等待或偶发导航故障请查阅[故障排除](troubleshooting.md)。

## 配置历史

站点和模板列表的“历史”入口可分页查看旧版本、本地配置、模板依赖和当时的解析结果。选择“恢复为新版本”会生成递增的新版本，不改写历史，不恢复登录凭据或 Cookie，也不递归回滚模板或撤销业务操作。

依赖或功能设置已变化时，先查看恢复预览；确认可接受当前依赖后再恢复。遇到版本冲突时，保留草稿并核对当前版本。详见[配置历史](workflow-history.md)。

## 导入与导出

模板和站点列表均支持勾选部分或全部项目后导入导出。导入前查看预览，处理同名项、父模板缺失或字段错误；同名项会跳过，不会直接覆盖。

站点导出包含流程配置，不包含保存的登录密码和 Cookie。导入后按需要重新设置凭据，并先手动验证再启用调度。自定义步骤字段仍可能包含敏感值，分享前应自行检查。

可使用 [插件 Demo](../plugins/examples/demo/README.md) 的单站点导入配置熟悉流程。它使用固定公开测试凭据，不用于真实账户。

## 执行与查看结果

可以从站点列表直接执行，也可以在「任务调度」选择站点运行。批量执行支持全部启用且有效的站点，或今天尚未成功且当前未在排队/运行的站点。

站点的最早签到时间与系统调度共同决定自动执行时机，日期按所设调度时区判断。

在运行详情中：

- 按站点切换子标签，查看每步状态、消息和输出。
- 切换「详细日志 / 状态日志」，定位等待、失败或超时原因。
- 打开失败截图，确认页面是否仍有挑战、已跳转，或出现站点错误提示。
- 任务运行中可以取消；系统会取消在途操作并清理任务页面，但已提交的请求不能撤回。
- 点击车道名进入任务对照视图，使用「定位任务标签页」查看该任务实际页面。

需要人工操作时，进入对应车道 VNC。任务结束通常会关闭其标签页，因此保留的失败截图和日志是排查历史运行的主要依据。重新运行前确认是否已签到或已发生购买，避免重复操作。

如果任务长时间停在等待、浏览器设置或清理阶段，见[多标签等待排查](troubleshooting.md#多标签等待排查)。

## 浏览器与人工操作

「车道状态」中可手动启动、进入 VNC 或关闭浏览器，也可等待任务按需启动。

- 退出 VNC 只关闭查看连接，不停止浏览器。
- 有任务租约（含未确认关闭的清理隔离租约）时禁止关闭浏览器；`in_use` 不只是正在执行业务的任务数。
- 没有任务或 VNC 查看者时，超过空闲时间会自动关闭；默认 300 秒，设置 `0` 则禁用空闲关闭。
- 关闭浏览器保留 profile 数据，下次启动继续使用。不要在外部 Manager 中同时修改或关闭 SiteFlow 正在使用的 profile。
- 可在车道设置调整空闲时间及通用车道并发数；普通默认 5、代理普通默认 3，交互固定 1。

VNC 已连接但画面不可用时，见[VNC 黑屏排查](troubleshooting.md#vnc-已连接但黑屏)。

## 插件管理

先按插件文档部署其容器并配置独立令牌，再在 SiteFlow「插件管理」查看注册结果和检查项。插件容器的安装、更新和删除由部署工具处理，不在 SiteFlow 页面执行。

1. 检查插件来源、声明能力和配置要求，确认可信后审批。
2. 审批完成后，在工作流、验证码方法或凭据/2FA 提供商中选择插件。
3. 更新后查看引用与影响提示，按要求修复配置并重新审批。插件未就绪时见[服务部署与集成](troubleshooting.md#服务部署与集成)。

停用会阻止接入但保留配置；撤销审批后需重新授权。移除接入不删除外部容器，恢复后也需重新审批。可通过审计列表查询相关管理操作。

## 通知与运行分析

在「通知设置」启用邮件或 HTTP 渠道，填写地址和必要凭据，发送测试确认可达。按需选择仅失败通知、自动调度通知，调整公共标题和正文；支持 `{{run_id}}`、`{{status_label}}`、`{{sites}}` 等变量。环境变量指定的字段在页面只读。

如需接收独立的助手调查结果，可在各通道开启「接收助手调查通知」。模板和筛选规则见[通知设置](notifications.md)与[运行通知](run-notifications.md)；未收到通知时见[通知故障排查](troubleshooting.md#通知未送达与资源监控不可用)。

「运行分析」提供站点与日期状态矩阵、趋势和失败筛选。点击记录进入运行详情，通过日志和截图判断是否需要修改流程、凭据或服务配置。

## 账户

右上角账户菜单可修改密码或退出登录。管理员密码由环境变量管理时，需修改部署配置后更新服务，不能在页面改密。不要将自己的登录会话分享给其他人。
