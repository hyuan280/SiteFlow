# 站点与模板配置历史

## 存储方式

站点和模板使用“当前态 + 不可变完整快照”：现有 `sites`、`templates` 和工作流子表继续承载当前配置；`workflow_history` 在配置写入时追加版本，不改写已有快照，允许管理员手动删除非受保护版本。不依赖差量补丁重建历史，也不把解析结果当作可回写的原始配置。

每个站点、模板拥有独立 UUID `history_key`。模板复用 `version`，站点复用 `config_revision`；版本号只在同一稳定身份内有意义。删除后新建即使复用整数 ID，也会得到新的身份和历史。

每个历史记录包含版本号、操作类型、时间、操作人、恢复来源版本、Schema 版本、内容 SHA-256，以及 AES-256-GCM 加密的快照。AAD 绑定对象类型、稳定身份、版本和 Schema 版本。SHA-256 用于内容比对，不是对数据库管理员的防篡改承诺。

`schema_version=1` 的快照包含：

| 字段 | 内容 |
| --- | --- |
| `local` | 当时的站点或模板本地配置，包含分组、步骤、信号、空值和排序锚点，不含写入前置条件 |
| `dependencies` | 当时的祖先模板链、稳定身份、版本和本地配置 |
| `features` | 相关功能版本、Schema、默认值、必填字段和执行设置 |
| `resolved` | 保存时冻结的解析结果，读取历史时不重新解析 |
| `resolution_error` | 无法解析存量配置时的通用说明，此时 `resolved` 为空 |

对象的创建、更新、恢复和删除均与历史写入处于同一数据库事务；任一校验、加密或保存失败会整体回滚。模板更新、恢复还会检查受影响的子模板和站点。

## 版本语义

- `create`：新对象的第一个版本。
- `update`：一次成功保存，本地版本递增，即使提交内容相同也会记录。
- `restore`：以历史本地配置创建新版本，并记录 `restored_from_revision`；不会倒退版本号或改写来源记录。
- `delete`：追加终止版本后删除当前对象，历史继续保留。
- `baseline`：升级时为尚无历史的对象记录当前配置，沿用已有版本号。之前未保存的旧版本无法补出。

本地版本不等于完整生效配置时间线。当前继承仍跟随最新模板，不固定到某个模板版本；父模板或全局功能设置变化不会自动递增站点本地版本。历史快照能查看该站点保存时的依赖和解析结果，但不代表该版本存续期间的每一次运行输入。本功能没有改动执行器，也没有提供运行重放。

## 页面操作

在站点或模板列表点击“历史”，分页查看版本并选择“查看快照”。可查看本地配置、依赖和冻结解析结果。“操作类型”列展示创建、更新、恢复等事件；右侧“操作”列提供“查看快照”和“删除版本”。删除需二次确认，当前版本的删除按钮禁用。

点击“恢复为新版本”并确认后，服务端读取历史本地配置，按当前功能和依赖重新校验。默认拒绝模板版本或功能设置漂移。确需使用当前依赖时，可显式勾选“接受当前依赖”；依赖已删除、被其他身份替换、继承链改变或功能版本不兼容时仍拒绝。

恢复只作用于选中的对象，不递归恢复父模板或全局设置。站点配置中的启用状态、地址、可信网址及凭据提供商引用也属于本地配置，恢复前应检查；恢复已启用的站点后，后续调度会使用恢复后的配置。

普通编辑保存会携带打开编辑器时的版本和稳定身份。冲突时不会自动覆盖或重试，页面保留草稿；应重新核对当前配置后处理。

删除对象后的归档仍可通过稳定身份 API 查询，首版没有归档列表页面或恢复已删除对象功能。需要长期定位归档时，应保留删除前详情中的 `history_key`。

## 手动删除版本

管理员可按稳定身份和版本号永久删除单条历史记录，适用于仍存在的对象和已删除对象的归档。每个身份的最高版本始终保留，包括对象删除时追加的 `delete` 终止版本；实际当前配置对应的版本也不能删除，即使存在更高的历史版本。保护条件在数据库 DELETE 中原子校验，避免并发请求绕过保护。

删除历史不会删除或修改当前站点、模板及其配置，不递增版本，不追加历史，也不重新加密或改写其他快照。此操作无需解密，因此非受保护的损坏快照也能删除。整数 ID 被新对象复用后，旧 `history_key` 的删除不会影响新对象。

删除后列表总数减少，版本号可以不连续且不会重新编号；被删版本无法再查看或恢复。后续保存和恢复仍从当前版本递增。其他快照内嵌的依赖内容、恢复来源版本号不会被改写，来源记录即使已删除，现有快照仍可读取。手动删除不可撤销，但不会清理已有数据库备份。

## API

站点和模板分别使用 `/api/v1/sites/{id}`、`/api/v1/templates/{id}` 为资源前缀：

| 方法与后缀 | 用途 |
| --- | --- |
| `GET /versions?limit=20&offset=0` | 倒序分页列表，返回 `history_key`、`current_revision`、`total` 和 `items` |
| `GET /versions/{revision}` | 获取元数据和完整冻结快照 |
| `POST /versions/{revision}/restore` | 恢复并返回新的站点或模板详情 |

列表的 `limit` 范围为 1 到 100。历史读取要求管理员会话；恢复还要求 `X-CSRF-Token`。

恢复请求示例：

```json
{
  "expected_revision": 5,
  "expected_history_key": "e83889f4-e381-4af7-a6f8-c250c09d232b",
  "accept_current_dependencies": false
}
```

普通 PUT 也接受 `expected_revision`、`expected_history_key`；DELETE 使用同名查询参数。为保留已交付的调用方式，这些普通写入前置条件可省略，但自动化调用方应始终同时提供两者，防止过期写入和整数 ID 复用。恢复必须提供预期版本，稳定身份字段同样应提供。数据库通过条件更新原子校验，冲突返回 409，不产生新历史。

以下稳定身份接口可用于当前对象及删除后的归档，均需管理员会话：

```text
GET /api/v1/workflow-history/{history_key}/versions
GET /api/v1/workflow-history/{history_key}/versions/{revision}
DELETE /api/v1/workflow-history/{history_key}/versions/{revision}
```

历史 DELETE 还要求 `X-CSRF-Token`，路径中的 `history_key` 必须是 UUID，`revision` 必须是正整数；无需请求体或当前版本前置条件。成功返回 `204` 且无响应体，身份或版本不存在返回 `404`，受保护版本返回 `409`，无效路径参数返回 `422`。这与删除站点或模板对象的 DELETE 不同，后者仍会追加终止版本并删除当前对象。

## 安全与升级

专用登录凭据、Cookie 和集成密钥不纳入配置快照，也不因恢复而改变。但是普通步骤参数、备注、URL 或功能默认值仍可能含手工填写的秘密，因此整个历史快照加密保存。管理员历史详情返回完整普通配置，并非脱敏输出；后续向大模型或 MCP 提供数据时必须另加授权和脱敏层。

首次升级会幂等增加稳定身份字段和索引，建立历史表，并在插件目录刷新后为存量对象生成基线。损坏的步骤配置、可信网址或标签 JSON 会保留原始值并标记无法解析，不伪造有效配置。重复启动不会重写基线。

升级前备份数据库和 `SITEFLOW_MASTER_KEY`，仅运行一个 API 实例执行迁移。历史与数据库一同备份，当前不自动清理历史。丢失或直接替换主密钥会导致旧快照无法解密，本次未增加密钥轮换机制。普通 JSON 导出只导出当前配置，不包含历史归档。
